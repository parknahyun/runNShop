## Clarifications

### Session 2026-10-13

- Q: 선착순형 행사의 제한 수량 차감 시점은? → A: 질문 대신 FR-013(시작·종료 자동 전환, 가격 복원, 선착순 소진 종료) 전체를 본 spec 범위에서 제외. 해당 동작은 별도 spec/이슈에서 다룬다. (FR 번호는 추적성을 위해 재부여하지 않고 FR-013을 결번으로 둔다.)
- Q: 한 주문에서 상품 쿠폰은 몇 장까지 함께 쓸 수 있는가? → A: 상품(주문 항목)당 1장, 주문 전체 상품 쿠폰 수는 제한 없음.
- Q: 프로모션 운영 권한은 어떻게 나누는가? → A: 단일 "관리자" 역할이 쿠폰·할인·배송비 할인 전체를 등록·운영하며 MD/플랫폼 운영자 등 역할 세분화는 하지 않는다. 입점사(partner) 편입 시 재검토한다.
- Q: 쿠폰 발급 한도 초과 요청에는 어떻게 응답하는가? → A: 한도 소진과 이미 수령을 서로 다른 사유로 즉시 거절하며 대기열 발급은 하지 않는다.
- Q: 배송비 할인(배송비 쿠폰, 무료배송 프로모션)을 이번 spec 범위에 포함하는가? → A: 포함. 배송비 대상 가격할인(정률, 무료배송=100%)과 배송비 쿠폰을 모두 추가한다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 주문 시 할인·쿠폰 계산 (Priority: P1)

고객이 상품을 담고 주문서에 진입하면, 주문 처리 쪽에서 프로모션에 "이 상품들에 적용할 할인은 얼마인가", "이 쿠폰을 쓸 수 있는가"를
묻는다. 프로모션은 상품 단위 할인(행사가 또는 수량구간 할인)을 먼저 계산하고, 그 결과 금액을 기준으로 장바구니(주문 단위) 할인과
쿠폰을 적용한 할인액과 사용 불가 사유를 돌려준다. 고객은 자신에게 가장 유리한 조합이 기본으로 선택된 금액을 확인한다.

**Why this priority**: 주문·결제의 금액이 결정되는 지점이며 1차 거래(Order+Payment) 범위의 선행 조건이다. 이 계산이 없으면 어떤 프로모션도 고객에게 혜택으로 전달되지 않는다.

**Independent Test**: 행사가·수량구간 할인·장바구니 할인·쿠폰이 각각 준비된 상태에서 계산 요청만 보내 반환된 할인액·사유를 검증한다. 다른 스토리(관리자 등록 화면 등) 없이 준비된 데이터만으로 가치 검증이 가능하다.

**Acceptance Scenarios**:

1. **Given** 상품에 활성 행사가가 있고, **When** 주문 처리가 해당 상품의 할인 계산을 요청하면, **Then** 행사가 기준 할인 적용 결과를 돌려준다. (REQ-PRM-001)
2. **Given** 상품에 활성 수량구간 할인(예: 3개 이상 10%)이 있고, **When** 구매 수량이 구간에 해당하는 상태로 계산을 요청하면, **Then** 해당 구간의 할인율이 적용된 결과를 돌려준다. (REQ-PRM-001, 006)
3. **Given** 상품 단위 할인 적용 후 주문 총액이 장바구니 할인 조건 금액 이상이고, **When** 장바구니 할인 평가를 요청하면, **Then** 정가 총액이 아니라 "상품 할인 적용 후 총액"을 기준으로 판정하여 할인액을 돌려준다. (REQ-PRM-002)
4. **Given** 회원이 보유한 쿠폰이 여러 장이고, **When** 특정 주문에 적용 가능한 쿠폰을 요청하면, **Then** 이 주문에 적용 가능한 쿠폰만 걸러서 각 할인액과 함께 돌려준다. (REQ-PRM-005)
5. **Given** 쿠폰이 유효기간 만료·이미 사용됨·최소 주문금액 미달·적용 상품 불일치 중 하나에 해당하면, **When** 쿠폰 사용 검증을 요청하면, **Then** 사용 불가 사유를 돌려준다. 사용 가능 판정은 "쿠폰 상태가 사용 가능 AND 유효기간 이내"를 함께 만족할 때만 성립한다. (REQ-PRM-003, 004)
6. **Given** 같은 레벨(상품 또는 주문)에서 자동 적용 할인과 쿠폰이 모두 가능하고, **When** 계산이 수행되면, **Then** 혜택이 더 큰 쪽이 기본값으로 적용되고 고객은 주문서에서 다른 옵션으로 바꿀 수 있다. (DBA §2.7)
7. **Given** 장바구니 쿠폰이 이미 적용된 주문에, **When** 다른 장바구니 쿠폰 적용을 요청하면, **Then** 동시에 1건만 허용되므로 거절된다. (REQ-PRM-048)
8. **Given** 주문 항목에 상품 쿠폰이 이미 적용되어 있고, **When** 같은 항목에 다른 상품 쿠폰 적용을 요청하면, **Then** 항목당 1장만 허용되므로 거절된다. 서로 다른 항목에는 각각 상품 쿠폰을 적용할 수 있다. (Clarifications 2026-10-13)
9. **Given** 주문에 여러 입점사 상품이 있고 입점사별 배송비가 있을 때, **When** 배송비 할인(자동 적용 또는 배송비 쿠폰) 계산을 요청하면, **Then** 입점사 단위 배송비에 정률(무료배송은 100%)로 할인이 적용된 결과를 돌려준다. 배송비 할인은 수량 조건을 쓰지 않고, 상품·주문 단위 할인과는 별개로 계산된다. (DBA §2.2~2.4, Clarifications 2026-10-13)

### User Story 2 - 관리자의 할인 정책 등록·운영 (Priority: P1)

프로모션 운영 관리자가 행사가, 수량구간 할인, 장바구니 할인을 등록한다. 등록·확정하면 즉시 적용되지 않고 "예약" 상태가 된다.
(시작·종료 시점의 자동 전환과 가격 복원은 본 spec 범위에서 제외 — Clarifications 참조)

**Why this priority**: 계산 대상이 되는 할인 정책이 존재해야 스토리 1이 의미가 있다. 운영 안정성(실수 방지를 위한 예약 활성화)이 핵심 가치다.

**Independent Test**: 관리자가 정책을 등록·확정하고 택1·1건 제한·예약 마감 규칙과 허용된 상태 전이(작성 중 ↔ 예약, 예약 → 종료)를 검증한다.

**Acceptance Scenarios**:

1. **Given** 관리자가 시작일 1영업일 전까지 행사가를 등록·확정하면, **When** 행사 기간과 종료방식(기간형/선착순형, 선착순형은 제한 수량 포함)이 유효하면, **Then** 예약 상태로 등록되고 즉시 활성화되지 않는다. (REQ-PRM-010)
2. **Given** 동일 상품에 예약 또는 적용 중인 행사가/수량구간 할인이 있으면, **When** 관리자가 또 다른 상품 가격할인 등록을 시도하면, **Then** 등록이 거부된다(행사가끼리도, 행사가↔수량구간 할인도 택1). 상품 쿠폰과 장바구니 할인은 이 제한 대상이 아니다. (REQ-PRM-007, 021)
3. **Given** 장바구니 할인이 이미 적용 중인 상태에서 다른 예약 건의 시작일이 도래하면, **When** 자동 활성화가 시도되면, **Then** 동시에 1건만 허용되므로 활성화가 보류된다. (REQ-PRM-030-1, 032)
4. **Given** 관리자가 아닌 주체(고객, 연동 시스템 등)가 할인 정책 등록·변경을 시도하면, **When** 요청하면, **Then** 거절된다. 모든 프로모션 등록·운영은 단일 "관리자" 역할이 수행하며 역할은 세분화하지 않는다. (REQ-PRM-031, Clarifications 2026-10-13)
5. **Given** 예약 상태의 정책이 아직 시작 전이면, **When** 관리자가 수정 또는 취소하면, **Then** 각각 작성 중 상태로 되돌아가거나 종료된다. 적용 중인 정책은 작성 중/예약 상태로 되돌릴 수 없고, 종료된 정책은 재활성화할 수 없다(신규 생성만 가능). (DH 상태머신)

### User Story 3 - 쿠폰 등록·발급·다운로드 (Priority: P2)

관리자가 쿠폰을 등록하고 적용 대상(타겟)을 설정하며, 특정 회원에게 임의로 발행(CS 보상 등)하거나 일괄 발급한다.
고객은 모바일에서 다운로드 가능한 쿠폰을 받아 보유하고, 유효기간이 지나면 자동으로 만료된다.

**Why this priority**: 쿠폰 소비(스토리 1)의 공급 측이다. 할인 정책 없이도 쿠폰만으로 먼저 가치를 낼 수 있어 독립 슬라이스로 분리하되, 거래 핵심(P1)보다 후순위다.

**Independent Test**: 관리자가 쿠폰을 등록·발급하고 고객이 다운로드한 뒤, 발급 한도·유효기간·만료 처리를 검증한다.

**Acceptance Scenarios**:

1. **Given** 플랫폼 직매입 상품의 쿠폰을 MD가 직접 등록하면, **When** 등록을 완료하면, **Then** 승인 단계 없이 즉시 사용 가능 상태가 된다. (REQ-PRM-039)
2. **Given** 관리자가 쿠폰 적용 대상(타겟팅)을 설정하면, **When** 저장하면, **Then** 대상 정보가 보관된다. (REQ-PRM-043)
3. **Given** 관리자가 특정 회원에게 쿠폰을 임의 발행하면, **When** 실행하면, **Then** 즉시 지급되고 발급 완료 알림 이벤트가 발생한다. (REQ-PRM-044)
4. **Given** 고객이 쿠폰 다운로드를 요청하고, **When** 발급 한도(전체 한도, 1인당 1회) 이내이면, **Then** 발급된다. 한도가 0이면 무제한이며, 한도가 소진되었으면 "한도 소진", 이미 받은 쿠폰이면 "이미 수령" 사유로 서로 구분하여 거절된다. (REQ-PRM-046, DBA §2.6, Clarifications 2026-10-13)
5. **Given** 쿠폰 유효기간(최대 90일)이 지나면, **When** 자동 만료 처리가 수행되면, **Then** 쿠폰과 미사용 발급 건이 모두 만료 상태가 된다. 만료 처리가 지연되는 구간에도 유효기간 판정이 우선하여 만료된 쿠폰은 사용할 수 없다. (REQ-PRM-004, 047)
6. **Given** 사용 중이던 쿠폰의 주문이 취소·환불되면, **When** 쿠폰이 아직 유효기간 내이면, **Then** 쿠폰이 사용 가능 상태로 복원된다. 구매 확정 후에는 복원할 수 없도록 잠긴다. (DH §3, DI 이벤트 카탈로그)
7. **Given** 결제가 완료되어 쿠폰이 사용되면, **When** 사용이 확정되면, **Then** 정산에서 쿠폰 할인액을 반영할 수 있도록 쿠폰 사용 이벤트가 발생한다. (DI COUPON_USED)

### User Story 4 - 상품 노출 할인가 연동 (Priority: P2)

고객이 상품 목록·상세·검색 결과에서 보는 가격은 현재 적용 중인 할인가를 반영한다. 행사가가 시작·종료될 때 상품 쪽과 검색 쪽에 노출 할인가가 갱신되고,
상품 상세에서는 고객별 적용 가능 쿠폰과 예상 최저가를 실시간으로 보여준다.

**Why this priority**: 고객이 구매 결정을 하는 지점의 가격 정확성을 보장하지만, 계산(스토리 1)·정책(스토리 2) 이후에 붙는 연동 기능이다.

**Independent Test**: 행사가 시작/종료 시점에 노출 가격이 갱신·복원되는지, 상세 조회 시 예상 최저가가 올바른지 검증한다.

**Acceptance Scenarios**:

1. **Given** 행사가가 적용 중으로 전환되면, **When** 전환이 완료되면, **Then** 대상 상품의 노출 할인가가 계산되어 상품·검색 쪽에 전달된다. (REQ-PRM-050)
2. **Given** 행사가 기간 만료·수량 소진·수동 종료 중 어떤 이유로든 종료되면, **When** 종료되면, **Then** 노출 가격이 원래 판매가로 복원되도록 전달된다. (REQ-PRM-051)
3. **Given** 고객이 상품 상세를 열면, **When** 상품과 회원 정보로 실시간 할인가를 요청하면, **Then** 적용 중인 행사가/수량구간 할인, 적용 가능 쿠폰 목록, 예상 최저가를 돌려준다. (REQ-PRM-052)

### Edge Cases

- 같은 상품에 행사가와 수량구간 할인이 동시에 예약되려 하면 → 먼저 예약·적용 중인 건이 있으면 나중 등록은 거부된다(통합 택1).
- 시작일 1영업일 이내에 등록·확정을 시도하면 → 거부된다(예약 마감 위반).
- 쿠폰 만료 배치가 지연되어 상태가 아직 "사용 가능"이지만 유효기간이 지난 경우 → 유효기간 판정이 우선하여 사용 불가.
- 주문 취소 시점에 쿠폰 유효기간이 이미 지난 경우 → 복원되지 않고 만료 상태로 남는다.
- 장바구니 할인 조건 금액 판정 시 쿠폰·행사가 적용 전 정가 총액을 쓰면 안 된다 → 상품 할인 적용 후 총액 기준.
- 반려·만료된 쿠폰은 재활성화할 수 없다 → 신규 등록으로만 재운영.
- 다운로드 동시 요청이 몰려도 발급 한도를 초과하여 발급되어서는 안 된다.

## Requirements *(mandatory)*

### Functional Requirements

**할인·쿠폰 계산 (주문 연동)**

- **FR-001**: 시스템은 주문 요청 시 상품별로 적용 중인 가격할인(행사가 또는 수량구간 할인 중 상품당 1종)을 계산해 반환해야 한다. (REQ-PRM-001)
- **FR-002**: 시스템은 장바구니 할인 조건을 "상품 단위 할인 적용 후 주문 총액" 기준으로 평가하고 할인액을 반환해야 한다. (REQ-PRM-002)
- **FR-003**: 시스템은 쿠폰 사용 가능 여부를 검증하고 할인액 또는 사용 불가 사유(만료·사용됨·최소금액 미달·적용 상품 불일치)를 반환해야 한다. 사용 가능 판정은 상태와 유효기간을 반드시 함께 확인해야 한다. (REQ-PRM-003, 004)
- **FR-004**: 시스템은 회원·주문 정보로 해당 주문에 적용 가능한 보유 쿠폰만 걸러 할인액과 함께 반환해야 한다. (REQ-PRM-005)
- **FR-005**: 시스템은 수량구간 할인의 구간별 수량·할인율을 조회할 수 있어야 한다. (REQ-PRM-006)
- **FR-006**: 시스템은 할인차수를 "상품 단위 먼저, 주문 단위 나중"으로 고정하고, 상품↔주문 혜택의 누적과 같은 레벨 내 자동 적용↔쿠폰 중복을 허용해야 한다. 같은 레벨 내 혜택이 큰 쪽을 기본값으로 하되 고객이 주문서에서 변경할 수 있어야 한다. (DBA §2.7)
- **FR-007**: 시스템은 정률 할인에 대해 최대 할인금액 상한을 적용할 수 있어야 한다(자동 적용·쿠폰 구분 없음). 정액·균일가에는 적용하지 않는다. (DBA §2.7)
- **FR-008**: 시스템은 장바구니 쿠폰을 주문당 동시에 1건만, 상품 쿠폰을 상품(주문 항목)당 1장만 허용해야 한다. 주문 전체의 상품 쿠폰 수에는 상한을 두지 않는다. (REQ-PRM-048, Clarifications 2026-10-13)
- **FR-009**: 시스템은 배송비를 대상으로 하는 가격할인(자동 적용)과 배송비 쿠폰을 지원해야 한다. 배송비 할인은 입점사 단위 배송비에 정률로만 적용하며(무료배송=100%, 정액 차감 미지원), 수량 조건은 사용하지 않고 기간·금액·결제수단 조건만 사용한다. 최대 할인금액 상한(FR-007)을 적용할 수 있다. (REQ-PRM-070~077, DBA §2.2~2.4, Clarifications 2026-10-13)

**할인 정책 관리**

- **FR-010**: 관리자는 행사가를 등록하고, 행사 기간(필수)과 종료방식(기간형 또는 선착순형·제한 수량)을 지정할 수 있어야 한다. (REQ-PRM-010)
- **FR-011**: 관리자는 수량구간 할인과 장바구니 할인을 등록할 수 있어야 한다. 모든 프로모션 등록·운영은 단일 "관리자" 역할이 수행하며(역할 세분화 없음) 관리자가 아닌 주체의 등록·변경은 거절한다. (REQ-PRM-020, 030, 031, Clarifications 2026-10-13)
- **FR-012**: 시스템은 모든 할인 정책을 시작일 1영업일 전까지 등록·확정하게 하고, 확정 시 즉시 활성화하지 않고 예약 상태로 둬야 한다. (REQ-PRM-010, 020, 030)
- **FR-014**: 시스템은 동일 상품에 예약 또는 적용 중인 상품 가격할인(행사가·수량구간)을 동시에 1건만 허용해야 한다. 상품 쿠폰·장바구니 할인은 대상이 아니다. (REQ-PRM-007, 021)
- **FR-015**: 시스템은 장바구니 할인을 동시에 1건만 적용 중으로 허용하고, 시작일 도래 시 이미 적용 중인 건이 있으면 활성화를 보류해야 한다. (REQ-PRM-030-1, 032)
- **FR-017**: 시스템은 상태 전이 규칙을 강제해야 한다 — 작성 중 → 예약 → 적용 중 → 종료의 순서만 허용하고, 즉시 활성화·역행·종료 후 재활성화는 금지한다. (DH §1~4)

**쿠폰 관리**

- **FR-020**: 관리자(단일 역할)는 쿠폰을 등록하고 적용 대상(타겟팅)을 설정할 수 있어야 한다. 직매입 상품 쿠폰은 승인 없이 즉시 사용 가능 상태가 된다. (REQ-PRM-039, 043)
- **FR-021**: 관리자는 특정 회원에게 쿠폰을 임의 발행하거나 일괄 발급할 수 있고, 발행 즉시 지급되어야 한다. (REQ-PRM-044)
- **FR-022**: 고객은 쿠폰을 다운로드할 수 있어야 하며, 전체 발급 한도(0이면 무제한)와 1인당 1회 제한을 넘는 발급은 거절되어야 한다. 거절 사유는 "한도 소진"과 "이미 수령"을 구분해 반환하며 대기열 발급은 하지 않는다. 동시 요청이 몰려도 발급 건수는 한도를 초과하지 않는다. (REQ-PRM-046, DBA §2.6, Clarifications 2026-10-13)
- **FR-023**: 시스템은 쿠폰 유효기간 만료 시 쿠폰과 미사용 발급 건을 일괄 만료 처리해야 한다. 쿠폰 유효기간은 최대 90일이다. (REQ-PRM-047)
- **FR-024**: 시스템은 결제 완료 시 쿠폰 발급 건을 사용 완료로 확정하고, 주문 취소·환불 시(유효기간 내) 사용 가능으로 복원하며, 구매 확정 후에는 복원할 수 없게 잠가야 한다. (DH §3, DI)
- **FR-025**: 시스템은 반려되거나 만료된 쿠폰을 재활성화할 수 없게 해야 하며, 반려 시 사유를 기록해야 한다. (DH §2)

**상품 노출가 연동**

- **FR-030**: 시스템은 행사가가 적용 중으로 전환되거나 종료될 때 대상 상품의 노출 할인가를 계산해 상품·검색 쪽에 전달해야 한다. (REQ-PRM-050, 051)
- **FR-031**: 시스템은 상품 상세 조회 시 회원별로 적용 중인 할인, 적용 가능 쿠폰 목록, 예상 최저가를 실시간 계산해 반환해야 한다. (REQ-PRM-052)

**이벤트 발행 (타 도메인 연동)**

- **FR-040**: 시스템은 쿠폰 발급 완료, 쿠폰 사용, 쿠폰 복원, 행사 종료, 노출가 변경을 사실로 알리는 이벤트를 발행해야 하고, 주문 취소·구매 확정 알림을 수신해 쿠폰 상태를 갱신해야 한다. (DI 이벤트 카탈로그)

### Key Entities

- **쿠폰(Coupon)**: 발급 가능한 쿠폰 정의. 종류(상품 쿠폰/장바구니 쿠폰/배송비 쿠폰), 유효기간, 발급 한도, 최소 주문금액, 적용 대상, 상태(사용 가능/만료/반려 등)를 가진다.
- **쿠폰 발급 건(Coupon Issue)**: 회원에게 발급된 개별 쿠폰. 상태는 사용 가능 → 사용 완료 → (복원 시) 사용 가능, 또는 만료. 유효기간 판정은 부모 쿠폰의 유효기간을 따른다.
- **행사가(Discount Event)**: 기간 동안 대상 상품 판매가를 자동 인하하는 가격할인. 종료방식(기간형/선착순형)과 선착순 잔여 수량을 가진다.
- **수량구간 할인(Quantity Discount)**: 구매 수량 구간별로 할인율이 다른 가격할인.
- **장바구니 할인(Cart Discount)**: 주문 총액 조건 충족 시 자동 적용되는 플랫폼 단위 할인. 쿠폰 방식의 "장바구니 쿠폰"과는 별개 개념이다.
- **노출 할인가(Display Sale Price)**: 상품 목록·상세·검색에 보이는, 적용 중인 할인이 반영된 가격.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 주문서 진입 시 할인·쿠폰 계산 결과가 고객에게 표시되기까지 대부분의 요청(95%)이 1초 이내에 끝난다.
- **SC-002**: 사용 가능 판정, 택1 규칙, 장바구니 할인 1건 제한, 상태 전이 금지 규칙 위반으로 잘못된 혜택이 적용되는 사례가 0건이다(인수 시나리오 전수 통과 기준).
- **SC-003**: 관리자가 시작일 1영업일 전까지 행사가·수량구간 할인·장바구니 할인을 한 번의 등록·확정 절차로 예약까지 완료할 수 있다.
- **SC-005**: 쿠폰 발급 한도가 N인 쿠폰에 동시 요청이 몰려도 발급 건수가 한도를 초과하지 않는다.
- **SC-006**: 주문 취소 후 유효기간 내 쿠폰의 100%가 사용 가능 상태로 복원되고, 구매 확정된 건은 복원되지 않는다.
- **SC-007**: 고객이 상품 목록·상세·검색에서 보는 가격이 적용 중인 행사가와 일치하며, 종료 후에는 원래 가격으로 일관되게 표시된다.
- **SC-008**: 관리자 화면과 모바일 화면에서 프로모션 관련 개인정보(회원명·연락처 등)가 마스킹되어 노출된다.

## Assumptions

- 본 spec의 범위는 원본 설계 중 EARS 요구가 도출된 **쿠폰 관리·할인 정책 관리·Order/Catalog 연동·노출가 관리**이다.
- **이벤트·기획전 생성·운영·참여**(상위 UC 이벤트·기획전관리 그룹)는 정책 미확정으로 원본에서도 EARS가 없다(부록 A, REQ-PRM-060번대 예정). 본 spec에서 제외하고 후속 spec으로 다룬다.
- **입점사(partner) 쿠폰 등록·승인·반려·비활성화**(REQ-PRM-040~042, 045)는 원본에서 "협의 대기"(도메인정의서에 partner 채널 미정의)이므로 범위에서 제외한다. 직매입 쿠폰의 즉시 활성화(REQ-PRM-039)와 관리자 직접 운영만 포함한다. 확정되면 별도 이슈로 편입한다.
- **할인 정책의 시작·종료 자동 전환, 종료 시 가격 복원·가격 변경 안내, 선착순 수량 소진 종료**(REQ-PRM-010-1, 011, 012, 013, 020-1; 구 FR-013·FR-016)는 2026-10-13 clarify에서 범위 제외로 결정했다. 이 spec은 정책 등록(예약)과 계산·연동만 다루며, 자동 전환·복원은 별도 spec으로 편입한다. 그 전까지 FR-015·FR-017·FR-030이 말하는 "적용 중/종료 전환"은 전환 트리거가 정의되지 않은 상태 규칙이다.
- **포인트 적립·사은품 지급** 혜택유형은 DBA 정책 축에는 있으나 요구사항(EARS)이 없고 포인트 소유 도메인도 미확정(Human Review #4)이므로 본 범위에서 제외한다.
- **결제수단 조건**은 조건 정의만 하고 실제 검증은 하지 않는다(PG 실연동 Out-of-Scope, D6A Q9).
- 쿠폰 회원 제한은 전체 / 회원등급 / 특정 회원 3종으로 한다(DBA §2.5).
- 의존: Order(쿠폰·할인 계산 요청, 주문 취소·구매 확정 알림), Catalog(할인 대상 상품, 노출가 갱신), Member(쿠폰 발급 대상, 등급 변경 시 등급 쿠폰 자동 발급 — 2~4차 파트), Settlement·Notification(쿠폰 사용·발급 이벤트 수신, 2~4차 파트).
- 프로토타입 단계에서는 데이터 변경이 영속화되지 않을 수 있으나 요청·응답 계약은 실 운영과 동일하다(헌법 VI).
- 모든 금액은 원화 정수 기준이며, 회원 정보는 마스킹하여 다룬다(헌법 I).
- 원본 Human Review 미해결 항목(결제수단 코드, 포인트 적립 방법 상세, 배송비 쿠폰 유형 추가, 제한수량 0 허용 규칙, 가격할인×주문 수량 조건 지원)은 계획(plan) 단계 이전에 확정이 필요한 후속 항목으로 남긴다.
