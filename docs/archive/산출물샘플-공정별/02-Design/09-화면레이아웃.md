# 샘플: 화면 레이아웃(확정) (Design, Bolt)

## 채널별 완성 경로

| 채널 | 완성 경로 | 이 Bolt 해당 여부 |
|---|---|---|
| admin/partner | md → tsx 직행 (시니어 Dev + AI) | ✅ 주문상세·결제정보 탭 (admin) |
| mobile (고객웹) | md → Figma → tsx (기획자 → 디자이너 → Dev) | ✅ 주문서 결제 화면 (mobile) |

> **작업 순서**: admin/partner 화면을 먼저 진행하여 API 계약을 확정한 뒤, mobile 화면을 후행 진행한다.

---

## [admin] 주문상세 — 결제정보 탭 (md → tsx 직행)

| UI 요소 | 호출 API | 시점 |
|---|---|---|
| 결제정보 탭 진입 | `GET /admin/orders/{id}/payment` | 탭 클릭 |
| 결제취소 버튼 | `POST /admin/orders/{id}/cancel` | onClick |
| 처리 결과 토스트 | - | API 응답 수신 시 |

- 스펙 작성: 시니어 Dev + AI
- 검증규칙: PAYMENT_COMPLETED 상태에서만 결제취소 버튼 활성화
- state: `orderDetail.paymentStatus`, refresh trigger: 취소 API 성공 시 상세 재조회

---

## [mobile] 주문서 — 결제하기 (md → Figma → tsx)

### md 스펙 (기획자 + AI 작성 → Dev 검토·승인)

| UI 요소 | 호출 API | 시점 |
|---|---|---|
| 결제수단 선택 라디오 | - | 로컬 상태 |
| 결제하기 버튼 | `POST /orders/{id}/payment` | onClick |
| 결제 진행 스피너 | - | 요청 중(300ms 지연 후 표시) |
| 결제 완료/실패 화면 | - | 응답에 따라 분기 |

- 검증규칙: 결제수단 미선택 시 버튼 비활성화
- state: `paymentStatus`(REQUESTED/APPROVED/FAILED), refresh trigger: API 응답 수신 시

### Figma 시안 필수 항목 (디자이너/기획자 + AI 작성 → PM 승인)

| 항목 | 내용 (예시) |
|---|---|
| Figma 링크 | `https://figma.com/file/xxx/주문서-결제?version-id=v2-확정` |
| 디자인 토큰 | Primary: #3B82F6, Text: #1F2937, spacing-md: 16px |
| 컴포넌트 명세 | Figma `PaymentButton` → React `PaymentSubmitButton` |
| 상태별 시안 | default / loading(스피너) / success(완료) / error(실패) |
| 인터랙션 스펙 | 버튼 탭 → 0.3s 후 스피너 표시 → 결과 화면 fade-in |
| 핸드오프 체크리스트 | ☐ 간격 확인 ☐ 폰트 사이즈 ☐ 터치 영역 44px ☐ 다크모드 |
