# Payment 도메인 수용기준 (GWT)

| 항목 | 내용 |
|---|---|
| 산출물 ID | SPEC-GWT-PAYMENT-001 |
| Scope | Bolt (Payment 도메인) |
| 상태 | DRAFT-v1 |
| 작성일 | 2026-07-30 |
| 입력 자산 | 04-기능요구사항(EARS)/04-Payment.md (33개 EARS) |

> **Payment 도메인 특성**: 프로토타입에서 사실상 미구현(전용 화면 0개)이며,
> 결제 정보는 Order 상세의 "결제정보" 탭에서만 간접 조회된다.
> 이 GWT는 본개발 구현 기준으로 작성하되, 프로토타입 범위는 우선순위로 구분한다.
>
> **제약사항**: CONS-004(토스페이먼츠 단일 PG), CONS-005(미지원 결제수단 제외)

| AC-PAY-003 | 예외 | PG에 결제 승인 요청을 전송한 상태이다 | PG로부터 결제 승인 실패 응답을 수신한다 | 시스템이 실패 사유를 기록하고 Order 도메인에 결제실패 이벤트를 발행한다 | REQ-PAY-003 |
| AC-PAY-004 | 예외 | PG로부터 FDS 이상거래 거부 응답을 수신했다 | 결제 실패 처리가 실행된다 | 시스템이 실패 사유를 기록하고 Order 도메인에 결제실패 이벤트를 발행하며, 운영팀에 이상거래 감지 알림을 추가 발송한다 | REQ-PAY-003 |
| AC-PAY-005 | 정상 | PG 통신이 실패했다(네트워크 에러) | 결제 승인 요청에 대한 PG 응답 실패를 수신한다 | 시스템이 동기 재시도 없이 비동기 최대 3회까지 재시도한다 | REQ-PAY-004 |
| AC-PAY-006 | 예외 | 비동기 재시도 3회 모두 실패했다 | 마지막 재시도가 실패한다 | 시스템이 최종 실패로 확정하고 Order 도메인에 결제실패 이벤트를 발행한다 | REQ-PAY-005 |
| AC-PAY-007 | 예외 | PG 승인 금액이 30,000원이고 주문 금액이 25,000원이다(불일치) | 금액 일치 검증이 수행된다 | 시스템이 해당 결제를 즉시 취소하고 운영팀에 알림을 발송한다 | REQ-PAY-006 |
| AC-PAY-008 | 경계값 | PG 승인 금액과 주문 금액이 동일하다(25,000원) | 금액 일치 검증이 수행된다 | 시스템이 정상으로 판단하고 결제 프로세스를 계속한다 | REQ-PAY-006 |
| AC-PAY-009 | 정상 | PG 결제 승인이 완료되었다 | 시스템이 결제수단 정보를 저장한다 | 시스템이 카드번호 등 원본 정보를 저장하지 않고 PG 토큰만 저장한다 | REQ-PAY-007 |
| AC-PAY-010 | 정상 | PG로부터 콜백이 수신되었고 서명(Signature)이 포함되어 있다 | 시스템이 콜백 서명 검증을 수행한다 | 시스템이 서명이 유효하면 콜백을 정상 처리한다 | REQ-PAY-034 |
| AC-PAY-011 | 예외 | PG로부터 콜백이 수신되었고 서명 검증이 실패했다 | 시스템이 콜백 서명 검증을 수행한다 | 시스템이 콜백을 거부하며 위조 시도 로그를 기록한다 | REQ-PAY-034 |
| AC-PAY-012 | 정상 | 거래번호 TX-001의 PG 콜백을 이미 1회 처리했다 | 동일 거래번호 TX-001의 PG 콜백이 재수신된다 | 시스템이 최초 1회만 처리하고 이후 수신은 무시한다(멱등성) | REQ-PAY-035 |

| AC-PAY-019 | 예외 | PG 환불 비동기 재시도 3회 모두 실패했다 | 마지막 재시도가 실패한다 | 시스템이 최종 실패로 확정하고 운영팀에 수동 처리 요청을 발송한다 | REQ-PAY-014 |
| AC-PAY-020 | 정상 | 고객 귀책 클레임에서 추가 배송비 5,000원 결제가 필요하다 | Order 도메인으로부터 추가배송비결제 요청 이벤트를 수신한다 | 시스템이 추가 결제(ExtraPayment)를 생성하고 고객에게 결제 요청을 발송하며, 고객 승인 시 PG 승인을 요청한다 | REQ-PAY-015 |
| AC-PAY-021 | 정상 | 결제가 PAID 상태이고 Order 도메인에서 재고선점 실패/타임아웃으로 승인취소가 필요하다 | Order 도메인으로부터 승인취소 이벤트를 수신한다 | 시스템이 PG에 승인취소 요청을 전송하고 결제 상태를 CANCELLED로 전환한다 | REQ-PAY-036 |
| AC-PAY-022 | 경계값 | 결제가 PENDING 상태(PG 승인 진행 중)이고 승인취소가 필요하다 | Order 도메인으로부터 승인취소 이벤트를 수신한다 | 시스템이 진행 중인 PG 요청을 취소(또는 승인 완료 시 즉시 승인취소)하고 CANCELLED로 전환한다 | REQ-PAY-036 |
