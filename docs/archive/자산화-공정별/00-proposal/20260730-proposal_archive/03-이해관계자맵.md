## 방법론 역할 체계와의 매핑 (겸임 구조)

`runNshop_project_management_v1_0.md` 3.5절은 PM·TL·DE·QA·AI CoE·AM(Asset Manager)·Dev
7개 역할과 "5인 이하 팀 겸임 가이드"(TL이 AI CoE 겸임, PM이 AM 겸임, DE가 QA 겸임)를 정의한다.
이걸 실제 인물에 매핑하면:

| 방법론 역할 | 실제 담당 | 확정 여부 |
|---|---|---|
| PM (공정 전이 판단, 일정 조율) | 페페 | 확정 |
| Tech Lead (기술 의사결정) | 페페 | 확정 |
| AI CoE (프롬프트 표준·AI 도구 관리) | 페페 (Claude를 직접 운용) | 확정 |
| Asset Manager (자산 등록·현행화, O3 KR3-1 담당) | 페페(현재) → **신규 합류 시니어 2명**(8/1·9/1 합류 후 이관) | 확정 |
| 도메인 전문가 / QA | 페페(현재) → **신규 합류 시니어 2명**(합류 후 이관) | 확정 |
| Dev | 페페(현재, Kiro를 실행 도구로 직접 운용) → **신규 합류 개발자 2명**(9월 중순 합류 후 이관) | 확정 |
| 기획 (가이드 v2.2 부록C 신설 역할, Front 화면기획) | 페페 | 확정 |

> **확정 (사업 오너 확인, 2026-07-28)**: 신규 인력 합류 전까지는 위 **7개 역할(3.5절 기준
> PM·TL·DE·QA·AI CoE·AM·Dev + 가이드 부록C 신설 "기획") 전부를 페페 1인이 겸임**한다. Claude·Kiro는
> 역할을 보유한 이해관계자가 아니라 페페가 그 역할을 수행할 때 쓰는 AI 실행 도구다. 신규 인력의
> 역할 배정도 확정됐다 — **시니어 2명(8/1·9/1)은 도메인 전문가(DE)/QA + Asset Manager(AM) 겸임,
> 개발자 2명(9월 중순)은 Dev**를 이관받는다. PM·TL·AI CoE·기획은 계속 페페가 담당한다(이관 대상
> 아님).

## 외부 이해관계자 여부

`runNshop_project_management_v1_0.md`는 일반화된 SI 방법론 문서라 "고객사"·"현업 MD"·"CS팀" 등
외부 이해관계자를 폭넓게 정의하지만(Track 1·6 참고), 이 정의들이 **runNshop Initiative에 실제로
적용되는지는 확인되지 않았다** — 즉 runNshop이 3TOP의 내부 이니셔티브(자체 자산화 목적)인지,
외부 발주처가 있는 프로젝트인지가 이 문서 corpus 안에서 명시적으로 드러나지 않는다.
