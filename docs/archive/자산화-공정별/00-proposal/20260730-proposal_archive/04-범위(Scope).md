## 스코프 변경 이력

- **착수 초기**: "설계 + 일부 구현"(9대 공정 설계 산출물 + Mock 기반 프로토타입) —
  `runNshop_policy_v1_2.md` 20장 프로토타입 정책과 일치.
- **이후**: 방법론 검증을 위해 "전체구현"으로 확장하는 논의가 시작됨(사업 오너 확인, 2026-07-24).
- **2026-07-27**: 전체구현은 아직 검토 대상이며 확정되지 않음 — 그때까지 확정된 범위는 주문
  (Order) 모듈 1차 구현뿐이었다.
- **확정** (사업 오너 확인, 2026-07-28): **전체 12개 도메인을 전부 구현하기로 확정**했다.
  진행 순서는 **1차 주문(Order)/결제(Payment)부터** 시작하고, 이후 도메인은 순차 진행한다
  (구체적 순서·시점은 아직 미정 — Human Review #1).
- **2026-07-30 (사업 오너 확인) — Out-of-Scope 재분류**: "보안, CS·마케팅은 Scope으로 하고
  나머지는 범위제외로 합니다"로 확정 — 인프라 보안과 운영·CS·마케팅 시스템을 In-Scope로
  편입하고, 외부 PG 실연동만 계속 Out-of-Scope로 남긴다. Human Review #2(제외 항목 리스크
  수용 여부)를 이 결정으로 해소했다.

## 도메인별 완성도 — 다수 도메인이 미완성 상태이며 자산화 대상에 포함

도메인기능표(`docs/자산화/참고자료/도메인기능표/`)에 따르면, "1차 확정 = 주문/결제"라는 이번
스코프 결정과 별개로 **12개 도메인 전체에 걸쳐 다수 도메인이 미완성 상태**다 — 고객화면(mobile)·
배치·컨슈머(비동기 처리) 계층이 전 도메인 공통으로 미착수이고, admin·partner에 화면이 있는
도메인도 초안 수준이다(1차 대상인 Order·Payment 두 도메인만 봐도 착수 수준이 서로 크게 다름).
이건 결함이 아니라 착수 순서상 당연한 현재 상태다(도메인기능표 README "현재 진행 상태 안내"
참고).

**이 "도메인별 완성도" 자체가 O3(자산화)의 추적 대상에 포함되어야 한다** — `02-목표KPI.md`
KR3-1(Asset Registry 메타데이터: 유형·공정·도메인·범위·상태·민감도)의 "상태" 항목이 각 도메인
산출물의 실제 완성도를 반영하도록 연결하는 게 자연스럽다. 단순히 Proposal 단계의 참고 서술로
끝내지 않고, O3 실행 시 도메인기능표를 완성도 추적의 1차 자료로 계속 갱신·활용해야 한다는 뜻이다.

## In/Out Scope

| 구분 | 내용 |
|---|---|
| **In-Scope (확정)** | **전체 12개 도메인 구현**(도메인별 세부 구성·전시(Display) 편입 등은 위 "참고자료" 도메인기능표가 최신 원본) + AI활용 방법론 검증(Bolt 단위 반복) + **보안 전체**(UI/UX 흐름 10개 항목 + **인프라 보안**(HTTPS·Nginx 접근통제·IP제한·JWT 실검증·FDS) — 2026-07-30 확정으로 인프라 레벨까지 실제 구현) + **운영·CS·마케팅 시스템**(2026-07-30 신규 In-Scope 편입) |
| **진행 순서 (확정)** | **거래(1차, Order+Payment, 진행 중) → 상품(2차, Catalog+Promotion+Search) → 고객(3차, Member+Community+Notification) → 파트너·운영(4차, Vendor+Settlement+Config+Audit)** — 도메인기능표 "4파트 분할 시 공수 균형"(각 파트 50~92 프로토타입 MD로 균형) 근거로 2026-07-30 사업 오너 확인. 구체적 착수 시점은 아직 미정(Human Review #1). 인프라 보안·운영·CS·마케팅 시스템이 어느 파트에 속하는지는 미배정(Human Review #4) |
| **Out-of-Scope** | 외부 PG 실연동뿐(2026-07-30 기준 — 인프라 보안·운영·CS·마케팅 시스템은 In-Scope로 편입되며 Out-of-Scope 목록에서 제외됨) |

> **명확화(2026-07-30 갱신)**: 착수 초기엔 인프라 레벨 보안(HTTPS·JWT 실검증 등)과 운영·CS·
> 마케팅 시스템을 Out-of-Scope로 뒀었으나, 2026-07-30 사업 오너가 **둘 다 In-Scope로 편입**
> 확정했다 — 이제 Out-of-Scope는 외부 PG 실연동 하나뿐이다. 이 결정은 `runNshop_policy_v1_2.md`
> §20.5-1("보안 요건 프로토타입 처리 기준" — 인프라 보안은 프로토타입에서 기본 미적용)의 기본
> 방침을 **의도적으로 오버라이드**한 것이라는 점을 명시해둔다 — 정책서 근거가 아니라 순수 사업
> 판단이다.

## 제외 항목의 리스크 수용 여부 (휴먼 의사결정 포인트)

방법론 가이드 6.1절이 이 산출물의 핵심 의사결정 포인트로 정의하는 항목. **2026-07-30 사업 오너
확인으로 인프라 보안·운영·CS·마케팅 시스템이 In-Scope로 편입**돼 아래 표에서 제외됐다 — 더 이상
"제외했으니 리스크를 감수할지" 판단할 대상이 아니라 직접 구현 대상이 됐기 때문. 남은 Out-of-Scope
항목은 외부 PG 실연동 하나뿐이다.

| Out-of-Scope 항목 | 잠재 리스크 | 리스크 수용 여부 |
|---|---|---|
| 외부 PG 실연동 | 프로토타입 단계 결제 로직 미검증 — 실 연동 시 재작업 가능성 | **수용** (2026-07-30, 범위 유지 확정과 함께 — 프로토타입 종료 후 실연동 시 재작업 필요성을 감수) |
