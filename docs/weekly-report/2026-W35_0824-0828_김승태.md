### 2.3 (08/27 13:55) 할인 vs 쿠폰 종류 구분 개념 매핑

- ERD에 "개념 구분: 할인 vs 쿠폰" 섹션 신설 — 할인은 테이블 자체(대상상품 자식테이블 유무)로, 쿠폰은 `coupon_type` 컬럼으로 구분
- "장바구니 할인(자동 적용, §9.2) ≠ 장바구니 쿠폰(발급형, §9.1)" 비교표 작성, 상태머신에 교차 참조 주석 추가

### 2.4 (08/27 16:47) 쿠폰 만료 판정 원칙 및 장바구니 할인 비교기준 정합화

- 쿠폰 사용 가능 판정식 확정: `status=AVAILABLE AND now≤valid_to` (상태 단독 판정 금지 — 만료 배치 지연 구간 오판 방지), valid_to는 부모 `prm_coupon` 참조로 명시
- 만료 배치의 역할을 "판정 전제"에서 "조회성능/통계/알림용 캐시 갱신"으로 재정의
- 쿠폰 복원(USED→AVAILABLE)에 유효기간 내 조건 가드 추가
- 장바구니 할인 조건금액 비교기준을 "정가 총액" → "상품할인(행사가/수량구간+상품쿠폰) 적용 후 총액"으로 정정 ("상품 먼저, 플랫폼 나중" 원칙)
- PlantUML §5 평가 프로세스 start=end 크래시 버그 수정
- 영향 문서 DE/DF/DG/DH/DI 전반 정합화 — 2차 교차검증으로 잔여 갭 정정(상태머신 전이 가드 expired_at→prm_coupon.valid_to, ERD condition_amount 컬럼 노트, DH 근거표, valid_to 출처 주석)

## 3. 확정된 주요 결정사항

| 결정 | 내용 |
|------|------|
| SCHEDULED 예약활성화 상태 도입 | 정책서 §3.7 근거로 행사가·수량구간·장바구니 할인에 DRAFT→SCHEDULED→ACTIVE→ENDED 전이 확정. 등록 즉시 활성화 금지, start_at 도래 시 배치 자동 전환 |
| 쿠폰 사용 가능 판정 = status+기간 조합 | `status=AVAILABLE AND now≤valid_to`를 반드시 함께 검증. 상태 단독 판정 금지(만료 배치 지연 구간 오판 방지). valid_to는 발급 건이 아닌 부모 쿠폰 소유 |
| 장바구니 할인 비교기준 정정 | condition_amount 비교 대상은 정가 총액이 아니라 상품 단위 할인 적용 후 총액 — "상품 먼저, 플랫폼 나중" |
| 파일명 채번 체계 06~12 → DC~DI 전환 | Catalog/Promotion 전체 문서에 적용, 향후 신규 도메인도 동일 체계 사용 |
| 작업범위 Promotion 도메인 한정 | steering 문서로 명문화. 타 도메인 문서는 열람·참조만 하며 직접 수정 금지 |
