# 샘플: 화면 레이아웃

> **단계**: 상세설계
> **문서범위**: Bolt
> **문서종류**: Design
>
> **작성 목적**: 시퀀스(⑯)에서 확정된 API 호출 시점과 응답 데이터를 화면에 매핑한다.
> "어떤 화면에서 어떤 데이터를 어떤 API로부터 가져와 표시하는가"를 확정한다.
>
> **흐름 내 위치**:
> ```
> ⑯ 시퀀스 → ⑰ 화면 레이아웃
> ```
>
> **작성 주체**: 
> - admin/partner: 시니어 개발자 + AI (md → tsx 직행)
> - mobile: 기획자 + AI (md → Figma → tsx)

---

## 채널별 완성 경로

| 채널 | 경로 | 이유 |
|---|---|---|
| admin/partner | md(스펙) → tsx(React) 직행 | 내부 운영 도구, 디자인 자유도 낮음 |
| mobile | md(스펙) → Figma(디자인) → tsx(React) | 고객 대면, UX 중요, 디자이너 협업 필요 |

---

## 샘플: 장바구니 화면 (mobile)

### 화면 구성

| 영역 | 데이터 소스 (API) | 표시 내용 |
|---|---|---|
| Header | — | "장바구니" 타이틀 + 뒤로가기 |
| 상품 목록 | GET /api/v1/cart | 상품이미지, 상품명, 옵션명, 수량, 단가, 소계 |
| 할인 정보 | GET /api/v1/cart (응답 내 포함) | 적용된 행사가, 장바구니 할인 혜택 |
| 수량 변경 | PATCH /api/v1/cart/items/{id}/quantity | +/- 버튼, 재계산 |
| 삭제 | DELETE /api/v1/cart/items/{id} | 스와이프 or 체크박스 삭제 |
| 합계 영역 | 계산 (FE) | 상품합계, 할인합계, 배송비, 최종결제금액 |
| CTA | POST /api/v1/checkout | "주문하기" 버튼 → 주문서 화면 이동 |

### 상태별 UI

| 상태 | 화면 표현 |
|---|---|
| 장바구니 비어있음 | 빈 상태 일러스트 + "쇼핑하러 가기" 버튼 |
| 품절 상품 포함 | 해당 아이템 비활성화 + "품절" 배지, 주문하기 시 제외 안내 |
| 로딩 중 | 스켈레톤 UI |
| 에러 | 토스트 메시지 (CART_FULL 등) |

## 작성 규칙

| 규칙 | 설명 |
|---|---|
| 영역별 API 매핑 필수 | "이 데이터가 어디서 오는가" 명시 |
| 상태별 UI 정의 | 빈 상태, 로딩, 에러 상태 포함 |
| CTA(행동 유도) 명시 | 주요 버튼과 다음 화면 이동 |
| 인터페이스 명세(⑮) 참조 | API 경로·응답 필드명 일치 |

---

## 작성 팁

| 팁 | 설명 |
|---|---|
| **API 응답 필드 = 화면 표시 항목** | 인터페이스 명세에 없는 필드가 필요하면 명세 보완 |
| **admin은 테이블 중심** | 목록(DataGrid) + 상세(Form) 패턴 반복 |
| **mobile은 카드/리스트 중심** | 스크롤·무한 로딩·스와이프 패턴 |
| **Figma 가이드 필요 시** | mobile 채널은 이 문서 → Figma 디자인 → 개발 순서 |
