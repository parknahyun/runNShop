# 샘플: 인터페이스 명세

> **단계**: 상세설계
> **문서범위**: Bolt
> **문서종류**: Spec
>
> **작성 목적**: GWT(⑬)의 예외를 에러코드로, 세부UC(⑭)의 행위를 endpoint로 변환하여
> API 계약(요청·응답·에러)을 확정한다.
> Frontend와 Backend 간의 명시적 계약 문서.
>
> **흐름 내 위치**:
> ```
> ⑬ GWT + ⑭ 세부UC → ⑮ 인터페이스 명세 → ⑯ 시퀀스
> ```
>
> **작성 주체**: 시니어 개발자 + AI 협업 (FE 개발자 검토)

## 샘플: 장바구니 담기 API

### POST /api/v1/cart/items — 장바구니 담기

| 항목 | 내용 |
|---|---|
| Method | POST |
| Path | /api/v1/cart/items |
| 인증 | Bearer {userId} (필수) |
| 설명 | 상품을 장바구니에 추가. 동일 상품+옵션 존재 시 수량 합산 |

#### Request Body

```json
{
  "productId": "prod-001",
  "skuId": "sku-001",
  "quantity": 2
}
```

#### Response 200 (성공)

```json
{
  "code": "SUCCESS",
  "data": {
    "cartItemId": "cart-001",
    "productId": "prod-001",
    "skuId": "sku-001",
    "quantity": 2,
    "unitPrice": 15000,
    "totalCartCount": 5
  }
}
```

#### Error Responses

| HTTP | code | message | 조건 | 대응 GWT |
|---|---|---|---|---|
| 400 | CART_FULL | 장바구니가 가득 찼습니다 (최대 50개) | 장바구니 50개 초과 | AC-ORD-004 |
| 400 | PRODUCT_NOT_AVAILABLE | 현재 구매할 수 없는 상품입니다 | 품절·판매중지 | AC-ORD-007 |
| 400 | INVALID_QUANTITY | 수량은 1~99 사이여야 합니다 | 수량 범위 초과 | AC-ORD-008 |
| 401 | UNAUTHORIZED | 로그인이 필요합니다 | 토큰 없음/만료 | — |

## 작성 규칙

| 규칙 | 설명 |
|---|---|
| GWT 예외 1개 = 에러코드 1개 | GWT에서 식별된 예외마다 에러코드 정의 |
| 세부UC 행위 1개 = endpoint 1개 | 세부UC의 "API 호출" 행이 endpoint |
| 응답 구조 표준 | `{ "code": "SUCCESS", "data": {...} }` |
| 에러 구조 표준 | `{ "code": "ERROR_CODE", "message": "...", "detail": "..." }` |
| Path Prefix 규칙 | `/api/v1/**` 고객, `/api/admin/v1/**` 어드민, `/api/partner/v1/**` 입점사 |

---

## 작성 팁

| 팁 | 설명 |
|---|---|
| **에러코드는 GWT에서 도출** | GWT 예외 시나리오의 Then절 = 에러 응답 |
| **요청 파라미터는 세부UC에서** | 세부UC Step의 "사용자 입력" = request body |
| **응답 필드는 화면에서** | 화면 레이아웃(⑰)에서 필요한 데이터 = response 필드 |
| **Mock 우선** | 프로토타입 단계에서는 Mock 응답으로 시작 |
