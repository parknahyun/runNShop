# 샘플: 세부 유스케이스

> **단계**: 상세설계
> **문서범위**: Bolt
> **문서종류**: Design
>
> **작성 목적**: 상위 유스케이스(⑥)를 버튼·화면 단위 행위로 분해한다.
> "사용자가 화면에서 어떤 순서로 무엇을 하는가"를 UI 흐름 수준으로 기술하여,
> 인터페이스 명세(⑮)의 endpoint 도출 근거가 된다.
>
> **흐름 내 위치**:
> ```
> Bolt 분할 → ⑬ GWT → ⑭ 세부 유스케이스 → ⑮ 인터페이스 명세
> ```
>
> **작성 주체**: 기획자 + 개발자 협업

---

## 샘플: 장바구니 담기 Bolt

### 기본 흐름

| Step | 액터 | 행위 | 시스템 응답 | 비고 |
|---|---|---|---|---|
| 1 | 고객 | 상품상세 화면에서 옵션 선택 | 선택된 옵션 표시, 가격 갱신 | |
| 2 | 고객 | 수량 입력 (기본 1) | 수량 × 단가 소계 표시 | |
| 3 | 고객 | "장바구니 담기" 버튼 클릭 | API 호출: POST /api/v1/cart/items | |
| 4 | 시스템 | — | 성공 응답 + 장바구니 뱃지 수량 갱신 | |
| 5 | 고객 | "장바구니 바로가기" 또는 쇼핑 계속 | 장바구니 화면 이동 or 현재 유지 | |

### 대안 흐름

| 조건 | Step 변경 | 결과 |
|---|---|---|
| 이미 동일 상품+옵션이 장바구니에 있음 | Step 4에서 수량 합산 | 기존 수량 + 새 수량 |
| 장바구니 50개 초과 | Step 4에서 거부 | "장바구니가 가득 찼습니다" 토스트 |
| 품절 상품 | Step 3 전에 버튼 비활성화 | "품절" 표시, 담기 불가 |

---

## 작성 팁

| 팁 | 설명 |
|---|---|
| **1 Bolt = 1 세부UC** | 동일 범위 |
| **행위 = 버튼 클릭 수준** | "결제한다"가 아닌 "결제하기 버튼 클릭" |
| **시스템 응답에 API 명시** | 인터페이스 명세(⑮) 도출 근거 |
| **대안 흐름 = GWT 예외** | GWT의 예외 시나리오와 대응 |
