# 샘플: 비즈니스 프로세스 (Design, Domain: Order, 스윔레인)

> **선행 산출물**: 상태머신(전이 트리거를 액티비티로 확장)
> **Scope**: Domain
> **대상 플로우**: 주문결제 핵심 플로우 (장바구니→결제완료→배송→구매확정)

---

## 정상 흐름: 주문결제~구매확정

```plantuml
@startuml
|고객|
start
:장바구니에서 상품 선택;
:"주문하기" 클릭;

|주문시스템|
:주문 초기 데이터 생성 (TEMP);
:주문서 데이터 반환;

|고객|
:배송지·포인트·결제수단 선택;
:필수 약관 동의;
:"결제하기" 클릭;

|주문시스템|
:주문 상태 TEMP → PROCESSING;
:Catalog 도메인에 재고선점 이벤트 발행;

|Catalog|
:재고선점 처리;
:선점 결과 반환;

|주문시스템|
if (재고선점 성공?) then (성공)
  :Payment 도메인에 결제요청 이벤트 발행;
else (실패)
  :주문 CANCELLED 전환;
  :고객에게 품절 안내;
  stop
endif

|Payment|
:PG(토스페이먼츠) 승인 요청;
if (PG 승인?) then (성공)
  :결제 상태 PAID;
  :Order 도메인에 결제완료 이벤트 발행;
else (실패/타임아웃)
  :결제 상태 FAILED;
  :Order 도메인에 결제실패 이벤트 발행;
endif

|주문시스템|
if (결제완료 이벤트?) then (수신)
  :주문 상태 PAYMENT_COMPLETED;
  :주문 확정 알림 발송 요청;
else (결제실패 이벤트)
  :선점 재고 복원;
  :주문 상태 CANCELLED;
  :고객에게 결제 실패 안내;
  stop
endif

|판매자|
:출고 처리 (PREPARING);
:운송장 등록 (IN_DELIVERY);

|배치(시스템)|
:배송상태 갱신 (60분 주기);
if (배송완료 확인?) then (완료)
  :주문 상태 DELIVERED;
else (미완료)
  :다음 배치에서 재확인;
endif

|고객|
if (구매확정 버튼?) then (수동 확정)
  :주문 상태 CONFIRMED;
else (미클릭)
endif

|배치(시스템)|
if (배송완료 후 7일 경과?) then (자동확정)
  :주문 상태 CONFIRMED;
  :정산 대상 포함;
endif

stop
@enduml
```

## 예외 흐름

| ID | 예외 | 분기 시점 | 처리 |
|---|---|---|---|
| E1 | 재고선점 실패(품절) | PROCESSING 진입 직후 | CANCELLED 전환 + 품절 안내 (REQ-ORD-058) |
| E2 | PG 승인 실패 | PG 응답 수신 | 재고 복원 + CANCELLED + 실패 안내 (REQ-ORD-095) |
| E3 | 3분 타임아웃 | PROCESSING 상태 3분 초과 | 재고 복원 + CANCELLED + 실패 안내 (REQ-ORD-078) |
| E4 | 고객 단순 취소 | PAYMENT_COMPLETED 상태 | Payment에 취소 이벤트 + 재고 복원 + CANCELLED (REQ-ORD-006) |
| E5 | 출고 기한 초과 | PAYMENT_COMPLETED 1영업일 초과 | 지연 안내 발송 (REQ-ORD-082) |
| E6 | 배송 미진행 3일 | IN_DELIVERY 상태 3일 미변동 | 지연 안내 발송 (REQ-ORD-083) |

## 시작/종료 조건

| 항목 | 조건 |
|---|---|
| 시작 조건 | 고객이 장바구니에서 1개 이상 상품을 선택하고 "주문하기" 클릭 |
| 정상 종료 | 주문 상태가 CONFIRMED (정산 대상 포함) |
| 예외 종료 | 주문 상태가 CANCELLED (재고 복원·환불 완료) |
