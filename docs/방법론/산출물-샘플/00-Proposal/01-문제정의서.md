# 샘플: 문제 정의서 (Proposal, Initiative 단위)

> Scope: Initiative. 원본: `docs_ai/00-proposal/01-문제정의서.md`(runNshop 전체 대상 소급 작성본)의
> 발췌·압축. 상세 BPIO 전문·Human Review·근거매핑은 원본 문서 기준.

**Background**: 3TOP 2본부가 러닝 전문 B2C 이커머스 "runNshop"을 신규 구축하며, 초기 워터폴식
9대 공정에서 AI 협업이 체계적으로 되지 않는 문제를 겪어 Bolt 단위 반복 구조의 "AI활용 개발공정
가이드"를 만들고, 이를 진행 중이던 runNshop에 재적용해 검증한다.

**Problem**: ①자산화 부재(핵심) ②AI 협업 프로젝트의 산정 불확실성(#1의 가장 구체적 증상)
③개발 패러다임 변화와의 정합(방법론적 근거).

**Impact**(방법론 없이 방치 시): ①AI 협업 경험 부재→산정(비용·기간) 실패(baseline 16억원/
6개월/1,000만원 대비 비교 근거 없음) ②자산 미정리→향후 프로젝트의 사업리딩·설계·구현 부족
③방법론(산출물정의·선후행관계·표준양식) 부재→자산화 보완작업 반복(Task Spec v1.0 결함
Section 5건·Template 4건 실측).

**Opportunity**: ①비용 30% 절감(11.2억원) + 산정 모델 자체를 자산으로 확보 ②방법론 자산화
(뷰티샵 등 타 프로젝트 재사용 예정) ③자산 보완의 효과 실증(v1.1 재검증 0건) ④자산 재사용
범위 극대화(3TOP은 개발업체이지 운영업체가 아니므로, 기회는 "이 사업의 수익성"이 아니라
"검증된 자산의 타 client 재사용 범위").
