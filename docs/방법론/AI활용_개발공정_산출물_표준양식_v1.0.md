# AI 활용 개발 공정 — 산출물 표준양식 (전 공정 40종)

**버전: 1.0 (초안)**
**관련 문서**: `AI활용_개발공정_가이드_v2.2` 6장(공정별 산출물 상세), `AI활용_개발공정_프롬프트_라이브러리_v2.0.md`(40종 전체 프롬프트 샘플 수록)
**목적**: 6장이 정의한 "입력자료·AI초안·휴먼결정포인트"에 더해, 각 산출물이 **구체적으로 어떤 항목(구조)에
어떤 내용을 담아야 하는가**를 정의한다. 6장과 중복하지 않도록, 여기서는 **필수 항목(표준양식)**만 다룬다.

---

## 0. 공통 원칙

- **AI 협업 전제**: 모든 산출물은 4.1절 실행 사이클(Asset Selection → AI Generation → Human Review
  → Artifact Finalization → Asset Management)로 만들어진다. 아래 "필수 항목"은 AI Generation
  단계에서 AI가 채워야 할 항목이며, Human Review는 5.1절 품질기준(완전성·일관성·추적성·실행가능성·
  정책준수)으로 판정한다.
- **표준양식의 두 단계**: ① 이 문서(가이드 6장 + 여기)가 정의하는 **최소 필수 항목**으로 우선
  작성해본다. ② O3(자산화) 자기완결성 검증에서 부족함이 드러나면(Task Spec 사례처럼) 그 산출물만
  **전용 표준양식**으로 별도 정교화한다 — 처음부터 40종 모두 전용 표준양식을 만들 필요는 없다.
- **출처 추적**: 모든 산출물은 `source_*` 필드(또는 "근거 자료 출처 매핑" 섹션)로 입력 자료를
  역추적할 수 있어야 한다(추적성 기준).
- **Gap 표기 원칙**: 원본 자산에 근거가 없는 항목은 추정으로 채우지 않고 "확인 필요"로 명시한다
  (00-proposal 6종 작성에서 이미 실증된 원칙).
- **파일 형식 원칙**: 모든 산출물은 기본적으로 **Markdown(.md)** 문서 하나로 작성한다. ERD·상태머신·
  시퀀스·의존성맵처럼 구조화된 서브 표기가 필요한 항목은 표준 표기법(**DBML/PlantUML/
  OpenAPI YAML**)을 .md 안에 **코드블록으로 내장**하는 것을 기본으로 하고, 도구 연동(Swagger 검증,
  dbdiagram.io, CI 파이프라인 등)이 실제로 필요해지는 시점에만 그 블록을 별도 파일(.yaml/.dbml/.puml)로
  추출한다 — 처음부터 파일을 쪼개 관리 부담을 늘리지 않는다. 유일한 예외는 **"코드 구현"**으로,
  이건 산출물 자체가 실제 소스코드(언어별 확장자)와 Mock 데이터(.json)라 처음부터 별도 파일이다.
  아래 각 표의 "파일 형식(권장)" 열은 이 원칙을 산출물별로 구체화한 것이다.
- **다이어그램 표기법은 PlantUML로 통일**(Mermaid 미사용, 페페 확인 2026-07-28): 시퀀스·클래스설계가
  이미 PlantUML을 쓰고 있어, 상태머신·비즈니스프로세스(액티비티/스윔레인)·컴포넌트·상위유스케이스·
  의존성맵 등 나머지 다이어그램 유형도 전부 PlantUML로 맞춰 렌더러·문법을 하나로 통일한다. (트레이드오프:
  Mermaid는 GitHub 등에서 플러그인 없이 바로 렌더링되는 반면 PlantUML은 별도 렌더 서버/플러그인이
  필요하다 — 이 프로젝트는 일관성을 우선한다)
