# 프로젝트 컨벤션 가이드 (Project Conventions Guide)

> **목적**: 프로젝트 산출물(Artifact)과 구분되는 "프로젝트 컨벤션(Process Asset)"의 정의, 전체 목록, 수립 시점, 참고 관계를 정의한다.
> **작성일**: 2026-08-12

---

## 1. 프로젝트 컨벤션이란

### 정의

| 구분 | 산출물 (Artifact) | 프로젝트 컨벤션 (Process Asset) |
|---|---|---|
| 성격 | 프로젝트 수행의 결과물 | 조직이 축적하는 참고 기준 |
| 범위 | 도메인/Bolt 단위 | 크로스 도메인 (Project 전체) |
| 수명 | 프로젝트 기간 중 생성·확정 | 프로젝트를 넘어 반복 재사용 |
| 흐름에서 위치 | **수직** (S0→S1→…→S5 단계별 생성) | **수평** (각 단계 산출물을 옆에서 참고) |
| 강제성 | 단계별 게이트 통과 조건 | 비강제 — 없어도 진행 가능, 있으면 속도·품질 향상 |
| 축적 시점 | (해당 없음) | 파일럿: 산출물과 동시 / 실제 프로젝트: 프로젝트 종료 시 보완(버전업) |

### 수평 참조 구조

```
           ┌── A-1 ──┐ ┌── A-2 ──┐ ┌── A-3 ──┐ ┌── A-N ──┐
           │  참고     │ │  참고    │ │  참고    │ │  참고    │
           ↓          ↓ ↓         ↓ ↓         ↓ ↓         ↓
  S0 ───→ S1 ───→ S2 ───→ S3 ───→ S4 ───→ S5
  (착수)  (요구)  (구조)  (상세)  (구현)  (테스트)
```

- 자산은 수직 파이프라인에 끼어들지 **않는다** (블로커 아님)
- 각 단계의 산출물이 해당 자산을 **참고**하여 일관성과 속도를 확보
- 자산 미비 시: 현업이 즉시 판단 → 결정사항은 프로젝트 종료 시 자산에 역축적

### 축적 사이클

```
[기존 프로젝트 컨벤션] ──참고──→ [산출물 작성 (현업 판단)]
                                    │
                                    ▼ (프로젝트 종료 시)
[프로젝트 컨벤션 버전업] ←──축적──────────┘
```

- **파일럿**: 프로젝트 컨벤션 = 산출물과 동시 생성 (초판 축적)
- **실 프로젝트**: 프로젝트 컨벤션은 참조 자료로 존재, 프로젝트 결과가 종료 시 반영(보완)

## 2. 프로젝트 컨벤션 전체 목록

| ID | 자산명 | 범주 | 내용 요약 |
|---|---|---|---|
| A-1 | 아키텍처 제약사항 | 기술 | 기술스택, 레이어 구조, 도메인 경계, 외부 연동 방식, 금지 패턴 |
| A-2 | 코딩 컨벤션 | 기술 | 네이밍, 패키지구조, 예외처리, 트랜잭션, 테스트 작성 규칙 |
| A-3 | 디자인 시스템 | UX | Foundation / Component / Pattern / Layout / Template |
| A-4 | API 설계 규칙 | 기술 | URL Path 체계, 응답 포맷, 에러 코드 체계, 버저닝 |
| A-5 | 데이터 모델링 규칙 | 기술 | 네이밍(접두사), PK 전략(ULID), 인덱스 규칙, Soft Delete 정책 |
| A-6 | 이벤트 설계 규칙 | 기술 | 이벤트명 컨벤션, payload 스키마, 멱등성, 재시도 정책 |
| A-7 | 테스트 전략 | 품질 | 단위/통합/E2E 범위, 커버리지 기준, 테스트 데이터 정책 |
| A-8 | 보안 정책 | 보안 | 인증/인가 체계, 데이터 암호화, PII 마스킹, 세션 관리 |
| A-9 | 용어 사전 | 업무 | 업무 도메인 용어 통일 (한/영 매핑, 약어, 동의어 금지) |
| A-10 | UX Writing 가이드 | UX | 에러 메시지, 버튼 레이블, 알림 문구 톤앤매너 |

## 3. 수립 데드라인 (최초 참고 산출물 기준)

**원칙**: 해당 자산을 처음 참고하는 산출물이 시작되기 전에 초판이 수립되어야 함.

| 자산 | 최초 참고 산출물 | 수립 데드라인 | 수립 근거 |
|---|---|---|---|
| A-9 용어 사전 | ③ 도메인 정의서 | **S1 시작 전** | 용어가 모든 산출물의 기초 어휘 |
| A-8 보안 정책 | ② NFR | **S0 중** | NFR 보안 항목 도출 시 참고 |
| A-1 아키텍처 제약사항 | ③ 도메인 정의서 / ④ 컴포넌트 구조 | **S1 말 ~ S2 시작 전** | 기술스택·레이어가 컴포넌트 구조 결정 |
| A-5 데이터 모델링 규칙 | ⑨ ERD | **S2 ERD 작성 전** | PK전략, 접두사, 인덱스 규칙 |
| A-6 이벤트 설계 규칙 | ⑫ 이벤트 플로우 | **S2 이벤트플로우 작성 전** | 이벤트명, payload, 멱등성 규칙 |
| A-4 API 설계 규칙 | ⑮ 인터페이스 명세 | **S3 인터페이스명세 작성 전** | URL Path, 응답 포맷, 에러 코드 |
| A-3 디자인 시스템 | ⑰ 화면 레이아웃 | **S3 화면레이아웃 작성 전** | 컴포넌트/레이아웃이 화면설계의 어휘 |
| A-10 UX Writing 가이드 | ⑰ 화면 레이아웃 | **S3 화면레이아웃 작성 전** | 에러메시지, 버튼텍스트 일관성 |
| A-2 코딩 컨벤션 | ⑲ 클래스 설계 | **S3 클래스설계 작성 전** | 네이밍·패키지가 클래스설계 어휘 |
| A-7 테스트 전략 | 단위테스트 (구현단계) | **S4 구현 시작 전** | 테스트 범위·기준이 코드 구조에 영향 |

## 4. 타임라인 시각화

```
단계     S0-착수      S1-요구      S2-구조        S3-상세           S4-구현
         │            │            │              │                │
자산     A-8 보안정책  A-9 용어사전  A-1 아키텍처    A-4 API설계규칙   A-7 테스트전략
수립     │            │            A-5 데이터규칙   A-3 디자인시스템   │
데드라인 │            │            A-6 이벤트규칙   A-10 UX Writing   │
         │            │            │              A-2 코딩컨벤션     │
         ▼            ▼            ▼              ▼                ▼
산출물   NFR          도메인정의    ERD            인터페이스명세     코드구현
(참고)   ←A-8        ←A-9         ←A-1,A-5      ←A-4             ←A-2,A-7
                      컴포넌트     이벤트플로우    화면레이아웃
                      ←A-1        ←A-6           ←A-3,A-10
                                                 클래스설계
                                                 ←A-2
```

## 5. 산출물 ↔ 프로젝트 컨벤션 참고 매핑 (상세)

| 산출물 | 참고하는 프로젝트 컨벤션 | 참고 목적 |
|---|---|---|
| ② NFR | A-8 보안정책 | 보안 요구사항 도출 기준 |
| ③ 도메인 정의서 | A-9 용어사전, A-1 아키텍처 | 용어 일관성, 도메인 경계 기준 |
| ④ 컴포넌트 구조 | A-1 아키텍처 | 레이어·모듈 분리 기준 |
| ⑧ EARS | A-9 용어사전 | 요구사항 기술 시 용어 통일 |
| ⑨ ERD | A-5 데이터 모델링 규칙 | PK, 네이밍, 인덱스 일관성 |
| ⑩ 상태머신 | A-5 데이터 모델링 (status enum) | status 값 네이밍 규칙 |
| ⑫ 이벤트 플로우 | A-6 이벤트 설계 규칙 | 이벤트명, payload 구조 일관성 |
| ⑮ 인터페이스 명세 | A-4 API 설계 규칙 | URL, 응답 포맷, 에러 코드 |
| ⑯ 시퀀스 | A-1 아키텍처, A-6 이벤트 | 트랜잭션 경계, 이벤트 발행 규칙 |
| ⑰ 화면 레이아웃 | A-3 디자인 시스템, A-10 UX Writing | UI 컴포넌트 어휘, 문구 톤 |
| ⑲ 클래스 설계 | A-2 코딩 컨벤션 | 네이밍, 패키지 구조 |
| 코드 구현 | A-2 코딩 컨벤션, A-7 테스트 전략 | 구현·테스트 기준 |
| 코드 리뷰 | A-2, A-4, A-5, A-6 (전체) | 규칙 준수 확인 |

## 6. 파일럿 vs 실 프로젝트 차이

| 항목 | 파일럿 (runNshop) | 실 프로젝트 |
|---|---|---|
| 자산 생성 시점 | 산출물 작성과 **동시** | 프로젝트 **착수 전** 초판 존재 |
| 자산 = 산출물? | 사실상 동일 (만들면서 축적) | **별개** (자산은 독립 유지보수) |
| 자산 갱신 시점 | 수시 (산출물 확정 즉시) | 프로젝트 **종료 시** 보완·버전업 |
| 자산 부재 시 | 현업 즉시 판단 (파일럿이므로 무방) | 기준 부재 → 일관성 리스크 (사전 수립 권장) |
| 자산 확정 주체 | 시니어 + AI (작성과 동시) | TL/아키텍트가 프로젝트 전 확정 |

## 7. 방법론 반영 요약

현행 방법론에서 변경할 포인트:

| 문서 | 변경 사항 |
|---|---|
| 지침서 3.3 "자산활용" | "프로젝트 컨벤션" 용어 도입, 전체 목록 참조 링크 |
| 지침서 각 단계 | `*자산: ...` → `*참고 프로젝트 컨벤션: A-N (비강제)*` 표기로 변경 |
| 표준양식 | "프로젝트 컨벤션 목록" 별도 테이블 (산출물 테이블과 분리) |
| 작성가이드 | 각 산출물 "선행 산출물" 옆에 "참고 프로젝트 컨벤션" 항목 추가 |
| 산출물 흐름 | 프로젝트 컨벤션 수평 참조 다이어그램 추가 |
