> 핵심 책임: 쿠폰·행사가·수량 할인·기획전·사은품·이벤트(출석/룰렛/응모/퀴즈 등) 등 혜택 정책을
> 정의하고 관리한다.

> **진행 상태 전제(2026-07-28)**: 고객화면(mobile)·배치·컨슈머(비동기 처리)는 아직 미착수,
> admin·partner도 초안 작업 상태 — 아래 N/A·스텁·dead code 발견은 결함이 아니라 진행 전 상태.
> 상세는 `README.md`의 "현재 진행 상태 안내" 절 참고.

**API 호출 개수 카운트 기준**: 화면/탭 로드 1개 = API 1개, 실제 제출 버튼 1개 = API 1개(취소·
편집토글·행 삭제(저장 전까지 로컬 반영)·검색팝업 내 "선택/추가"처럼 최종 저장 시에만 백엔드에
반영되는 UI 전용 조작은 제외). 화면/코드 자체가 없는 기능은 "N/A"로 표기(추정치를 억지로 만들지
않음).

  워크플로우를 공유 — 도메인정의서엔 이 승인 단계가 명시돼 있지 않았음.
- **기획전이 단순 "등록·게시"가 아니라 다른 프로모션 유형들을 묶는 캠페인 컨테이너**임을 확인
  (admin `promotion/exhibition`의 PromotionsTab).
- **쿠폰 타겟팅**(전체/등급별/엑셀 임의지정)과 **임의발행**(CS가 개별 회원에게 즉석 발급)은
  서로 다른 기능 — 하나는 대량 발행 조건, 하나는 개별 예외 처리.
- **customer 앱(mobile)**: 쿠폰 적용·포인트 사용은 체크아웃 화면의 비활성 스텁 버튼으로만 존재
  — 쿠폰함(보유쿠폰 목록) 조회 화면 자체가 없음(Member 도메인 갭과 연결).
- **API 호출 개수 산정(2026-07-28)**: 11개 소분류 중 10개를 산정, N/A 1건(약 40개 API). "쿠폰
  승인/반려(MD)"는 partner `CouponPage`/`CouponDetail`에 `PENDING_APPROVAL`/`REJECTED` 상태값과
  목록 필터·요약카드는 있지만, 그 상태를 실제로 바꾸는 승인/반려 버튼이 admin·partner 어디에도
  없음을 확인 — 벤더 등록(`CouponRegister`)과 비활성화(`CouponDetail` "비활성화" 버튼)는 partner
  쪽에 구현돼 있는데, 그 사이의 심사 단계만 코드가 비어 있는 상태(스텁조차 아닌 완전한 갭).
  admin `promotion/quantity-discount`도 partner `promotion/qty-discount`와 마찬가지로
  "벤더 등록→승인대기→활성/반려" 상태값(`PENDING_APPROVAL`/`REJECTED`)을 가진 벤더용 화면이
  별도로 존재하는데(admin은 `ACTIVE`/`ENDED`만 쓰는 MD 직접관리 화면이라 승인 개념이 없음),
  "수량 할인 관리" 소분류는 도메인정의서 문구가 admin의 구간(tier) 빌더와 정확히 일치해 admin
  기준으로 산정했다 — 쿠폰과 동일한 벤더-승인 갭이 수량할인에도 그대로 있다는 신호.
  기획전은 상세 탭 5개(기본정보/상품관리/소속 프로모션/미리보기/변경이력) 중 미리보기·변경이력을
  "등록·게시"(전체 라이프사이클 관리) 소분류로 묶어 산정했다.
- **신규 추가(채널 확장, 2026-07-28)**: 고객(M)·배치(B)·컨슈머(C) 채널 소분류 5건 추가 —
  쿠폰 다운로드/사용(고객), 쿠폰 만료 처리(배치), 기획전 상품 조회(고객), 할인 적용 계산(컨슈머).
  모두 mobile·배치·비동기 처리 미착수 상태이며, 정책 근거는 `runNshop_policy_v1_2.md` 9장.
- **신규 추가(이벤트관리, 2026-07-29)**: 기존 3개 소분류를 15개로 세분화 —
  고객참여(6건): 이벤트 목록·상세 조회/출석체크/룰렛·복권형/응모형 참여/참여이력·당첨확인/공유.
  MD운영(7건): 이벤트 생성·기본설정/스케줄링/대상자타겟팅/당첨자추첨·발표/경품재고·발송/성과분석/배너·랜딩.
  입점사협찬(2건): 상품·경품 협찬/참여현황 조회.
  `apps/` 전체에서 관련 키워드(attendance, roulette, quiz 등) 코드 근거 0건, 순수 신규 공백.
  랭킹이벤트는 `07-Vendor.md`의 판매랭킹 통계(성과통계)와는 목적이 다른 별개 개념(게이미피케이션).
  카드사 할인·번들할인은 여전히 사업 판단 보류 상태.
- **신규 추가(사은품·성과분석·연동, 2026-07-29)**: 보류했던 4건 중 3건 추가 반영 — ① 대분류
  "사은품관리" 신설(사은품 정책 관리(MD)/확인·선택(고객)/대상 상품 확인(입점사) 3개 소분류, 전부
  코드·정책 근거 없는 신규 공백). ② 대분류 "성과분석" 신설(프로모션 성과 조회(MD)·참여 실적
  조회(입점사) 2개 소분류) — `07-Vendor.md`의 매출/클레임 성과통계와는 별개인 프로모션·이벤트
  전용 지표(클릭수·참여율·전환율·쿠폰사용률 등)로, 코드 근거 없음. ③ "쿠폰 적용 상품 등록
  (입점사)"은 신규 소분류가 아니라 기존 "쿠폰 타겟팅" 행 비고에 보강 — 상품 타겟팅의 실제 주체가
  벤더(등록 시점)가 아니라 admin(MD, 승인 후 별도 단계)이라는 프로세스 차이를 명시. ④ "혜택 적용
  내역 조회(고객)"는 대분류 "연동"에 BC 대상 행으로 추가(채널=C) — Order(주문상세)·Member(쿠폰함/
  포인트내역)가 실제 소유자이고 Promotion은 데이터만 제공한다는 점을 명시, "Promotion이 하지
  않는 것" 목록에도 반영. 카드사 할인·번들할인은 여전히 사업 판단 보류 상태로 남김.
