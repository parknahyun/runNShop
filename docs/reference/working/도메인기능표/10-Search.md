## 코드 기반 보완 (2026-07-28, apps/ 실제 소스 조사)

admin·partner 어디에도 Search 전용 관리 화면이 없음(인기검색어 관리 화면 포함 — MD 수동 관리라
되어 있지만 실제 UI 없음). 고객 앱(mobile) 검색 화면도 "아직 구현되지 않았습니다" 완전 스텁 —
Header에 검색 아이콘 링크만 있고 키워드 입력·자동완성·필터 UI 전혀 없음. **Search 도메인은
프로토타입에서 admin/customer 양쪽 다 화면 0개.**

## 코드 기반 보완 (2026-07-29, 회원/운영자/입점사 일반 기능표 대조 검토)

- **신규 추가 8건**: 인기 검색어 조회(고객)/검색 필터(고객)/검색 정렬(고객)/판매자 검색(고객)
  (이상 "검색" 대분류), 인기 검색어 관리(운영자)/검색 품질 관리(운영자)(신규 대분류
  "검색운영관리"), 검색 분석(운영자)/검색 노출·순위 확인(입점사)(신규 대분류 "검색분석"). 인기
  검색어·검색 필터·검색 정렬은 `runNshop_policy_v1_2.md` §14.2~14.4에 항목까지 구체적으로
  명시돼 있음에도 표에 행 자체가 없었던 누락이었다(§14.3 필터는 카테고리·브랜드·가격대·성별·
  사이즈·평점·배송 7항목, §14.2 정렬은 최신순·인기순·낮은가격순·높은가격순·리뷰많은순·
  평점높은순 6종 — 사용자가 제시한 일반 커머스 기준의 "정확도순"·"판매순"·"판매자/색상/재고
  필터"는 이 정책엔 없어 제외). 검색 품질 관리·검색 분석·검색 노출순위·판매자 검색 4건은
  코드·정책 근거가 전무한 "개념만 존재하는" 신규 공백으로, Human Review 대상임을 명시.
- **BC 대상(별도 논의)**: 검색 최적화(입점사 — 상품명·키워드·브랜드정보·카테고리·속성 관리)는
  `02-Catalog.md`의 상품등록/속성관리 필드에 이미 귀속된 항목이라 Search 신규 불필요 — "키워드
  최적화(SEO)"라는 별도 목적의 필드·화면은 코드·정책 어디에도 없음을 확인.
- **콘텐츠 유형별 검색(카테고리·브랜드·기획전·이벤트·리뷰·FAQ/공지)**: 각 콘텐츠의 조회/
  브라우징 자체는 이미 해당 도메인(05-Promotion·09-Community·11-Config)에 등재돼 있어, 이
  콘텐츠들을 "검색 결과 조회(고객)" 한 행으로 대표시켰다 — 상품 외 콘텐츠까지 포괄하는 통합검색
  확장은 코드·정책 근거가 없어 신규 행을 만들지 않고 이 노트로만 남긴다.
