## 코드 기반 보완 (2026-07-28, apps/ 실제 소스 조사)

Payment 전용 화면은 admin·partner 어디에도 없음 — 결제 정보는 Order 상세의 "결제정보" 탭에서만
조회된다(admin). 고객 앱(mobile) 주문서의 결제수단 선택 탭은 로컬 상태 토글만 되고 실제 PG 연동·
결제 실행은 전부 스텁이며, 결제 완료 화면 자체가 없다 — 이 도메인은 **프로토타입에서 사실상
미구현**(Payment 도메인 자체 화면 0개)임을 확인. 기존 6개 소분류는 도메인정의서 근거로 유효하나,
실제 코드로 검증된 것은 하나도 없다. 신규 추가 5개(PG 결제 요청·응답 처리, 결제 취소/환불 처리,
부분환불 처리, 결제 내역 조회, 결제 수단 관리)는 도메인 역할 정의에 따라 **구현 예정 기능**으로
등재했다.
- **일반 이커머스 체크리스트 대조(2026-07-29)**: 페페가 결제수단/결제진행/증빙/실패재결제/
  해외·자동결제/취소환불/결제이력 등 표준 체크리스트로 보완 대상을 검토해달라고 요청했다.
  먼저 정책서 §12.1("지원 결제수단")을 재확인한 결과 **신용카드(1단계)+간편결제(2단계: 카카오
  페이·네이버페이·토스) 딱 2가지만 정책 범위**임을 확인 — 체크리스트의 계좌이체·무통장입금·
  휴대폰결제·해외결제·자동결제(정기결제)·부분결제는 "미구현 갭"이 아니라 **정책상 명시적으로
  범위 밖**이라 신규 소분류로 추가하지 않았다(도입 여부는 Human Review).
  - **확실 반영(A) 10개**: 결제 성공/실패 모니터링·결제 실패 로그 확인(신규 대분류
    "결제모니터링"), PG/간편결제 연동 관리·결제수단 활성화비활성화 관리·결제 정책 설정
    (신규 대분류 "PG관리"), 복합결제 처리(§12.3 포인트+카드 적용순서·환불방식까지 정확히
    명시)·재결제(결제처리 "복합결제·재결제" 중분류 신설), 환불 진행상태 조회(고객)·결제내역
    조회(고객)·결제내역 조회(입점사, 체크리스트의 "결제완료 확인" 흡수)를 결제조회에 추가.
  - **BC 대상(B) 6개**: 포인트·쿠폰 금액 반영(연동, BC=Order·Member·Promotion), 영수증
    조회(BC=Order — `01-Order.md`에 이미 있음), 세금계산서 신청(BC=Settlement —
    `06-Settlement.md`에 이미 있음), 정산 데이터 연계(BC=Settlement), 결제상태별 주문
    조회(입점사, BC=Order), 판매·정산 예정금액 확인(입점사, BC=Settlement) — 전부 신규
    "정산·증빙연계" 대분류(정산연계 3건)와 결제처리(포인트쿠폰반영)·결제조회(영수증조회)에
    분산 반영하고, 비고에 BC 대상 도메인을 명시했다. 결제금액 계산(할인·배송비 포함 최종금액,
    회원)은 이미 Order 주문서 PriceSummary의 표시 요소로 존재해 신규 행을 만들지 않았다.
  - **정책 인용 오류 정정**: 기존 행들의 정책참조가 전부 "8장"으로 표기돼 있었는데, 정책서
    목차를 재확인한 결과 "8장"은 클레임·CS 관리 정책이고 결제는 **"12장"(결제 관리 정책)**
    이었다 — 기존 행 전체를 §12.1~12.5 세부 조항까지 포함해 정정했다.
