## CUS-010 — 카테고리 목록 (mobile, 일반기능 기준)

> **소스 상태**: `apps/runNshop-mobile/app/category/[categoryCode]/page.tsx`가 존재하지만 **"카테고리 화면은 아직 구현되지 않았습니다"** 안내 문구만 렌더링한다(실제 UI 미구현). 아래는 원본 화면정의서(§2.2 상품 카드 유형, §2.4 CUS-010 "전시페이지 CATEGORY")와 CUS-001의 전시 페이지 패턴을 근거로 재구성한 일반기능 기준 구조다.

### 메타정보

> **화면 ID**: CUS-010 · **화면명**: 카테고리 목록 · **유형**: 목록형
> **메뉴 경로**: GNB 카테고리 클릭 (`/category/{category_code}`) · **권한**: 전체
> **문서상태**: DRAFT-v1.0 (일반기능 기준, 실제 미구현 확인됨)

### 와이어프레임

```
┌─────────────────────────────┐
│ [Header][GNB] (공통)          │
├─────────────────────────────┤
│ 러닝화                        │ ← R1 카테고리 타이틀
├─────────────────────────────┤
│ [필터: 브랜드▾ 가격▾ 사이즈▾][F1]│ ← R2 필터바
├─────────────────────────────┤
│ [상품카드A][상품카드A]         │ ← R3 상품 그리드 (Type A, §2.2)
│ [상품카드A][상품카드A]         │   360×360, 행사아이콘 좌하단, 평점 노출
├─────────────────────────────┤

└─────────────────────────────┘
```

### 상세디스크립션

| 코드 | 이름 | 구분 |
|---|---|---|
| R1 | 카테고리 타이틀 | 영역 |
| R2 | 필터바 | 영역 |
| R2-F1 | 필터 적용 | 기능 |
| R3 | 상품 그리드 | 영역 |

| 항목 | 내용 |
|---|---|

> **Human Review**: 실제 구현이 안내 문구뿐이라 이 구조는 100% 추정이다. 실제 개발 시 이 문서를 초안으로 활용하되, 필터 항목·정렬 옵션 등 세부는 재확인 필요.

#### R4 — Toolbar (편집 모드 토글)

| 항목 | 내용 |
|---|---|
| 역할 | 비편집 모드에서는 [편집] 버튼만, 편집 모드에서는 [취소]/[저장] 버튼으로 전환 |
| 진입/노출 조건 | `editing` state 값에 따라 버튼 세트 전체 교체 |

| 코드 | 기능명 | 트리거 | 동작 | 검증/제약사항 |
|---|---|---|---|---|
| R4-F2 | 편집 | [편집] 클릭 | 현재 페이지 표시된 항목의 재고값을 `draft` state로 복제, 입력 필드로 전환 | 편집 대상은 **현재 페이지에 보이는 항목만**(`displayed` 전체가 아니라 화면에 표시된 것 기준 — 소스 `startEdit`이 `displayed.forEach`로 전체를 채우므로 실제로는 필터된 전체 대상. 페이지네이션과 무관하게 입력 필드는 테이블 렌더링 시 `pageItems`에만 나타남에 유의) |
| R4-F3 | 저장 | [저장] 클릭 | 변경된 SKU만 골라 `stock`·`status`(0이면 SOLD_OUT) 갱신, 변경 이력(R7)에 추가 | 값이 기존과 동일하면 이력에 남지 않음(`newStock === item.stock` 시 skip) |
