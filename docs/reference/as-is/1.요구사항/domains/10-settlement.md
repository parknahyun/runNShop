# runNshop 요구사항 정의서 — 10. 정산 (Settlement)

## FR-STL-001 정산 대상 등록
- **우선순위**: P1
- **내용**:
  - 구매확정 시 자동 등록 (stl_settlement_target)
  - 수수료율 스냅샷 저장 (확정 시점 기준)
  - 직매입 제외 (is_platform_direct=TRUE)

## FR-STL-002 월 정산 계산
- **우선순위**: P1
- **내용**:
  - 배치: SettlementCalculateBatch (매월 5일)
  - 계산: 매출 - 수수료 + 배송비 - 쿠폰분담 - 포인트분담 - 재정산 - 패널티 + 이월
  - 수수료: 카테고리 기본수수료율 - 입점사등급 감면율
  - 정산항목 유형(itemType): 매출(SALES)/판매수수료(FEE)/배송비 분담(SHIPPING)/포인트 분담(POINT_SHARE)/쿠폰 분담(COUPON_SHARE)/패널티(PENALTY)/전월 이월(CARRY_OVER) 7종으로 구분 관리 (프로토타입 기준)

## FR-STL-003 정산 확정
- **우선순위**: P1
- **내용**:
  - 정산담당 검토 후 확정
  - 이의제기 가능 기간: 확정일 + 5영업일
  - 입점사 알림: 정산 확정 + 이의제기 기간 안내
  - 이의제기 마감일은 확정일시 기준 영업일(주말 제외) 5일 후 날짜로 시스템이 자동 계산 (공휴일 미반영, 프로토타입 기준)

## FR-STL-004 이의제기 처리
- **우선순위**: P1
- **내용**:
  - 기간 내 입점사 BO에서 등록
  - 정산담당 수용/기각
  - PENDING 이의제기 있으면 지급 보류
  - 관련 테이블: stl_settlement_objection
  - 지급 보류 사유에 이의제기 건수/검토 상태가 함께 기록되어 지급 처리와 연동됨 (예: "입점사 이의제기 2건 검토 중 (지급 보류)")

## FR-STL-005 지급 처리
- **우선순위**: P1
- **내용**:
  - 지급일: 매월 15일 (SettlementPayBatch)
  - 최소 지급: 10,000원 (미만 시 이월, 3회 연속 강제 지급)
  - 지급 보류 조건 5가지 (부정거래·분쟁·세금계산서·계약위반·법적분쟁)
  - 계좌 오류 시 보류 후 재지급
  - 지급 상태: 지급예정(SCHEDULED)/지급완료(PAID)/보류(HOLD)/지급실패(FAILED) 4단계로 관리
  - 보류 처리 시 보류사유 입력 필수, 보류 해제 시 지급예정 상태로 복귀하며 보류사유 초기화
  - 계좌 이체 실패(FAILED) 시 재시도 배치(SettlementPaymentRetryBatch)가 재처리

## FR-STL-006 외부 정산
- **우선순위**: P2
- **내용**:
  - PG사·물류사·광고주 외부 정산 별도 관리
  - stl_external_settlement 테이블
  - 거래유형(partnerType): PG사/물류사/광고주 외 플랫폼(제휴) 정산도 포함하여 4종으로 관리
  - 상태: 청구대기(PENDING)/지급완료(PAID) 2단계로 관리
  - 정산 항목: 정산월, 거래유형, 거래처명, 청구금액, 지급금액, 청구일, 지급일, 설명
  - 관리 화면은 배치 자동 생성이 아닌 수기 등록/수정/삭제가 가능한 CRUD 성격
