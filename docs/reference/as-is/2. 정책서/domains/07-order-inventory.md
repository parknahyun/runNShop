## 7.1 주문 상태 정의

### 주문 상태값

| 상태 | 코드 | 설명 |
|------|------|------|
| 임시주문 | `TEMP` | 주문 요청 접수, 재고확보·결제 처리 대기 |
| 처리중 | `PROCESSING` | 비동기 재고확보·결제 처리 진행 중 (3분 타임아웃 → CANCELLED) |
| 결제완료 | `PAYMENT_COMPLETED` | 재고확보 + 결제 승인 완료 |
| 상품준비중 | `PREPARING` | 입점사 출고 준비 중 |
| 배송중 | `IN_DELIVERY` | 운송장 등록 완료, 배송 진행 |
| 배송완료 | `DELIVERED` | 배송사 완료 확인 |
| 구매확정 | `CONFIRMED` | 고객 수동 확정 또는 7일 자동 확정 |
| 주문취소 | `CANCELLED` | 결제 전·후 취소 처리 완료 |
| 반품접수 | `RETURN_REQUESTED` | 고객 반품 신청 완료, 수거 대기 |
| 반품진행중 | `RETURNING` | 수거 완료, 검수·환불 처리 중 |
| 반품철회 | `RETURN_WITHDRAWN` | 반품 신청 철회 (수거 전 고객 요청) |
| 반품완료 | `RETURNED` | 반품 확정, 환불 완료 |
| 교환접수 | `EXCHANGE_REQUESTED` | 고객 교환 신청 완료, 수거 대기 |
| 교환진행중 | `EXCHANGING` | 수거 완료, 교환 출고 처리 중 |
| 교환철회 | `EXCHANGE_WITHDRAWN` | 교환 신청 철회 (수거 전 고객 요청) |
| 교환완료 | `EXCHANGED` | 교환 출고 완료 |

### 주문 상태 전이 규칙

```
TEMP
    ├─ 동기: 재고확보 성공 + 결제 성공 → PAYMENT_COMPLETED
    ├─ 비동기: 처리 시작 → PROCESSING → PAYMENT_COMPLETED
    └─ 재고확보 실패 or 결제 실패 → CANCELLED

PROCESSING (비동기 전용)
    ├─ 재고확보 + 결제 성공 → PAYMENT_COMPLETED
    ├─ 3분 타임아웃 → CANCELLED + 보상 처리
    └─ 최종 실패 → CANCELLED + 보상 처리

PAYMENT_COMPLETED → PREPARING → IN_DELIVERY → DELIVERED
    ├─ 고객 확정 or 7일 경과 → CONFIRMED
    ├─ 반품 신청 (10일 이내)
    │   → RETURN_REQUESTED (반품접수)
    │       ├─ 수거 완료 → RETURNING (반품진행중) → RETURNED (반품완료)
    │       └─ 수거 전 철회 → RETURN_WITHDRAWN (반품철회) → DELIVERED 복귀
    └─ 교환 신청 (10일 이내)
        → EXCHANGE_REQUESTED (교환접수)
            ├─ 수거 완료 → EXCHANGING (교환진행중) → EXCHANGED (교환완료)
            └─ 수거 전 철회 → EXCHANGE_WITHDRAWN (교환철회) → DELIVERED 복귀
```

### 재고·상태 연동 규칙

| 상태 전이 | 재고 변화 | 비고 |
|----------|----------|------|
| TEMP 생성 | -1 (선점) | 30분 선점 유지 |
| CANCELLED (미결제) | +1 복구 | 선점 해제 |
| CANCELLED (결제후) | +1 복구 | 즉시 복구 |
| RETURNED | +1 복구 | 상품 상태 SOLD_OUT 유지 |
| EXCHANGED | ±0 | 동일 상품 옵션 변경 |

### 동기·비동기 처리 분기 기준

```
주문 내 MD 비동기 플래그 상품 포함 여부 확인
    ├─ 없음 → 동기 처리 (순차 블로킹)
    └─ 1개 이상 포함 → 비동기 처리 (이벤트 기반)
        → 주문 전체를 비동기 흐름으로 처리
```

> 재고확보 → 결제승인 처리 순서는 동기·비동기 공통 적용

## 7.2 주문 처리 기준

플랫폼은 고객 경험과 거래를 통합 관리하고, 판매 주체는 주문 이행을 책임하는 **역할 기반의 하이브리드 주문 운영 정책**을 적용한다.

- 고객은 플랫폼과 거래하며, 플랫폼이 주문 및 결제를 통합 관리한다.
- 직매입 상품은 플랫폼이 직접 출고 및 배송을 수행한다.
- 입점 상품은 Vendor Order 기반으로 입점사가 주문 이행을 수행한다.
- 고객 문의는 플랫폼이 1차 대응하며, 필요 시 입점사와 협업한다.
- 정산은 플랫폼이 통합 수행한다.

## 7.3 오류·보상 처리 정책

### 동기 처리 오류 기준

| 항목 | 기준 |
|------|------|
| 결제 승인 오류 재시도 | **없음** (즉시 실패 처리) |
| 보상 처리 재시도 | **1회** (재고·포인트·쿠폰 복원) |
| 보상 실패 시 | 운영팀 수동 처리 이관 |

```
결제 승인 오류 (재시도 없음)
    ↓
보상 처리 1회 시도
    ├─ 재고 복원 1회 → 실패 시 운영팀 이관
    ├─ 포인트 복원 1회 → 실패 시 운영팀 이관
    └─ 쿠폰 복원 1회 → 실패 시 운영팀 이관
```

### 비동기 처리 오류 기준

| 항목 | 기준 |
|------|------|
| 이벤트 처리 재시도 | **최대 3회** |
| 재시도 간격 | 즉시 → 30초 → 1분 (점진적 백오프) |
| 3회 실패 시 | DLQ 적재 → 운영팀 수동 처리 이관 |
| 적용 대상 | 결제 승인 / 재고·포인트·쿠폰 복원 |

```
이벤트 처리 실패
    ↓ 1차 재시도 (즉시)
    ↓ 2차 재시도 (30초 후)
    ↓ 3차 재시도 (1분 후)
    ↓ 최종 실패
DLQ 적재 → 운영팀 이관 + 모니터링 알림
```

### 모니터링 기준

| 항목 | 알림 조건 | 알림 대상 |
|------|----------|----------|
| 결제 승인 오류 (건별) | 건별 즉시 | 운영팀 |
| **결제 승인 오류 임계치** | **10분 내 2회 이상** | **관리자** |
| 재고·포인트·쿠폰 복원 실패 | 건별 즉시 | 운영팀 |
| DLQ 적재 | 건별 즉시 | 운영팀 |

### 운영팀 수동 처리 기준

| 항목 | 기준 |
|------|------|
| 이관 방식 | 모니터링 대시보드 + 카카오 알림톡 |
| 처리 기한 | 이관 후 1영업일 이내 |
| 처리 항목 | 재고 수동 복원 / 포인트 수동 지급 / 쿠폰 수동 재발급 |
| 처리 이력 | 운영 로그에 처리자·시각·내용 기록 |
| 고객 안내 | 처리 완료 후 고객 결과 알림 발송 |

## 7.4 장바구니 유효성 검사 정책

장바구니 진입 시 및 로그인 후 머지 시 다음 검사를 수행한다.

| 검사 항목 | 실행 시점 | 처리 방식 |
|---------|----------|---------|
| 장바구니 담기 시 검증 | 담기 요청 시 | 판매상태·재고·옵션·행사가격 유효성을 Catalog/Promotion PublicApi로 확인, 실패 시 담기 거부(REQ-ORD-059, 104) |
| 재고 확인 | 매번 (진입·머지) | 품절 SKU 비활성 처리·안내 |
| 행사 유효성 | 변경 시에만 | cart.carted_at vs 행사·상품 updated_at 비교 |

- 행사 변경(updated_at > carted_at) 감지 시 행사 정보 재조회·재계산
- 변경 케이스: 행사가 만료·가격 변경·수량 할인 조건 변경·쿠폰 만료·상품 가격 변경
- 로그인 후 장바구니 머지 직후에도 동일 검사 수행

## 7.5.1 영수증 조회·출력 정책 (Spec 단계 보완 — 기존 정책서 누락 항목)

> 전자상거래법상 결제 증빙 제공은 필수 의무이며, EARS 작성 과정에서 누락이 식별되어 역추가됨.

- 고객은 주문상세 화면에서 결제 영수증을 조회·출력할 수 있다.
- 영수증에는 상품명·결제수단·승인번호·결제금액·결제일시를 포함한다.
- 출력 형식은 PDF 또는 웹 프린트를 제공한다.
- 관련 기능요구사항: REQ-ORD-097

## 7.6 재고 관리 기준

재고의 소유와 관리 책임은 판매 주체에 귀속하며, 초기에는 입점사 직접 관리 방식으로 운영한다.

- 직매입 상품 재고는 플랫폼이 관리한다.
- 입점 상품 재고는 입점사가 직접 관리한다.
- 입점사 전용 BO를 통해 재고 수량을 등록·수정한다.
- 재고 정확성 유지 책임은 재고 관리 주체에게 있다.

## 7.7 품절 관리 기준

품절 책임은 재고 관리 주체가 부담하며, 플랫폼은 고객 보호 및 운영 품질 관리를 수행한다.

- 직매입 상품 품절은 플랫폼이 책임진다.
- 입점 상품 품절은 입점사가 책임진다.
- 재고 연동 오류는 원인 분석 후 책임 주체를 결정한다.
- 고객 피해 최소화를 위한 취소·환불·보상 정책을 운영한다.
- 반복적인 품절 발생 시 입점사 평가 및 운영 정책에 반영할 수 있다.
