## 9.0 직매입/입점형 프로모션 프로세스 분기
플랫폼은 직매입(DIRECT)과 입점형(VENDOR) 하이브리드 구조(§2.2)에 따라, 프로모션 등록·승인 프로세스를 공급 주체별로 구분한다.
### 프로세스 분기 기준
| 항목 | 직매입 (vendor.is_platform_direct = TRUE) | 입점형 (외부 벤더) |
|------|------------------------------------------|-------------------|
| 쿠폰 등록 | MD가 직접 등록 → **즉시 ACTIVE** (승인 게이트 생략) | 벤더 등록 → PENDING_APPROVAL → MD 승인 → ACTIVE |
| 행사가(즉시할인) 등록 | MD가 직접 등록·활성화 | MD가 직접 등록·활성화 (동일) |
| 수량구간 할인 등록 | MD가 직접 등록·활성화 | MD가 직접 등록·활성화 (동일) |
| 장바구니 할인 등록 | 플랫폼 운영자만 등록 | 플랫폼 운영자만 등록 (동일) |
| 상품 등록 | MD가 직접 등록 → **즉시 ON_SALE** (심사 생략) | 벤더 등록 → REVIEW_REQUESTED → MD 심사 → ON_SALE |
| 비용 부담 | 플랫폼 부담 | 입점사 부담 (공동 쿠폰은 계약 비율) |
### 직매입 프로모션 등록 규칙
- 직매입 상품(vendor_id = 1)에 대한 쿠폰·행사가는 MD가 어드민에서 직접 등록한다.
- 직매입 쿠폰은 PENDING_APPROVAL 단계를 거치지 않고 등록 즉시 ACTIVE로 전환된다.
- 직매입 상품 등록은 심사(REVIEW_REQUESTED→UNDER_REVIEW) 단계를 거치지 않고 즉시 ON_SALE로 전환된다.
- 시스템은 `vendor.is_platform_direct` 플래그를 기준으로 승인 게이트 적용 여부를 자동 판별한다.
### 입점형 프로모션 등록 규칙
- 입점사가 등록한 쿠폰은 반드시 MD 승인을 거쳐야 ACTIVE로 전환된다.
- 입점사가 등록한 상품은 반드시 MD 심사를 거쳐야 ON_SALE로 전환된다.
- 승인/심사 거부 시 반드시 사유를 기록한다.
## 9.1 쿠폰
- **발행 주체**: 플랫폼 발행 쿠폰(직매입 MD 직접 등록) / 입점사 발행 쿠폰(벤더 등록→MD 승인) 구분
- **적용 기준**: 상품 단위·카테고리 단위·주문 단위 적용 구분
- **중복 사용**: 플랫폼 쿠폰과 입점사 쿠폰은 중복 적용 가능하나, 동일 주체 쿠폰은 1장만 적용
- **비용 부담**: 플랫폼 쿠폰은 플랫폼 부담, 입점사 쿠폰은 입점사 부담, 공동 쿠폰은 계약 비율에 따라 분담
- **유효기간**: 발행일 기준 최대 90일, 이벤트성 쿠폰은 별도 기간 설정 가능
- **직매입 쿠폰**: MD가 어드민에서 직접 등록 시 승인 절차 없이 즉시 ACTIVE 전환
## 9.1-1 행사가 수량 관리
- 행사가 수량은 Redis에서 실시간 관리한다
- 주문 시 Redis DECR로 차감, 취소 시 INCR로 복구 (행사 기간 내)
- Redis 장애 시 DB 기준으로 fallback 처리
## 9.2 장바구니 할인
- 주문 금액 구간별 자동 할인 적용 (예: 5만원 이상 3,000원 할인)
- 특정 상품 조합 구매 시 추가 할인 적용 가능
- 장바구니 할인과 쿠폰 중복 적용 가능 여부는 프로모션 설정에서 개별 제어
## 9.3 회원등급 쿠폰
- **등급 체계**: New → Runner → Pacer → Elite (4단계)
- **쿠폰 지급 시점 1**: 등급 승급 시 즉시 지급 (승급 등급 기준 쿠폰 수)
- **쿠폰 지급 시점 2**: 매년 12월 31일 현재 등급 기준 일괄 지급
- **등급별 쿠폰 수량**: New 0장 / Runner 1장 / Pacer 2장 / Elite 3장
- **등급 산정 주기**: 월 1회 갱신, 하향 시 1개월 유예 기간 부여
