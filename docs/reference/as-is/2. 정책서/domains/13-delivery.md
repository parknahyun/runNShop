## 13.0-1 배송지 변경 정책

| 주문 상태 | 변경 가능 여부 | 처리 주체 |
|---------|-------------|---------|
| PAYMENT_COMPLETED (결제완료) | ✅ 가능 | 고객 직접 변경 |

| IN_DELIVERY 이후 | ❌ 불가 | 택배사 직접 문의 안내 |

## 13.1 출고 처리 기준

| 항목 | 기준 |
|------|------|
| 출고 의무 기한 | 결제완료 후 **1영업일 이내** |
| 출고 기한 초과 시 | 입점사 즉시 알림 + 운영팀 모니터링 |
| 출고 기한 초과 반복 시 | 입점사 등급 산정 클레임율에 반영 |
| 직매입 출고 기한 | 결제완료 후 1영업일 이내 (플랫폼 물류 기준) |

## 13.1-1 운송장 수정 정책

| 주문 상태 | 운송장 수정 가능 여부 |
|---------|-----------------|
| IN_DELIVERY 이전 | ✅ 가능 (입점사 BO에서 직접 수정) |
| IN_DELIVERY 이후 | ❌ 불가 (CS 협의 필요) |

## 13.2 배송사 정책

플랫폼이 제공하는 2개 배송사 중 1곳을 선택하여 운영한다.

| 항목 | 기준 |
|------|------|
| 플랫폼 제공 배송사 | 2개사 (API 연동 완료) |
| 입점사 선택 | 제공 배송사 2곳 중 1곳 선택 |
| 미선택 시 | 운송장 수동 등록 (API 자동화 미적용) |

### 배송사 선택에 따른 처리 방식

```
플랫폼 제공 배송사 선택
    → 운송장 등록 시 API 자동 연동
    → 배송 추적·완료 이벤트 자동 수신

미선택 (자체 배송사 사용)
    → 운송장 번호 수동 등록
    → 배송 추적 미제공
    → 배송완료 확인 수동 처리
```

### 배송사 미선택 시 제약 사항

| 항목 | 내용 |
|------|------|
| 배송 추적 | 미제공 (고객 직접 배송사 조회) |
| 배송완료 자동 처리 | 불가 (수동 확인 필요) |
| 구매확정 자동화 | 배송완료 기준 7일 카운트 수동 시작 |
| 분쟁 귀책 | 배송 증빙 확인 어려움으로 분쟁 귀책 입점사 귀속 |

> 플랫폼 제공 배송사 선택을 강력 권고한다.

## 13.3 배송사 API 연동

| 항목 | 기준 |
|------|------|
| 연동 방식 | 배송사 API 직접 연동 |
| 운송장 등록 | 입점사 BO 등록 시 배송사 API 자동 연동 |
| 배송 추적 | 배송사 API 실시간 조회 |
| 배송완료 확인 | 배송사 API 완료 이벤트 수신 시 자동 처리 |
| **배송상태 갱신 주기** | **60분 주기 배치 실행** (REQ-ORD-030) |
| API 장애 시 | 수동 운송장 등록 fallback 허용 + 운영팀 알림 |

## 13.4 배송 지연 처리 기준

| 상황 | 처리 기준 |
|------|----------|
| 출고 기한 초과 (미출고) | 입점사 즉시 알림 + 고객 지연 안내 |
| 배송 중 3일 이상 미진행 | 배송사 확인 후 고객 안내 |
| 배송 분실 의심 | 배송사 조사 요청 + 고객 안내. 분실 확정 시 재발송 또는 환불 |

## 13.5 도서산간 배송

- **도서산간 배송 미지원**
- 주문 시 배송 불가 지역 사전 안내
- 배송 불가 지역 주소 입력 시 주문 차단 처리

## 13.6 반송 처리 기준

| 상황 | 처리 기준 |
|------|----------|
| 수취인 부재 반송 | 고객 연락 후 재배송 또는 환불 선택 |
| 주소 오류 반송 | 고객 귀책. 재배송 배송비 고객 부담 |
| 장기 미수령 반송 | 14일 보관 후 반송. 환불 처리 |
