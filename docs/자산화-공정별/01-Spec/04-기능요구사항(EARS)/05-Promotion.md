> **Promotion 도메인 핵심 책임**: 쿠폰·행사가·수량할인·장바구니할인 등 혜택 정책을 정의하고 관리한다.
>
> **1차 본개발 관계**: Order·Payment가 1차 본개발 대상이며, Promotion은 PublicApi(할인계산·장바구니할인평가·쿠폰검증)를
> 정의하고 Mock 구현으로 제공한다.
>
> **할인 유형 체계 (확정)** — `프로모션-할인유형-적용순서.md` 참조:
> - 상품 행사가(즉시할인) ↔ 수량구간 할인: **택1** (중복등록 방지)
> - 상품 쿠폰: 행사와 **중복 적용 가능** (고객 선택)
> - 장바구니 할인: **플랫폼 단위** (벤더별 아님, 운영자만 등록)
> - 적용 순서: ①상품행사 → ②상품쿠폰 → ③장바구니가격할인 → ④장바구니쿠폰 → ⑤포인트 → ⑥배송비할인

## PublicApi — Order 연동 (Phase 0 최우선)

| ID | 패턴 | 채널 | 요구사항 | 출처 | 우선순위 |
|---|---|---|---|---|---|
| REQ-PRM-001 | Event-driven | C | WHEN Order 도메인이 상품별 할인 계산을 요청하면(productId, skuId, qty), THE 프로모션시스템 SHALL 해당 상품에 적용되는 행사가(즉시할인) 또는 수량구간 할인(택1)을 계산하여 할인 유형·할인금액·할인 후 단가를 반환한다 | Order REQ-ORD-059/064, 할인유형 적용순서 §3 | P1 |
| REQ-PRM-002 | Event-driven | C | WHEN Order 도메인이 장바구니 할인 조건 평가를 요청하면(주문 총액, 상품 목록), THE 프로모션시스템 SHALL 현재 활성 장바구니 할인 정책의 조건 충족 여부를 판단하고, 충족 시 할인금액·조건명을 반환한다 | Order REQ-ORD-103, 할인유형 적용순서 §4 | P1 |
| REQ-PRM-003 | Event-driven | C | WHEN Order 도메인이 쿠폰 유효성 검증을 요청하면(couponId, memberId, productIds, orderAmount), THE 프로모션시스템 SHALL 쿠폰의 사용 가능 여부(유효기간·사용횟수·최소주문금액·적용상품)를 검증하고 할인금액을 계산하여 반환한다 | Order 장바구니쿠폰 적용 API, 할인유형 적용순서 §4 | P1 |
| REQ-PRM-004 | Unwanted | C | IF 쿠폰 검증 시 유효기간 만료·사용횟수 초과·최소주문금액 미달·적용상품 불일치 중 하나라도 해당하면, THEN THE 프로모션시스템 SHALL 사용 불가 사유를 반환한다 | Order REQ-ORD-103 | P1 |
| REQ-PRM-005 | Event-driven | C | WHEN Order 도메인이 사용 가능 쿠폰 목록을 요청하면(memberId, productIds), THE 프로모션시스템 SHALL 해당 회원이 보유한 쿠폰 중 현재 주문 상품에 적용 가능한 쿠폰 목록(상품쿠폰+장바구니쿠폰)을 반환한다 | Order 주문서 생성 응답 | P1 |
| REQ-PRM-006 | Event-driven | C | WHEN Order 도메인이 수량구간 할인 조건 조회를 요청하면(productId), THE 프로모션시스템 SHALL 해당 상품의 수량구간 할인 조건(구간별 필요 수량·할인율)을 반환한다 | Order REQ-ORD-106 (넛지 안내) | P3 |
| REQ-PRM-007 | Ubiquitous | C | THE 프로모션시스템 SHALL 동일 상품에 행사가(즉시할인)와 수량구간 할인을 동시 등록할 수 없도록 한다(택1 중복등록 방지) | 할인유형 적용순서 §4 "중복 적용 규칙" | P1 |
