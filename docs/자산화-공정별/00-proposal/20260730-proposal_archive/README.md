# 00-proposal

방법론 가이드(`docs_method/AI활용_개발공정_가이드_v2.2_...md`) 6.1절 "Proposal 공정"을 runNshop
Initiative에 소급 적용하는 파일럿. 목적은 두 가지다.

1. **Gap 확인**: runNshop은 착수 시 Proposal 공정 없이 정책서부터 바로 시작했다. 방법론이 요구하는
   6종 Proposal 산출물(문제정의서·목표KPI·이해관계자맵·범위·대안비교·리스크가정) 중 착수 당시
   존재하는 건 하나도 없었다.
2. **방법론 검증**: 이미 확정된 산출물(정책서·decision_log·주간보고 등)을 자산으로 삼아 AI가 Proposal
   산출물 초안을 얼마나 완전하게 재구성할 수 있는지 검증한다.

> 상세 작업 이력(1~64차, 시점별 발견·의사결정의 전체 맥락)은 `CHANGELOG.md` 참고 — 이 파일은
> 현재 상태 요약만 유지한다(2026-07-30, 간략화).

## 폴더 번호가 "00"인 이유

`docs/`의 원본 폴더 번호(1.요구사항~8.운영매뉴얼)를 그대로 따르는 다른 산출물과 달리, Proposal은
방법론 v2.2에서 신설된 개념으로 요구사항(01)보다도 앞 단계이므로 `00`을 사용한다.

## 현재 상태 (2026-07-30 기준)

**6종 Proposal 산출물 전부 초안 완성** — `01-문제정의서.md`, `02-목표KPI.md`, `03-이해관계자맵.md`,
`04-범위(Scope).md`, `05-대안비교.md`, `06-리스크가정.md`. 페페의 최종 Review(Pass/Reject)가 아직
남아있다.

**목표 구조(O1/O2/O3)**: O1(플랫폼 구축·오픈)은 독립 목표가 아니라 **O2(방법론 검증)를 실증하기
위한 수단** — `02-목표KPI.md`에서 O2 하위 "완결 기준(舊 O1)"으로 중첩돼 있다. O2와 O3(자산화)가
실질적인 이원 목표이며, O3의 자산 인정 기준은 "① 방법론 준수(산출물 정의·선후행관계·표준양식) +
② 고품질(자기완결성)" 두 조건이다.

**스코프 확정 현황**:
- 전체구현(12개 도메인) Go 확정(2026-07-28)
- 진행 순서: **거래(1차, Order+Payment, 진행 중) → 상품(2차, Catalog+Promotion+Search) →
  고객(3차, Member+Community+Notification) → 파트너·운영(4차, Vendor+Settlement+Config+Audit)**
  확정(2026-07-30) — 구체적 착수 시점은 미정
- Security는 13번째 독립 도메인이 아니라 Config에 편입 확정(2026-07-30) — 도메인 수는 12개 유지
- Out-of-Scope 재분류(2026-07-30): 인프라 보안·운영·CS·마케팅 시스템 In-Scope 편입, **외부 PG
  실연동만 Out-of-Scope 유지**(리스크 수용 확정) — 신규 편입분의 진행순서·도메인 소속은 미정(HR#4·#5)

**Proposal→Spec 전이 조건(가이드 4.4절)**: "리스크 수용 여부 결정 완료"는 2026-07-30 Out-of-Scope
재분류(외부 PG만 Out-of-Scope 유지) + R1(신규인력 실측부재→공수산정 리스크) 수용으로 **충족됨**.
"Proposal 산출물 전체 Finalized 상태"만 남았다 — 6개 문서 전부 아직 DRAFT-v1, 페페의 Pass/Reject
Finalization Review가 마지막 조건이다.

**참고자료 `docs/자산화/참고자료/도메인기능표/`**: 12개 도메인, apps/ 실제 코드 + 정책서 대조로
지속 보완 중. Order·Catalog·Member·Payment는 일반 이커머스 체크리스트 전수 대조 완료, 나머지
도메인은 외부 확장 작업으로 390건 전체 난이도·공수(프로토타입 2,342h/293MD, 본개발 589~879MD)
산정까지 완료된 상태 — 세부 이력은 그 폴더의 `README.md`·`CHANGELOG.md` 참고.

**방법론 횡단 자산**: 산출물 표준양식 40종, 프롬프트 라이브러리 40종, "주문결제" Bolt 전공정
(Proposal~안정화) 실증 샘플이 `docs_method/`에 완성돼 있다. 가이드 부록C엔 "기획" 역할이
추가됐고, 신규 합류 인력(시니어 2·개발자 2, 8/1~9월중순)의 역할 배정(DE/QA/AM/Dev)도 확정됐다.
