# C8 UXWriting컨벤션
> 수립 데드라인: S3 화면레이아웃 전 | 참고 대상: 화면레이아웃, 알림
---

## 1. 목적
사용자에게 노출되는 모든 텍스트(UI 라벨, 메시지, 알림)의 작성 규칙을 통일하여 일관된 사용자 경험을 제공한다.

## 2. 규칙

### 2.1 문체 원칙

| 항목 | 규칙 |
|------|------|
| 존칭 | 해요체 (고객웹), 합니다체 (어드민/입점사) |
| 톤 | 친근하고 명확한 안내 |
| 길이 | 한 문장 30자 이내 권장 |
| 주어 | 시스템 주어 생략, 사용자 행위 중심 |

### 2.2 앱별 톤앤매너

| 앱 | 톤 | 예시 |
|----|-----|------|
| 고객웹 (mobile) | 친근·해요체 | "주문이 완료됐어요!" |
| 어드민 (admin) | 업무·합니다체 | "주문이 승인되었습니다." |
| 입점사 (partner) | 협력·합니다체 | "정산 내역이 확정되었습니다." |

### 2.3 성공/실패 메시지 패턴

#### 성공 메시지
```
{동작}되었습니다. / {동작}됐어요!
```

| 앱 | 예시 |
|----|------|
| mobile | "저장됐어요!" / "주문이 완료됐어요!" |
| admin | "저장되었습니다." / "상태가 변경되었습니다." |
| partner | "등록되었습니다." / "수정이 완료되었습니다." |

#### 에러 메시지
```
{원인}을(를) 확인해 주세요. / {동작}에 실패했습니다.
```

| 상황 | 메시지 |
|------|--------|
| 필수값 누락 | "{필드명}을(를) 입력해 주세요." |
| 형식 오류 | "올바른 {필드명} 형식으로 입력해 주세요." |
| 서버 오류 | "일시적인 오류가 발생했어요. 잠시 후 다시 시도해 주세요." |
| 권한 없음 | "접근 권한이 없습니다." |

### 2.4 버튼 라벨

| 동작 | 라벨 | 잘못된 예 |
|------|------|-----------|
| 생성 | 등록 / 추가 | 만들기, 새로 만들기 |
| 수정 | 수정 / 저장 | 변경하기, 업데이트 |
| 삭제 | 삭제 | 지우기, 제거하기 |
| 확인 | 확인 | OK, 네 |
| 취소 | 취소 | 뒤로, 아니요 |
| 검색 | 검색 / 조회 | 찾기, 서치 |

### 2.5 빈 상태 (Empty State)

| 상황 | 메시지 |
|------|--------|
| 주문 없음 | "아직 주문 내역이 없어요." |
| 검색 결과 없음 | "검색 결과가 없어요. 다른 키워드로 검색해 보세요." |
| 장바구니 비어있음 | "장바구니가 비어있어요." |
| 알림 없음 | "새로운 알림이 없어요." |

### 2.6 알림 메시지 (Notification)

| 유형 | 제목 패턴 | 본문 패턴 |
|------|-----------|-----------|
| 주문 접수 | "주문이 접수되었어요" | "{상품명} 외 {n}건이 접수되었습니다." |
| 배송 시작 | "배송이 시작됐어요" | "{상품명}이(가) 배송 중입니다." |
| 리뷰 요청 | "상품은 만족하셨나요?" | "리뷰를 작성하면 포인트를 드려요." |
| 정산 완료 | "정산이 완료되었습니다" | "{기간} 정산금 {금액}원이 입금됩니다." |

### 2.7 날짜·숫자 표기

| 항목 | 형식 | 예시 |
|------|------|------|
| 날짜 | YYYY.MM.DD | 2024.01.15 |
| 시간 | HH:mm | 14:30 |
| 날짜+시간 | YYYY.MM.DD HH:mm | 2024.01.15 14:30 |
| 금액 | 천 단위 콤마 + 원 | 35,000원 |
| 전화번호 | 하이픈 구분 | 010-1234-5678 |

### 2.8 미구현 화면 안내

PlaceholderPage에 표시할 기본 문구:
```
"아직 구현되지 않았습니다."
```

## 3. 예시

### Toast 메시지 사용
```tsx
// mobile (해요체)
showToast("장바구니에 담았어요!");
showToast("주문이 취소됐어요.");

// admin (합니다체)
showToast("저장되었습니다.");
showToast("상태가 변경되었습니다.");
```

### 유효성 검증 메시지
```tsx
// 필수값
"상품명을 입력해 주세요."
"수량을 입력해 주세요."

// 형식 검증
"올바른 이메일 형식으로 입력해 주세요."
"휴대폰 번호는 숫자만 입력해 주세요."

// 범위 검증
"수량은 1개 이상이어야 해요."
"할인율은 0~100 사이로 입력해 주세요."
```

## 근거
- 앱별 톤앤매너 통일로 브랜드 일관성 유지
- 메시지 패턴화로 개발 시 문구 고민 시간 절감
- 사용자 행위 중심 문구로 직관적 이해 도모
- 날짜·숫자 표기 통일로 데이터 표현 일관성 확보
