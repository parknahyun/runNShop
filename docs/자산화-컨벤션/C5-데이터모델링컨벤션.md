# C5 데이터모델링컨벤션
> 수립 데드라인: S2 ERD 전 | 참고 대상: ERD, 상태머신
---

## 1. 목적
ERD 설계 시 일관된 테이블 구조와 네이밍을 적용하여, 데이터 모델의 가독성과 유지보수성을 확보한다.

## 2. 규칙

### 2.1 테이블 네이밍

| 규칙 | 설명 | 예시 |
|------|------|------|
| 접두사 | 도메인 약어 (3자) + 언더스코어 | ord_, pay_, ctg_, mbr_ |
| 본명 | snake_case 복수형 | ord_orders, pay_payments |
| 매핑테이블 | 두 테이블 접두사 조합 | ord_ctg_order_items |

### 2.2 도메인별 접두사

| 도메인 | 접두사 |
|--------|--------|
| order | ord_ |
| catalog | ctg_ |
| member | mbr_ |
| payment | pay_ |
| promotion | prm_ |
| settlement | stl_ |
| vendor | vnd_ |
| notification | ntf_ |
| community | cmt_ |
| search | sch_ |
| config | cfg_ |
| audit | adt_ |

### 2.3 PK 컨벤션

| 항목 | 규칙 |
|------|------|
| 타입 | `varchar(26)` |
| 값 | ULID (시간순 정렬 가능) |
| 컬럼명 | `{entity}_id` (예: order_id, product_id) |

### 2.4 공통 컬럼

모든 테이블에 아래 컬럼을 포함한다:

| 컬럼 | 타입 | 설명 |
|------|------|------|
| {entity}_id | varchar(26) | PK, ULID |
| is_deleted | boolean | Soft Delete 플래그 (default: false) |
| created_at | timestamp | 생성 시각 |
| updated_at | timestamp | 수정 시각 |
| created_by | varchar(26) | 생성자 ID (nullable) |
| updated_by | varchar(26) | 수정자 ID (nullable) |

### 2.5 상태 컬럼

| 항목 | 규칙 |
|------|------|
| 타입 | `varchar(30)` |
| 값 | UPPER_SNAKE_CASE enum 문자열 |
| 컬럼명 | `status` 또는 `{구분}_status` |

### 2.6 Soft Delete

- 물리 삭제 대신 `is_deleted = true`로 논리 삭제
- 조회 쿼리에서 `WHERE is_deleted = false` 기본 적용
- 실제 물리 삭제는 배치로 30일 이후 처리 (향후)

### 2.7 금액 컬럼

| 항목 | 규칙 |
|------|------|
| 타입 | `decimal(15, 0)` (원 단위, 소수점 없음) |
| 컬럼명 | `{항목}_amount` 또는 `{항목}_price` |
| 음수 허용 | 환불 금액 등에 한해 허용 |

### 2.8 인덱스 네이밍

```
idx_{테이블약어}_{컬럼1}_{컬럼2}
uq_{테이블약어}_{컬럼}
```

## 3. 예시

### 주문 테이블 예시
```sql
CREATE TABLE ord_orders (
    order_id        varchar(26)     PRIMARY KEY,
    member_id       varchar(26)     NOT NULL,
    status          varchar(30)     NOT NULL DEFAULT 'PENDING',
    total_amount    decimal(15, 0)  NOT NULL,
    is_deleted      boolean         NOT NULL DEFAULT false,
    created_at      timestamp       NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at      timestamp       NOT NULL DEFAULT CURRENT_TIMESTAMP,
    created_by      varchar(26),
    updated_by      varchar(26)
);

CREATE INDEX idx_ord_orders_member_id ON ord_orders(member_id);
CREATE INDEX idx_ord_orders_status ON ord_orders(status);
```

### 상태값 정의 예시
```
ord_orders.status:
  PENDING → PAID → SHIPPING → DELIVERED
                              → CANCELLED
  DELIVERED → RETURN_REQUESTED → RETURN_COMPLETED
```

## 근거
- ULID를 PK로 사용하여 시간순 정렬과 분산 환경 ID 충돌 방지를 동시 달성
- 접두사로 테이블 소속 도메인을 즉시 식별 가능
- Soft Delete로 데이터 복구 가능성 확보 및 감사 추적 지원
- varchar 상태 컬럼으로 DB 비의존적 enum 관리 (코드 변경 시 마이그레이션 불필요)
