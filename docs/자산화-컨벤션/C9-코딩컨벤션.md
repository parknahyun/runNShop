# C2 코딩컨벤션
> 수립 데드라인: S3 클래스설계 전 | 참고 대상: 클래스설계, 코드구현
---

## 1. 목적
프로젝트 전체에서 일관된 코드 스타일과 구조를 유지하여 가독성, 유지보수성, 협업 효율을 극대화한다.

## 2. 규칙

### 2.1 네이밍 규칙

| 대상 | 규칙 | 예시 |
|------|------|------|
| 컴포넌트 파일 | PascalCase | ProductCard.tsx |
| 유틸·훅 파일 | camelCase | useProductList.ts |
| 상수 | UPPER_SNAKE_CASE | MAX_CART_ITEMS |
| Kotlin 패키지 | 소문자 | com.runnshop.order |
| Mock 파일 | {domain}__{METHOD}_{path}.json | catalog__GET_products_{product_id}.json |
| CSS 클래스 | BEM 스타일 | .dash-card__header, .nav-item__label--active |

### 2.2 Kotlin 패키지 구조

```
com.runnshop.{domain}/
├── controller/     ← REST Controller
├── service/        ← 비즈니스 로직
├── dto/            ← Request/Response DTO
└── mock/           ← MockLoader
```

### 2.5 데이터 로딩 규칙

- 모든 데이터는 Back-end API를 통해 가져온다 (하드코딩 금지)
- POST/PUT/DELETE 요청도 실제 API를 호출한다
- Front-end는 API 응답 결과를 받아 사용자에게 안내한다

```tsx
// ✓ 올바른 패턴
const { data } = await fetch('/api/v1/products');

// ✗ 잘못된 패턴
const products = [{ id: '1', name: '상품1' }]; // 하드코딩 금지
```

## 3. 예시

### 전체 컴포넌트 예시 (mobile)
```tsx
'use client';

import { useState, useEffect } from 'react';
import { useRouter } from 'next/navigation';
import { Header } from '@/components/layout/Header';
import { Skeleton } from '@/components/common/Skeleton';
import type { Order } from '@/types/order';

const PAGE_SIZE = 20;

export default function OrderListPage() {
  const router = useRouter();
  const [orders, setOrders] = useState<Order[]>([]);
  const [loading, setLoading] = useState(true);

  useEffect(() => {
    fetchOrders();
  }, []);

  const fetchOrders = async () => {
    try {
      const res = await fetch('/api/v1/members/me/orders');
      const json = await res.json();
      setOrders(json.data.items);
    } finally {
      setLoading(false);
    }
  };

  if (loading) return <Skeleton />;

  return (
    <div className="min-h-screen bg-gray-50">
      <Header title="주문 내역" />
      <main className="p-4 space-y-3">
        {orders.map((order) => (
          <div
            key={order.orderId}
            className="rounded-lg border bg-white p-4"
            onClick={() => router.push(`/orders/${order.orderId}`)}
          >
            <p className="font-medium">{order.productName}</p>
            <p className="text-sm text-gray-500">{order.orderDate}</p>
          </div>
        ))}
      </main>
    </div>
  );
}
```

### 전체 Controller 예시 (Kotlin)
```kotlin
package com.runnshop.order.controller

import com.runnshop.common.mock.MockLoader
import org.springframework.http.ResponseEntity
import org.springframework.web.bind.annotation.*

@RestController
@RequestMapping("/api/v1/members/me/orders")
class OrderController(
    private val mockLoader: MockLoader
) {
    @GetMapping
    fun getMyOrders(): ResponseEntity<String> {
        return mockLoader.load("v1", "order__GET_members_me_orders.json")
    }

    @GetMapping("/{orderId}")
    fun getOrderDetail(@PathVariable orderId: String): ResponseEntity<String> {
        return mockLoader.load("v1", "order__GET_members_me_orders_{orderId}.json")
    }
}
```

## 근거
- 네이밍 통일로 파일 검색·코드 네비게이션 효율 향상
- BEM 방식으로 CSS 스코프 충돌 방지 및 컴포넌트 독립성 확보
- API 호출 패턴 통일로 프로토타입 → 실 프로젝트 전환 시 Front-end 코드 변경 최소화
- Git 브랜치 규칙으로 PR 단위 코드리뷰 효율 향상
