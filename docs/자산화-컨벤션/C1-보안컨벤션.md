# C8 보안컨벤션
> 수립 데드라인: S0 착수 중 | 참고 대상: NFR
---

## 1. 목적
프로토타입 단계에서의 보안 범위를 명확히 정의하고, 실 프로젝트 전환 시 적용할 보안 아키텍처의 방향을 사전에 확립한다.

## 2. 규칙

### 2.1 프로토타입 단계 (현재 적용)

| 항목 | 처리 방식 |
|------|-----------|
| 로그인·2FA·본인인증·재인증 | 화면 UI 구현 + API 항상 성공 응답 |
| 세션 만료 | 미적용 (항상 로그인 유지) |
| 권한 체크 | 미적용 (메뉴 전체 노출) |
| 개인정보 마스킹 | Mock 데이터에 적용 |
| 인프라 보안 (HTTPS, Nginx, JWT 검증) | 미적용 |

### 2.2 PII 마스킹 규칙 (프로토타입 포함)

| 데이터 유형 | 마스킹 패턴 | 예시 |
|-------------|-------------|------|
| 이름 (3자) | 첫글자 + * + 끝글자 | 홍*동 |
| 이름 (2자) | 첫글자 + * | 김* |
| 휴대폰 | 010-****-끝4자리 | 010-****-5678 |
| 이메일 | 앞3자 + *** + @도메인 | hon***@gmail.com |
| 카드번호 | 앞4자리-****-****-끝4자리 | 1234-****-****-5678 |

### 2.3 실 프로젝트 방향 (향후 적용)

| 영역 | 방안 |
|------|------|
| 인증 | JWT (Access + Refresh Token) |
| 인가 | RBAC (Role-Based Access Control) |
| 데이터 암호화 | AES-256 (민감정보 필드 단위) |
| 카드 정보 | PCI DSS 준수 — 카드번호 미저장, pg_billing_key만 보관 |
| 통신 | HTTPS (TLS 1.3) |
| API 보안 | Rate Limiting, Input Validation, CORS 정책 |

### 2.4 보안 관련 API 응답

프로토타입에서 인증/인가 API는 항상 성공 응답을 반환한다.

```json
{
  "code": "SUCCESS",
  "data": {
    "accessToken": "mock-access-token",
    "refreshToken": "mock-refresh-token",
    "expiresIn": 3600
  }
}
```

## 3. 예시

### Mock 데이터 마스킹 적용
```json
{
  "code": "SUCCESS",
  "data": {
    "name": "홍*동",
    "phone": "010-****-5678",
    "email": "hon***@gmail.com"
  }
}
```

### 로그인 API (프로토타입)
- 어떤 아이디/비밀번호를 입력해도 성공 응답
- Front-end는 토큰을 localStorage에 저장하는 로직까지 구현
- 실제 JWT 검증은 수행하지 않음

## 근거
- 프로토타입 목적: 비즈니스 로직과 UX 검증에 집중
- 보안 레이어는 프로토타입 완료 후 실 프로젝트 전환 시 일괄 적용
- PII 마스킹은 프로토타입에서도 적용하여 개인정보 보호 습관화 및 실제 화면 표현 확인
