# C1 보안컨벤션

> **수립 데드라인**: S0 착수 중 | **참고 대상**: D8 NFR

---

## 1. 목적

보안 관련 규칙을 정의하여, 프로토타입부터 실 프로젝트까지 단계적으로 적용한다.
프로토타입에서는 **즉시 적용 규칙**만 준수하고, 실 프로젝트 전환 시 전체 규칙을 활성화한다.

---

## 2. 핵심 원칙

| 원칙 | 설명 | 프로토타입 적용 |
|---|---|---|
| Server Trust | 모든 검증·계산은 서버에서 수행 (클라이언트 신뢰 금지) | ✅ 즉시 |
| Least Privilege | Path Prefix로 접근 경계 분리 | ✅ 즉시 |
| Data Masking | PII는 항상 마스킹하여 노출 | ✅ 즉시 |
| No Secrets in Code | 시크릿 하드코딩 금지 | ✅ 즉시 |
| Defense in Depth | 다중 계층 방어 (Gateway→App→Data) | ⏳ 실 프로젝트 |
| Default Deny | 명시 허용 외 전체 거부 | ⏳ 실 프로젝트 |

---

## 3. 즉시 적용 규칙 (프로토타입 포함)

### 3.1 PII 마스킹

| 데이터 | 마스킹 규칙 | 예시 |
|---|---|---|
| 이름 | 가운데 글자 `*` | 홍*동 |
| 전화번호 | 중간 4자리 `****` | 010-\*\*\*\*-5678 |
| 이메일 | ID 3자 이후 `**` | h\*\*@example.com |
| 카드번호 | 뒤 4자리만 노출 | \*\*\*\*-1234 |

- Mock 데이터에도 반드시 마스킹 적용 (실 데이터 사용 금지)

### 3.2 서버 측 검증

| 규칙 | 적용 |
|---|---|
| 금액 검증 | 클라이언트 전달 금액 무시, 서버 재계산 |
| 입력 검증 | @Valid + DTO 제약 어노테이션 (@NotBlank, @Size, @Min) |
| 수량 범위 | 1~99 (음수·0·초과 서버 거부) |
| 열거형 | enum 매핑, 미정의 값 → 400 에러 |

### 3.3 접근 경계 분리

| 채널 | Path Prefix | 역할 |
|---|---|---|
| 고객웹 | `/api/v1/**` | CUSTOMER |
| 어드민 | `/api/admin/v1/**` | ADMIN |
| 입점사 | `/api/partner/v1/**` | VENDOR |

- 프로토타입: 실제 인증/인가 미적용 (메뉴 전체 노출), 하지만 Path 구조는 유지

### 3.4 시크릿 관리

| 규칙 | 적용 |
|---|---|
| 코드 내 API Key/Password 하드코딩 | 금지 |
| 환경변수 사용 | `application.yml`에 `${ENV_VAR}` 참조 |
| .env 파일 | `.gitignore`에 포함 |
| Mock 데이터 | 실제 키 대신 더미값 사용 |

### 3.5 에러 응답

| 규칙 | 적용 |
|---|---|
| 응답 구조 | `{ "code": "ERROR_CODE", "message": "사용자 메시지" }` |
| 스택트레이스 | 클라이언트에 절대 미노출 |
| 인증 실패 | 401 + "로그인이 필요합니다" (원인 상세 미노출) |
| 인가 실패 | 403 + "접근 권한이 없습니다" |
| 서버 에러 | 500 + "일시적인 오류가 발생했습니다" |

## 4. 실 프로젝트 전환 시 적용 규칙

> 프로토타입 → 실 프로젝트 전환 시 아래 규칙을 활성화한다.

### 4.1 인증 (Authentication)

| 항목 | 규칙 |
|---|---|
| 방식 | JWT (Access 30분 + Refresh 14일) |
| 저장 | HttpOnly Secure Cookie |
| 비밀번호 | bcrypt (cost 12+) |
| 소셜 | OAuth 2.0 (카카오, 네이버, 구글) |
| 어드민 | 2FA 필수 (TOTP) |

### 4.2 인가 (Authorization)

| 항목 | 규칙 |
|---|---|
| 모델 | RBAC (CUSTOMER / VENDOR / ADMIN / SUPER_ADMIN) |
| 리소스 소유권 | WHERE member_id = :currentUserId |
| 처리 계층 | Spring Security Filter → @PreAuthorize → Data 필터 |

### 4.3 데이터 보호

| 항목 | 규칙 |
|---|---|
| 전송 | TLS 1.3 (HTTPS) |
| 저장 | 민감 데이터 AES-256-GCM |
| 카드번호 | 미저장, PG 빌링키만 보관 (PCI DSS) |
| 보관 기한 | 전자상거래법 5년, 이후 배치 파기 |

### 4.4 API 보안

| 항목 | 규칙 |
|---|---|
| Rate Limiting | 인증 5회/분, 일반 100회/분/사용자 |
| 요청 크기 | Body 10MB, 파일 5MB/건 |
| CORS | 허용 Origin 명시 (와일드카드 금지) |
| 멱등성 | POST에 Idempotency-Key 권장 |

### 4.5 웹 보안

| 항목 | 규칙 |
|---|---|
| XSS | React 기본 이스케이프 + dangerouslySetInnerHTML 금지 |
| CSRF | SameSite=Strict + CSRF Token |
| Clickjacking | X-Frame-Options: DENY |
| CSP | Content-Security-Policy 설정 |

### 4.6 외부 연동 보안

| 연동처 | 규칙 |
|---|---|
| PG | Secret Key 환경변수, 원본 응답 PII 마스킹 후 로깅 |
| 택배사 | API Key 90일 로테이션 |
| OAuth | Redirect URI 화이트리스트 |
