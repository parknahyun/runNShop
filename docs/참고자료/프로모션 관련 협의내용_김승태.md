# 프로모션 ↔ Order 도메인 연동 협의 요청

> **작성일**: 2026-07-08
> **작성자**: 김승태 (Promotion 도메인)
> **협의 대상**: Order 도메인 담당자
> **상태**: 협의 대기

---

## 배경

Promotion 도메인 S2-구조설계 문서 작성 중, Order 도메인과의 연동 지점에서 누락·불일치 사항이 발견되어 협의가 필요합니다.

---

## 협의 항목

### 1. [심각] Order EARS에 Promotion PublicApi 호출 요구사항 부재

**현상**: Order EARS(08-EARS기능요구(Order).md) 전체에 "Promotion에 할인 계산/쿠폰 검증을 요청한다"는 요구사항이 하나도 없음.

**Promotion 측 정의**:
- REQ-PRM-001: 상품별 할인 계산 (행사가/수량구간 택1)
- REQ-PRM-002: 장바구니 할인 조건 평가
- REQ-PRM-003: 쿠폰 유효성 검증
- REQ-PRM-005: 사용 가능 쿠폰 목록 반환
- REQ-PRM-006: 수량구간 할인 조건 조회 (넛지 안내)

**요청**: Order EARS에 아래 요구사항 추가 여부 확인
- 주문서 생성 시 Promotion PublicApi로 상품 할인 계산 요청
- 주문서 생성 시 장바구니 할인 평가 요청
- 쿠폰 적용 시 유효성 검증 요청
- 사용 가능 쿠폰 목록 조회
- 장바구니에서 수량할인 넛지 안내 표시

---

### 2. [심각] Order 이벤트 플로우에 Promotion 수신자 누락

**현상**: `12-이벤트플로우.md` (Order↔Payment 통합)에서 아래 이벤트의 수신 도메인에 Promotion이 빠져 있음.

| 이벤트 | 현재 수신자 | Promotion 추가 필요 사유 |
|---|---|---|
| ORDER_CANCELLED | Payment, Catalog*, Member* | 사용된 쿠폰 복원 (USED→AVAILABLE) |
| CLAIM_COMPLETED | Payment, Catalog*, Member* | 부분 반품 시 쿠폰 복원 |
| ORDER_CONFIRMED | Settlement*, Member* | 쿠폰 사용 확정 (복원 불가 잠금) |

**요청**: 위 3개 이벤트의 수신 도메인에 `Promotion*` 추가 가능 여부 확인

---

### 3. [심각] 구매확정 시 쿠폰 사용 확정 (복원 불가 잠금)

**현상**: `prm_coupon_issue` 상태가 AVAILABLE/USED/EXPIRED 3개뿐이고, 구매확정 후 복원 불가를 강제하는 상태가 없음.

**제안 방안 (2가지 중 택1)**:

| 방안 | 설명 | 장점 | 단점 |
|---|---|---|---|
| A: CONFIRMED 상태 추가 | USED → CONFIRMED (구매확정 시) | 명시적, 상태만 보면 복원 가능 여부 판단 가능 | 상태 1개 추가, 조회 쿼리 변경 |
| B: 가드 조건 강화 | USED→AVAILABLE 전이 가드에 "구매확정 전 AND 유효기간 내" 조건 | 상태 추가 없음 | 복원 가능 여부를 Order 상태까지 조회해야 판단 |

**결정 필요**: 어떤 방안 채택? 또는 다른 방안?

---

### 4. [보완] 할인 적용 5단계 순서 시퀀스 부재

**현상**: 양쪽 비즈니스프로세스 문서에 할인 적용 순서(①상품행사→②상품쿠폰→③장바구니가격할인→④장바구니쿠폰→⑤포인트)가 시퀀스 다이어그램으로 도식화되지 않음.

**요청**: Order 비즈니스프로세스 또는 cross-domain 문서에 "주문서 할인 적용 서브프로세스"를 신설할 때, Promotion PublicApi 호출 순서를 어떻게 배치할지 협의

**참조**: `참고자료/프로모션-할인유형-적용순서.md` §3

---

### 5. [보완] Promotion EARS 도출근거의 Order REQ 번호 불일치

**현상**: Promotion EARS 도출근거에 기재된 Order REQ 번호가 실제와 불일치

| Promotion REQ | 참조된 Order REQ | 실제 Order REQ 내용 |
|---|---|---|
| REQ-PRM-001 | REQ-ORD-059/064 | 059=운송장 등록 시 shipment 전환, 064=수량 1~99 범위 검증 |
| REQ-PRM-002 | REQ-ORD-103 | **존재하지 않음** (Order EARS는 REQ-ORD-076까지) |
| REQ-PRM-006 | REQ-ORD-106 | **존재하지 않음** |

**원인 추정**: Promotion EARS가 Order EARS 확정 전(초기 Draft) 기준으로 작성됨. Order EARS가 Finalized(2026-08-21)인 반면 Promotion EARS는 Draft(2026-07-08).

**요청**: Order에 대응 REQ가 신설되면 번호 공유 요청

---

### 6. [보완] 수량할인 넛지 안내 소비 측 미정의

**현상**: REQ-PRM-006이 수량구간 할인 조건 조회 API를 제공하지만, Order 장바구니에서 이를 호출해 고객에게 넛지(예: "2개 더 담으면 10% 할인!")를 보여주는 요구사항이 Order 측에 없음.

**요청**: 장바구니 화면에서 수량할인 넛지를 표시할 계획인지, 표시한다면 호출 시점(장바구니 진입 시? 수량 변경 시?) 확인

---

### 7. [정책 결정] 부분 반품 시 쿠폰 복원 범위

**질문**: CLAIM_COMPLETED(부분 반품) 이벤트 수신 시, 어떤 쿠폰을 복원할지 정책 결정 필요

| 케이스 | 복원 여부 | 사유 |
|---|---|---|
| 상품쿠폰 (반품 상품에 적용된 쿠폰) | 복원? | 해당 상품 반품이므로 쿠폰도 복원이 자연스러움 |
| 장바구니쿠폰 (주문 전체에 적용) | 복원? | 주문 총액 기준이라 부분 반품 시 조건 재계산 필요 |
| 포인트 | 복원? | Member 도메인 소관이나 연동 규칙 필요 |

---

### 8. [정책 결정] 쿠폰 사용 확정 시점

**질문**: COUPON_USED 이벤트 발행 시점이 불명확

| 시점 후보 | 장점 | 단점 |
|---|---|---|
| 결제 요청 시 (PAYMENT 생성) | 빠른 잠금, 중복 사용 방지 | 결제 실패 시 롤백 필요 |
| 결제 완료 후 (PAYMENT_COMPLETED) | 확실한 결제 확인 후 처리 | 결제 중 동시 쿠폰 사용 가능성 |
| 구매확정 시 (ORDER_CONFIRMED) | 가장 안전 | 배송 중 쿠폰 재사용 가능 문제 |

**현재 Promotion 문서 기준**: "주문 결제 완료 시" (PAYMENT_COMPLETED 후)로 가정하고 작성됨
