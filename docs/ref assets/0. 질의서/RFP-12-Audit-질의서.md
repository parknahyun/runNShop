# 질의서 — Audit (감사, 발주사 대상)

> **목적**: 감사 도메인의 업무 범위·정책을 발주사로부터 확인한다.
> **사용 시점**: 착수(Kick-off) 미팅 또는 도메인정의서(DB) 작성 전
> **반영 대상**: `DB-도메인정의서`(Audit 책임 정의), `D7-제약사항`(법적 보존 요건)

| # | 질문 | 답변 | 비고 |
|---|---|---|---|
| 1 | 관리자 행위 로그(누가·언제·무엇을 변경)를 어느 수준까지 기록해야 하는가? | 전 도메인의 주요 이벤트를 기록한다. 주문 생성·상태변경·취소·반품·교환, 결제 요청·승인·실패·환불·보상, 재고 등록·수정·선점·복구·품절전환, 가격(정가·판매가·공급가) 변경, 상품 상태 전이 등을 변경 전/후 값·처리 주체(시스템/고객/입점사/운영자)·처리 시각과 함께 기록하며, TraceID(TRC-{YYYYMMDD}-{일련번호})로 전 구간을 추적할 수 있다. 로그는 수정·삭제가 불가한 Append-only 방식이다. | 요구사항 FR-AUD-001, 정책서 17.3~17.4 |
| 2 | 감사 로그 보관 기간에 대한 법적·내부 정책 요건이 있는가? | 있다. ERROR·WARN·INFO 로그와 Trace 전체는 1년, DEBUG 로그는 30일(운영 환경 미수집, 스테이징에서만) 보관하며 보존 기간 초과 시 자동 삭제한다. 별도로 주문·거래 이력은 전자상거래법 기준 5년 보존 의무가 적용된다. | 요구사항 NFR-006, 정책서 17.5 |
| 3 | 개인정보 접근 로그(누가 언제 어떤 개인정보를 조회했는지)를 별도로 기록해야 하는가? | 필요하며 이미 정의되어 있다. AOP 기반으로 자동 기록(adt_member_access_log)되고, 회원·주문·클레임 조회 및 조치 행위가 기록 대상이며, 회원 목록 조회 시에는 필수 검색어 1개 이상 입력 후에만 조회가 가능하도록 통제된다. 개인정보보호법 제29조(안전조치 의무)와 연계된다. | 요구사항 FR-AUD-002, FR-COM-006 |
| 4 | 내부 통제(예: 정산 승인 시 이중 확인) 요구사항이 있는가? | 정산 확정은 정산담당자의 단일 검토·승인 프로세스로 정의되어 있으며, 이중 확인(승인자 분리·복수 결재) 절차는 문서에 명시되어 있지 않다. | 요구사항 FR-STL-003 참고 — 이중 확인 요건은 '-' |
| 5 | 감사 로그를 조회·다운로드할 수 있는 대상(외부 감사기관 포함)이 있는가? | 운영 어드민에서 TraceID 기반으로 전체 흐름을 조회할 수 있는 기능은 정의되어 있으나, 조회 대상자는 내부 운영자(슈퍼관리자 등)로 한정되어 보이며 외부 감사기관에 대한 별도 조회·다운로드 권한 부여 규정은 문서에 명시되어 있지 않다. | 정책서 17.2·17.7 — 외부 감사기관 제공 여부는 '-' |
