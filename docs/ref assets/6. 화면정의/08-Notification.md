## 참고: 실제 발송 흐름은 이 화면 밖에서 발생

이 화면은 템플릿(문구) 관리만 다루며, **실제 발송 트리거·발송 이력**은 다른 도메인 산출물에 있다:

| 항목 | 위치 |
|---|---|
| 발송 이벤트(예: `ORDER_CONFIRMED_KAKAO`가 언제 발생하는지) | `DI-이벤트플로우.md`(자산화 산출물), Notification 도메인의 이벤트 구독 로직 |
| 발송 성공/실패 로그 | 원본 `DB-도메인정의서.md` Notification 책임(발송 이력)에 해당하나, admin 화면 목록(`runNshop_screen_definition_v1_1.md`)에는 "발송 이력 조회" 화면 자체가 없음(Human Review) |
| 고객이 알림을 받을지 여부 | `03-Member.md` CUS-066(알림 설정) — 수신자가 유형별로 ON/OFF |

> **Human Review**: 원본 화면정의서 전체(§2~§4)를 통틀어 "알림 발송 이력"을 조회하는 admin 화면이 없다. 발송 실패 시 재시도 여부·실패 사유 확인이 운영상 필요할 텐데, 이 기능이 어디에도 할당되어 있지 않다 — `12-Audit.md`(감사 로그)가 이 역할을 겸하는지, 별도 화면이 빠진 것인지 확인이 필요하다.
