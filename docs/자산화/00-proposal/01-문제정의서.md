## Background

3TOP 2본부는 2026-06-21부터 러닝 전문 B2C 이커머스 플랫폼 "runNshop"을 신규 구축 중이다. 고객웹·어드민·입점사 BO 3개 채널, 러닝 전문 카테고리 특화(러닝화·의류·기어, 웨어러블 데이터 연동), 복수 입점사+직매입 오픈마켓형 구조로 설계되었다.

초기에는 워터폴식 9대 공정으로 진행했으나 AI 협업이 체계적으로 진행되지 않는 문제가 드러나, Bolt 단위 반복 구조의 "AI활용 방법론"(v2.2)을 수립하고 runNshop에 재적용해 검증·보완한다. 이 과정에서 자산 범위가 "설계+프로토타입"에서 **전체 12개 도메인 구현**으로 확장됐다 — 단일 도메인으로는 방법론의 범용성도, 자산 라이브러리의 폭도 부족하기 때문이다.

## Problem

> 핵심: 커머스 구축 경험이 체계적으로 자산화되지 않아, AI 협업 시 산정 근거 자체가 없다.

1. **자산화 부재** — 3TOP은 다수의 커머스 구축 프로젝트를 수행하며 노하우를 축적해왔으나, 체계적으로 관리·적용하지 못해왔다. 짧은 개발 기간과 빠른 기술 변화 속에서 비체계적인 자산으로는 대응이 어렵다.

2. **AI 협업 산정 불확실성** — AI와 협업하면 개발기간·인력·비용 산정이 어렵다. 체계화된 자산이 없으니 "AI 협업이 기존 방식 대비 얼마나 절감되는가"를 판단할 근거 자체가 없다.

3. **개발 패러다임 정합** — 위 두 문제는 기존 방법론의 구조적 한계(요구사항 변경 시 유지비용 증가, 핵심 인력 의존도, AI Agent 협업 구조 부재)와 맞물려 있다. 대응 방향은 AI를 활용해 프로젝트를 진행하는 방법론을 수립하는 것이다.

## Impact

> 방치했을 때의 예상 영향

1. **산정 실패** — 전통 방식 baseline은 총 사업비 약 16억원·기간 6개월·인력 단가 월 1,000만원이다. 이 baseline과 비교할 "AI 협업 방식의 산정 근거"가 없어 투자 승인·인력 계획·ROI 판단이 불확실하다.

2. **향후 프로젝트 자산 부족** — runNshop에서 AI와 만든 산출물이 자산화되지 않으면, 이후 다른 프로젝트(예: 뷰티샵)를 진행할 때 매번 처음부터 쌓아야 한다.

3. **보완작업 반복** — 표준양식 없이 만든 자산은 결함으로 이어진다(실증: Task Spec v1.0에서 Section 5건·Template 4건 결함 발견). 검증 안 된 나머지 약 39종 산출물에서도 같은 반복이 예상된다.

## Opportunity

> 대응했을 때의 기대효과

1. **비용 절감 + 산정 모델 확보** — baseline 대비 기간 5개월·비용 30% 절감(약 11.2억원) 목표. 인력 단가 인하가 아니라 기간과 투입 인월(MM)을 줄이는 구조다. 재사용 가능한 산정 모델 자체를 자산으로 확보한다.

2. **방법론 자산화** — runNshop에서 검증된 산출물·프롬프트·하네스를 다른 프로젝트에 재사용한다.

3. **자산 보완 효과 실증** — Task Spec v1.1 보완 후 재검증에서 결함 0건 달성. 자기완결성 검증을 자산 등록 관문으로 삼는 원칙이 이미 효과를 증명했다.

4. **재사용 범위 극대화** — 3TOP은 커머스 개발업체이므로, B2C 시장 대표성 덕분에 이번 자산(정책서 패턴·화면정의서·Task Spec 등)이 향후 다른 client 프로젝트에 폭넓게 재사용 가능하다.
