## 코드 기반 보완 (2026-07-28, apps/ 실제 소스 조사)

- **Outbox/DLQ가 조회만이 아니라 재시도·무시 액션까지 실제 구현**돼 있음을 확인(admin
  `system/outbox-dlq`) — 도메인정의서엔 "관리"로만 있었는데 실제로는 상태 조회 + 2개의 개별
  액션으로 나뉜다. 화면은 Outbox·DLQ 2개 탭뿐이라 "재시도"·"무시 처리" 두 소분류는 별도 화면이
  아니라 DLQ 탭 안의 행별 버튼(재시도/무시확정)이며, 무시확정은 사유 메모 입력 모달을 거친다.
- **PII 접근 이력이 시스템 감사로그와 별도 화면**(`settings/access-log`)으로 분리돼 있음 —
  일반 감사로그(생성/수정/삭제)와는 다른 개인정보 컴플라이언스 목적. 이 항목을 03-Member와
  12-Audit 중 어디를 1차 소속으로 할지는 아직 미정(Human Review). 이 화면의 "엑셀 다운로드"
  버튼은 `alert('준비 중')` 스텁으로 실제 API를 호출하지 않아 버튼 카운트에서 제외했다.
- **Trace관리·모니터링·알림 2개 소분류는 전용 화면이 코드상 확인되지 않음** — TraceID는
  감사로그 상세·Outbox 테이블의 필드로만 존재하고, ERROR 임계치 알림을 위한 화면/배치/트리거
  코드도 admin 소스에서 발견되지 않아 N/A 처리했다(백엔드 전용이거나 미구현일 가능성, Human
  Review 필요).
- **감사기록(컨슈머·배치) 2개 소분류는 화면 없는 백엔드 전용 처리** — 각 도메인의 변경 이벤트를
  수신하여 자동으로 감사 로그를 기록하는 컨슈머와, 보관 기간 경과 로그를 아카이빙하는 배치는
  UI가 없으므로 N/A 처리했다.

## 코드 기반 보완 (2026-07-29, 회원/운영자/입점사 일반 기능표 대조 검토)

- **신규 공백이 거의 없음을 확인** — 대조 검토한 9개 후보(로그인이력·메뉴접근이력·데이터변경
  이력·API호출이력·이벤트로그·시스템모니터링/알림·회원보안·권한변경이력·회원활동이력) 중
  7건이 이미 다른 도메인표에 반영돼 있거나 Audit 기존 행으로 충분히 커버됨을 확인했다: 로그인
  이력(고객·전체조회는 `03-Member.md`, 운영자 자기 자신은 `11-Config.md` 화면·API 접근 이력
  조회), 메뉴 접근 이력(`11-Config.md` 동일 화면), 데이터 변경 이력(이 문서 "시스템 감사 로그
  조회"의 `actorType`이 MEMBER/OPERATOR/VENDOR를 이미 구분), API 호출 이력(운영자는
  `11-Config.md` "프로그램 호출 로그 조회"), 회원 보안(`03-Member.md`+`07-Vendor.md`), 회원
  활동 이력 통합조회(`01-Order.md`+`09-Community.md` — `03-Member.md`가 이미 "주문/클레임
  이력은 Order 소유"라 배제한 선례와 동일 패턴).
- **"Outbox·DLQ 조회" 서술 보정**: 코드(`OutboxDlqPage.tsx`)를 재확인한 결과 PENDING/
  PROCESSING/PROCESSED/FAILED 4개 상태를 모두 조회 대상으로 삼고 있어, 기존 비고의 "실패 이벤트"
  중심 서술이 실제 코드 범위(정상 처리 건 포함)보다 축소돼 있었다 — 위 표에서 정정.
- **시스템 모니터링/운영 알림은 성격이 다른 두 기능(상태 대시보드 조회 vs 알림 트리거)이지만,
  둘 다 코드·정책 근거가 전무한 채로 이미 "모니터링·알림" 1개 N/A 행에 등재돼 있어 분리 실익이
  낮다고 판단** — 현행 유지.
- **BC 대상(Vendor 소관, Audit 아님)**: 입점사 로그인 이력 조회·입점사 API 연동 이력 조회 2건은
  코드·문서 어디에도 없는 진짜 공백이었으나, admin 쪽 대칭 기능이 이미 `11-Config.md`(운영자
  자기 로그인·API호출 이력)에 있다는 점에서 Audit이 아니라 Vendor 소관으로 판단해
  `07-Vendor.md`에 반영했다(2026-07-29).
- **권한 변경 이력**은 근거가 약해 신규 공백으로 단정하지 않았다 — `11-Config.md` "권한(Role)
  관리"에 이력 추적 탭을 신설하는 편이 Audit 신규 행보다 적합하다고 판단, Human Review로 남김.
