# C4 데이터모델링컨벤션

> **수립 데드라인**: S2 ERD 작성 전 | **참고 대상**: DF ERD, DH 상태머신

---

## 1. 목적

데이터 모델링 규칙을 사전에 정의하여, 도메인별 ERD 작성 시 일관된 구조·네이밍·제약조건을 적용한다.

---

## 2. 모델링 원칙

| 원칙 | 설명 |
|------|------|
| 정규화 우선 | 기본적으로 제3정규형을 준수한다 |
| 반정규화 허용 조건 | 조회 성능 또는 이력 관리 등 명확한 목적 + 정합성 유지 방안이 있는 경우 |
| 도메인 소유권 | 각 도메인은 자기 테이블만 직접 접근. 타 도메인 데이터는 API/Event |
| 스냅샷 원칙 | 주문·결제 시점 데이터(상품명, 단가)는 스냅샷으로 저장 (원본 변경 영향 차단) |

---

## 3. 테이블 네이밍

| 규칙 | 예시 |
|------|------|
| `{domain_prefix}_{entity}` | `ord_order`, `pay_payment` |
| 소문자 snake_case | `ord_order_item` (camelCase 금지) |
| 복수형 금지 | `ord_order` (✗ `ord_orders`) |
| 중간 테이블 | `{prefix}_{entity1}_{entity2}` | `prm_coupon_product` |

### 도메인별 접두사

| Domain | 접두사 | 예시 |
|--------|--------|------|
| order | `ord_` | ord_order, ord_cart, ord_claim |
| catalog | `cat_` | cat_product, cat_category |
| member | `mbr_` | mbr_member, mbr_address |
| payment | `pay_` | pay_payment, pay_payment_method |
| promotion | `prm_` | prm_coupon, prm_exhibition |
| settlement | `stl_` | stl_settlement |
| vendor | `vnd_` | vnd_vendor, vnd_contract |
| notification | `ntf_` | ntf_template |
| community | `cmt_` | cmt_review, cmt_qna |
| search | `sch_` | sch_keyword |
| config | `cfg_` | cfg_code, cfg_setting |
| audit | `adt_` | adt_log |

## 4. 컬럼 네이밍

| 의미 | 규칙 | 예시 |
|------|------|------|
| PK | `id` | `id` (테이블 내 유일) |
| FK | 참조 대상 테이블의 PK 의미 반영 | `member_id`, `order_id`, `vendor_id` |
| 명칭 | `{대상}_name` | `product_name`, `recipient_name` |
| 코드 | `{대상}_code` | `category_code` |
| 수량 | `{대상}_quantity` 또는 `quantity` | `quantity`, `claim_quantity` |
| 금액 | `{대상}_amount` 또는 `{의미}_fee` | `total_amount`, `shipping_fee` |
| 일시 | `{행위}_at` | `created_at`, `shipped_at`, `confirmed_at` |
| 날짜 | `{의미}_date` | `restricted_date` |
| 여부 | `is_{상태}` | `is_deleted`, `is_default` |
| 상태 | `status` 또는 `{대상}_status` | `status`, `payment_status` |
| 횟수 | `{대상}_count` | `retry_count`, `fail_count` |
| 비율 | `{대상}_rate` | `commission_rate` |
| URL | `{대상}_url` | `image_url` |
| 순서 | `sort_order` | `sort_order` |

## 5. PK / FK / Key

### 5.1 PK

| 항목 | 규칙 |
|------|------|
| 컬럼명 | `id` |
| 타입 | `varchar(26)` |
| 생성 방식 | ULID (시간순 정렬 가능, 분산 환경 충돌 없음) |
| Auto Increment | 사용 금지 (분산 환경 대비) |

### 5.2 FK

| 항목 | 규칙 |
|------|------|
| 컬럼명 | 참조 대상의 의미를 반영한 `{entity}_id` |
| 타입 | 참조 대상 PK와 동일 (`varchar(26)`) |
| 물리 FK 제약 | **사용하지 않음** (애플리케이션 레벨에서 무결성 관리) |
| 이유 | 도메인 간 물리 FK는 결합도 증가 → 서비스 분리 시 장애물 |
| 인덱스 | FK 컬럼에는 반드시 인덱스 생성 |

### 5.3 UNIQUE

| 항목 | 규칙 |
|------|------|
| 네이밍 | `uq_{테이블약어}_{컬럼1}_{컬럼2}` |
| 적용 대상 | 업무적으로 중복이 허용되지 않는 값 |
| 예시 | `uq_cart_member_sku` (동일 회원+SKU 중복 방지) |

---

## 6. 데이터 타입

| 데이터 | 표준 타입 | 비고 |
|--------|-----------|------|
| PK/FK | `varchar(26)` | ULID |
| 짧은 문자열 | `varchar(n)` | n은 업무 최대 길이 기준 설정 |
| 긴 문자열 | `text` | 사유, 상세 설명, Raw 응답 등 |
| 코드/열거값 | `varchar(30)` | 상태, 유형 등 enum 문자열 |
| 정수 | `int` | 수량, 횟수 |
| 금액 | `int` | 원(KRW) 단위 정수 (소수점 없음) |
| 비율 | `decimal(5,2)` | 수수료율 등 (99.99%까지) |
| 날짜 | `date` | restricted_date 등 |
| 일시 | `timestamp` | UTC 기준 저장, 표시 시 KST 변환 |
| 여부 | `boolean` | NOT NULL + DEFAULT 필수 |
| JSON | `jsonb` (PostgreSQL) / `json` (MySQL) | 비정형 확장 데이터 (최소 사용) |

## 7. 공통 컬럼

### 일반 업무 Entity (기본 적용)

| 컬럼 | 타입 | 설명 |
|------|------|------|
| `id` | varchar(26) | PK, ULID |
| `created_at` | timestamp | 생성 일시 (NOT NULL) |
| `updated_at` | timestamp | 수정 일시 (NOT NULL) |
| `is_deleted` | boolean | Soft Delete (DEFAULT false) |

### 예외 (선택 적용)

| Entity 유형 | 적용 공통 컬럼 | 제외 |
|-------------|----------------|------|
| 이력/로그 (ord_order_history, adt_log) | `id`, `created_at` | `updated_at`, `is_deleted` (수정/삭제 불가) |
| 매핑 테이블 (prm_coupon_product) | `id`, `created_at` | `updated_at` (변경 없이 삭제 후 재생성) |
| 스냅샷 (ord_order_item) | `id`, `created_at` | `is_deleted` (주문 시점 고정, 삭제 불가) |

---

## 8. NULL / Default 규칙

| 규칙 | 적용 |
|------|------|
| 업무상 필수값 | NOT NULL |
| 선택값 (입력하지 않을 수 있는 값) | NULL 허용 |
| 상태값 | NOT NULL (초기 상태 반드시 존재) |
| 여부(Boolean) | NOT NULL + DEFAULT 지정 |
| 금액 | NOT NULL + DEFAULT 0 |
| 일시 (created_at) | NOT NULL |
| 일시 (선택적: confirmed_at, shipped_at) | NULL 허용 (해당 이벤트 미발생 시) |
| "미정" 상태를 NULL로 표현 | 금지 — 별도 상태값 사용 |

---

## 9. 상태값

| 규칙 | 설명 |
|------|------|
| 타입 | `varchar(30)` (enum 문자열) |
| 네이밍 | UPPER_SNAKE_CASE |
| 허용값 정의 | 상태머신(DH) 문서가 Single Source of Truth |
| DB 제약 | CHECK constraint 또는 애플리케이션 레벨 검증 |
| 이력 관리 | 상태 변경이 중요한 Entity는 별도 History 테이블 (ord_order_history) |
| 한/영 매핑 | C2 용어컨벤션 참조 |

---

## 10. 금액 / 수량

| 항목 | 규칙 |
|------|------|
| 금액 단위 | 원(KRW) 정수 (소수점 없음) |
| 금액 타입 | `int` (최대 ~21억원 — 충분) |
| 할인 금액 | 양수 저장, 표시 시 `-` 접두사 |
| 수량 | `int`, NOT NULL, @Min(1) @Max(99) |
| 안분 금액 | `actual_paid_amount` — 할인 안분 후 실결제 금액 |

## 11. 제약조건

| 제약 | 규칙 | 네이밍 |
|------|------|--------|
| PK | 모든 Entity 필수 | (DBMS 자동) |
| UNIQUE | 업무적 중복 불허 값 | `uq_{테이블약어}_{컬럼}` |
| NOT NULL | 필수 속성 | — |
| CHECK | DB에서 검증 가능한 값 범위 | `ck_{테이블약어}_{컬럼}` |
| FK (물리) | 사용하지 않음 | — |

---

## 12. Soft Delete / Lifecycle

| 정책 | 적용 대상 | 규칙 |
|------|-----------|------|
| Soft Delete | 사용자 관점 삭제 복구 필요 Entity | `is_deleted = true`, 30일 보관 후 배치 물리 삭제 |
| 영구 보관 | 법적 보관 의무 데이터 | `is_deleted = true`, 영구 보관 (전자상거래법 5년) |
| 물리 삭제 없음 | 이력/로그/감사 | 삭제 자체 불가 |
| Soft Delete 미적용 | 이력, 스냅샷, 매핑 테이블 | `is_deleted` 컬럼 없음 |

> Soft Delete는 **삭제 복구 또는 논리적 삭제가 필요한 Entity에만** 적용한다. 모든 테이블에 강제하지 않는다.

## 13. Index

### 네이밍

| 유형 | 규칙 | 예시 |
|------|------|------|
| 일반 인덱스 | `idx_{테이블약어}_{컬럼1}_{컬럼2}` | `idx_order_status_date` |
| UNIQUE 인덱스 | `uq_{테이블약어}_{컬럼}` | `uq_cart_member_sku` |

### 생성 기준

| 조건 | 생성 여부 |
|------|-----------|
| PK | 자동 (필수) |
| UNIQUE 제약 | Unique Index 사용 |
| FK 컬럼 | **반드시 생성** (JOIN 성능) |
| WHERE 조건에 자주 사용 | 검토 후 생성 (조회 패턴 기반) |
| 상태 + 일시 복합 | 목록 조회용 복합 인덱스 권장 (`status, created_at`) |
| ORDER BY 대상 | 조회 패턴에 따라 생성 |
| 단일 컬럼 과도 생성 | 금지 (쓰기 성능 저하) |
| 중복 인덱스 | 금지 |

## 14. 관계

| 관계 | 모델링 규칙 |
|------|-------------|
| 1:1 | 부모 테이블에 FK 컬럼 또는 동일 PK 공유 |
| 1:N | 자식 테이블에 부모 FK 컬럼 |
| N:M | 중간 매핑 테이블 사용 (`{prefix}_{entity1}_{entity2}`) |
| 도메인 간 | 물리 FK 없음, 논리적 참조만 (varchar FK 컬럼 + 인덱스) |

## 15. ERD 표기 규칙

| 항목 | 규칙 |
|------|------|
| 도구 | PlantUML (entity 다이어그램) |
| PK 표시 | `* id : varchar <<PK, ULID>>` |
| FK 표시 | `* {참조}_id : varchar <<FK>>` |
| 관계 표시 | `||--o{` (1:N), `||--o|` (1:1) |
| 필수/선택 | `*` = NOT NULL, (없음) = NULL 허용 |
| 동일 Domain | 같은 다이어그램에 배치 |
| 타 Domain 참조 | `<<FK {Domain}>>` note로 표시 |
| 불변식 | 다이어그램 하단에 별도 테이블로 기술 |

## 16. 예시

```sql
-- ord_order (주문)
CREATE TABLE ord_order (
    id              VARCHAR(26)   NOT NULL,  -- PK, ULID
    platform_order_id VARCHAR(26) NOT NULL,  -- FK (논리적)
    vendor_id       VARCHAR(26)   NOT NULL,  -- FK Vendor 도메인
    status          VARCHAR(30)   NOT NULL,  -- enum: 상태머신(DH) 참조
    total_amount    INT           NOT NULL DEFAULT 0,
    shipping_fee    INT           NOT NULL DEFAULT 0,
    cancel_reason   VARCHAR(200),            -- NULL 허용 (취소 시에만)
    confirmed_at    TIMESTAMP,               -- NULL 허용 (확정 전)
    created_at      TIMESTAMP     NOT NULL,
    updated_at      TIMESTAMP     NOT NULL,
    is_deleted      BOOLEAN       NOT NULL DEFAULT FALSE,
    
    CONSTRAINT pk_order PRIMARY KEY (id)
);

CREATE INDEX idx_order_platform ON ord_order (platform_order_id);
CREATE INDEX idx_order_vendor ON ord_order (vendor_id);
CREATE INDEX idx_order_status_date ON ord_order (status, created_at);
```

## 근거

| 항목 | 출처 |
|------|------|
| 테이블 접두사 | 도메인정의서(DB) 12개 도메인 |
| ULID | 분산 환경 대비 + 시간순 정렬 |
| 물리 FK 미사용 | C3 아키텍처 — 도메인 간 의존 최소화 |
| Soft Delete 정책 | DF ERD — 테이블별 차등 적용 |
| 금액 int | KRW 정수 단위 (소수점 불필요) |
| 상태 varchar | DH 상태머신 — UPPER_SNAKE_CASE enum |
| 스냅샷 원칙 | REQ-ORD-009 (주문 시점 상품정보 고정) |
| 인덱스 패턴 | DF ERD — 실제 정의된 인덱스 패턴 추출 |
