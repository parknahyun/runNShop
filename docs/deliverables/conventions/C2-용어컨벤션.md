# C2 용어컨벤션

> **수립 데드라인**: S1 시작 전 | **참고 대상**: 도메인정의서, EARS

---

## 1. 목적

프로젝트 내 업무 용어를 통일하여 커뮤니케이션 혼란을 방지하고,
코드·문서·UI 간 용어의 일관성을 확보한다.

---

## 2. 규칙

|---|---|---|

| settlement | 정산 | 매출 정산·수수료 계산·지급 |

### 2.2 용어 사용 원칙

| # | 원칙 | 예시 |
|---|---|---|
| 1 | **코드**: 영문 Domain 명칭 사용 | `com.runnshop.order`, `OrderService` |
| 2 | **UI**: 표준 한글 명칭 사용 | "주문 현황", "결제 완료" |
| 3 | **문서**: 최초 한글(영문) 병기 후 한글 사용 | "주문(Order) 도메인은..." 이후 "주문" |
| 4 | Domain 명칭 임의 축약 금지 | ✗ `ord`, `pmt` → ✓ `order`, `payment` |
| 5 | 동의어 혼용 금지 | "입점사" = 유일 명칭 (셀러/판매자/파트너 금지) |

### 2.3 상태값 명명 규칙

> 상세 전이 규칙은 상태머신(DH) 문서를 Single Source of Truth로 참조한다.
> 아래는 주요 상태의 한/영 매핑 목록이다.

> **v6 동기화 (2026-08-24)**: 배송 실행(택배사가 실제로 물건을 이동시키는 구간)을 `ord_shipment`(신규, order/claim 공용)로 분리 — order 11→10상태, claim 14→11상태. 아래 두 상태 목록은 "고객·입점사·CS가 판단·결정하는 지점"만 표현하며, 배송 실행 상세는 `ord_shipment.status`(본 절 하단) 참조.

#### ord_order.status (10상태)

| 상태값 (코드) | UI 표시 | 설명 |
|---|---|---|
| TEMP | 임시주문 | 주문서 진입 시 데이터 생성 |
| ORDER_RECEIVED | 주문접수 | 재고차감 요청 중 |
| PAYMENT_PENDING | 결제대기 | 재고선점 완료, PG 승인 대기 |
| PAYMENT_COMPLETED | 결제완료 | PG 승인 성공 |
| PREPARING | 출고준비~배송중 | 입점사 확인 (배송실행 상세는 ord_shipment 참조) |
| DELIVERED | 배송완료 | shipment(OUTBOUND) DELIVERED (파생) |
| CONFIRMED | 구매확정 | 고객 수동 or D+7 자동 |
| CANCELLED | 주문취소 | 고객 취소 or CS 예외 취소 |
| PAYMENT_FAILED | 결제실패 | PG 실패/타임아웃 |
| STOCK_FAILED | 재고부족 | 재고 선점 실패 |

> "배송중" 표시는 `PREPARING` + `shipment(OUTBOUND).status=IN_TRANSIT` 조인으로 화면에서 계산한다 (IN_DELIVERY 상태값 폐지).

#### ord_claim.status (11상태)

| 상태값 (코드) | UI 표시 | 설명 |
|---|---|---|
| RECEIVED | 접수됨 | 고객 반품/교환 신청 |
| PAYMENT_PENDING | 배송비결제대기 | 고객 귀책 확정 |
| PAYMENT_EXPIRED | 결제만료 | 24시간 초과 자동 취소 |
| INSPECTING | 품질점검중 | 입점사 귀책 즉시 또는 수거 shipment 입고 확인 |
| PICKED_UP | 수거완료 | 품질점검 합격 |
| PICKUP_REJECTED | 수거거부 | 품질점검 불합격 |
| REFUNDED | 환불완료 | 어드민 환불 처리 |
| RETURN_PAYMENT_PENDING | 반송배송비결제대기 | 어드민 반송결제 요청 |
| DISPOSED | 폐기 | 어드민 폐기 결정 |
| COMPLETED | 클레임완료 | 환불완료 or 반송배송완료(shipment) or 폐기 후 자동 |
| REJECTED | 반려 | CS 즉시 반려 |

> PICKUP·RETURN_SHIPPING·RETURN_DELIVERED는 `ord_shipment.status`(PICKUP/RETURN 타입)로 이관되었다.

#### ord_shipment.status (5상태, 신규 — order/claim 공용)

| 상태값 (코드) | UI 표시 | 설명 |
|---|---|---|
| PENDING | 운송장 미등록 | shipment 레코드 생성 |
| IN_TRANSIT | 배송중 | 운송장 등록, 이동 중 |
| DELIVERED | 배송완료 | 택배사 배송완료 확인 (배치) |
| FAILED | 배송실패/반송 | 택배사 배송실패 신호 (배치) |
| CANCELLED | 배송취소 | 상위 주문/클레임 취소로 배송 취소 |

> `shipment_type`: OUTBOUND(주문출고)/PICKUP(클레임수거)/RETURN(클레임반송)/EXCHANGE_OUT(교환선출고).

#### pay_payment.status (5상태)

| 상태값 (코드) | UI 표시 | 설명 |
|---|---|---|
| PENDING | 결제대기 | PG 승인 요청 중 |
| PAID | 결제완료 | PG 승인 성공 |
| CANCELLED | 결제취소 | 전액 취소 |
| REFUNDED | 환불완료 | 전액 환불 |
| PARTIAL_REFUNDED | 부분환불 | 부분 클레임 환불 |

#### catalog 상태

| 상태값 (코드) | UI 표시 | 설명 |
|---|---|---|
| DRAFT | 임시저장 | 미등록 |
| ON_SALE | 판매중 | 정상 판매 |
| SOLD_OUT | 품절 | 재고 0 |
| HIDDEN | 숨김 | 비노출 |

#### vendor 상태

| 상태값 (코드) | UI 표시 | 설명 |
|---|---|---|
| APPLIED | 입점신청 | 신규 신청 |
| APPROVED | 승인완료 | 입점 확정 |
| REJECTED | 반려 | 입점 거절 |

### 2.4 복합 용어

| 표준 용어 | 정의 | 금지/비권장 용어 |
|---|---|---|
| 주문번호 | 고객에게 노출되는 주문 식별자 | 오더번호, 거래번호 |
| 상품번호 | 개별 상품 식별자 | 품번, 아이템번호 |
| 입점사 | 플랫폼에 입점한 판매자 | 셀러, 판매자, 파트너 |
| 정산금 | 입점사에 지급할 금액 | 수익금, 판매대금 |
| 클레임 | 반품·교환 통합 명칭 | 클레임건, 반품건, AS건 |
| 반품 | 상품 반환 후 환불 | 반송, 회수반품 |
| 교환 | 상품 교체 (맞교환) | 교체, 상품변경 |
| 귀책 | 클레임 책임 소재 | 과실, 잘못, 원인 |
| 수거 | 고객 → 입점사 상품 회수 | 반송, 픽업, 회수 |
| 반송 | 입점사 → 고객 상품 돌려보냄 (품질점검 거부 시) | 역배송, 재발송 |
| 품질점검 | 수거 후 상품 상태 확인 | QC, 검수, 검품 |
| 택유지 | 교환 시 상품 태그 유지 여부 확인 | 태그확인, 라벨검사 |
| 배송비 결제 | 클레임 시 고객이 추가 부담하는 비용 | 추가비용, 왕복배송비 |
| 알림톡 | 카카오 비즈 알림 (템플릿 메시지) | SMS, 문자, 카톡 |
| 구매확정 | 배송완료 후 고객 최종 확인 (D+7 자동) | 수취확인, 인수확인 |
| 바로구매 | 장바구니 미경유 즉시 주문 | 즉시구매, 원클릭 |

```kotlin
    CANCELLED, PAYMENT_FAILED, STOCK_FAILED
}

// ✗ 금지

enum class Status { ... }       // 도메인 접두사 누락
```

### 3.2 API

```
✓ POST /api/v1/orders/{orderId}/claims       ← "claims" 사용
✗ POST /api/v1/orders/{orderId}/returns      ← "returns" 금지 (클레임이 표준)

✓ GET /api/admin/v1/claims/{claimId}/refund  ← "refund" 사용
✗ GET /api/admin/v1/claims/{claimId}/payback ← "payback" 금지

✓ Mock 파일: order__POST_orders_{orderId}_claims.json
✗ Mock 파일: ord__POST_orders_{orderId}_returns.json  ← 축약+비표준 용어
```

## 4. 변경 관리

| 규칙 | 설명 |
|---|---|
| 신규 도메인 추가 | 용어컨벤션에 즉시 등록 (Domain 테이블 + 상태값 + 복합 용어) |
| 기존 용어 변경 | 영향 범위(코드·API·문서·UI) 전수 검토 후 일괄 변경 |
| 상태값 추가/변경 | 상태머신(DH) 변경 → 용어컨벤션(C2) 동기 갱신 |
| 금지 용어 위반 | 코드리뷰에서 지적 → 표준 용어로 교체 |
