## 1. 정책 개요

### 1.1 목적

프로모션의 생성·운영·적용에 필요한 공통 정책을 정의하여, 프로모션 혜택이 일관된 기준에 따라
제공되고 프로모션 간 적용 규칙이 명확하게 관리되도록 한다.

- 프로모션 유형 및 적용 대상에 대한 기준 정의
- 할인 및 혜택 제공 조건 정의
- 회원 대상 및 운영 방식 정의
- 복수 프로모션 적용 시 처리 기준 정의
- 프로모션 운영 과정에서 발생하는 예외 및 제한 기준 정의

### 1.2 적용 범위

본 정책은 커머스 서비스에서 상품 및 주문에 적용되는 프로모션의 혜택 정의부터 적용 및 운영까지를
대상으로 한다.

**포함 범위**

- 가격할인, 포인트 적립, 사은품 지급 (쿠폰은 혜택유형이 아니라 혜택운영의 적용방식으로 포함,
  배송비 할인은 대상구분의 값으로 포함)
- 프로모션 대상 및 조건
- 회원 제한
- 프로모션 발급·지급·적용 방식
- 프로모션 중복 및 우선순위
- 프로모션 제한 및 예외

**제외 범위**

- 프로모션 화면의 UI/UX 상세 설계
- 프로모션 시스템의 API 및 데이터 구조
- 프로모션 구현 방식 및 기술 아키텍처
- 일회성 운영 업무 중 시스템 정책으로 관리하지 않는 사항

> 제외 범위는 이 문서(DBA)의 몫이 아니라 후속 산출물의 몫이다 — UI/UX는 DN 화면레이아웃,
> API·데이터 구조는 DL 인터페이스명세·DF ERD, 구현 방식은 코드 구현 단계에서 다룬다.

## 2. 프로모션 구성요소

> Promotion을 하나의 객체로 보고 속성/정책 조합으로 분해하는 방식이다. 최초 D6A 기반 8축
> 체계에서 쿠폰(혜택유형→혜택운영으로 재배치)·배송혜택(혜택유형→대상구분 "배송비"로 흡수)·
> 제한수량(신설 독립 축) 재검토를 거쳐 7축으로 재편했다(2026-09-28, 근거는 §6 참조).

| 요소 | 목적 | 근거 |
|---|---|---|
| ① 혜택유형 | 어떤 것을 주는가 | D6A Q1 (재검토) |
| ② 대상구분 | 무엇에 주는가 | D6A Q2 |
| ③ 혜택조건 | 어떤 조건인가 | D6A Q3 (재검토) |
| ④ 혜택방법 | 얼마나 주는가 | D6A Q4 (재검토) |
| ⑤ 혜택운영 | 누구에게, 어떻게 전달하는가 | D6A Q5·Q6 통합 (재검토) |
| ⑥ 제한수량 | 몇 건까지 허용하는가 | 2026-09-28 대화 (신설) |
| ⑦ 혜택정책 | 다른 혜택과 어떻게 관계하는가 | D6A Q7 (재검토) |

프로모션 형태(기획전·시즌행사 등, 구 ⑧)는 정책 축이 아니라 위 7축의 조합을 캠페인 단위로
묶는 컨테이너 개념이라 §2.8에서 별도로 다룬다.

이 구조는 "프로모션 관리" Feature가 등록 → 대상설정 → 혜택설정 → 조건설정 → 할인차수/중복정책 →
기간설정 → 승인 → 적용 → 실적/정산으로 이어지는 업무 프로세스(DG에서 상세화)의 기초가 된다.

### 2.1 혜택유형

> **재검토 배경**: 최초 D6A Q1 회신은 가격할인·쿠폰·적립·사은품·배송혜택 5종을 나열했으나,
> 이는 "무엇을 주는가"(혜택 내용)와 "어떻게 갖는가"(전달 방식)를 같은 축에 섞은 것이었다.
> 실제 화면설계(`DN-화면레이아웃/mobile.md`)에 "배송비쿠폰"이 이미 존재해 쿠폰↔배송혜택이
> 서로 배타적이지 않다는 모순이 드러났다. 쿠폰은 §2.5 혜택운영의 적용방식 값으로, 배송혜택은
> §2.2 대상구분의 "배송비" 값으로 재배치하여 혜택유형을 3종으로 정리했다.

| 유형 | 설명 |
|---|---|
| 가격할인 | 상품·주문·배송비 금액에서 직접 금액을 차감 |
| 포인트 적립 | 구매 또는 조건 충족 시 포인트 지급 |
| 사은품 지급 | 조건 충족 시 상품·경품 제공 (계량값 없이 지급여부만 관리) |

### 2.2 대상구분

| 구분 | 지정 단위 |
|---|---|
| 상품 | 카테고리, 브랜드 (개별 상품 지정은 예외적) |
| 주문 | 장바구니 전체 금액 기준 |
| 배송비 | 벤더(입점사) 단위 배송비. 가격할인 전용 대상 — 포인트 적립·사은품 지급은 배송비를 대상으로 가질 수 없음 |

**혜택유형 × 대상구분 매트릭스** (2026-09-28 확정)

| | 상품 | 주문 | 배송비 |
|---|---|---|---|
| 가격할인 | O (상품↔주문 중복/누적 허용) | O (상품↔주문 중복/누적 허용) | O (가격할인 전용 대상) |
| 포인트 적립 | O (상품↔주문 중복/누적 허용) | O (상품↔주문 중복/누적 허용) | X |
| 사은품 지급 | O (상품↔주문 중복/누적 허용) | O (상품↔주문 중복/누적 허용) | X |

> 상품 단위와 주문 단위는 모든 혜택유형에서 동시 적용(누적) 가능하다 — 상품에 걸린 혜택을
> 먼저 적용한 결과를 기준으로 주문 단위 혜택을 이어서 적용하는 구조이며(§2.7 할인차수 참조),
> "택1"이 아니라 "순차 누적"이다. 배송비는 벤더당 단일 값(order.md §4.2 입점사 단위 그룹화)이라
> 애초에 상품처럼 여러 개별 항목이 존재하지 않으므로 중복 개념 자체가 적용되지 않는다.

### 2.3 혜택조건

> **용어 변경**: 구 "할인조건" → "혜택조건"으로 변경 — 가격할인뿐 아니라 포인트 적립·사은품
> 지급에도 공통으로 적용되는 조건이라는 점을 반영했다.

| 조건 | 설명 | 성격 |
|---|---|---|
| 기간(시간) | 프로모션 유효 기간·시간대 | 필수, 전체 공통 |
| 금액 | 최소 주문/구매 금액 | 필수(기본), 전체 공통 |
| 수량 | 최소~최대 구매 수량 구간 (min=max 고정값 포함, 예: 1+1 행사는 min=2·max=2) | 옵션 — **가격할인×상품·주문 전용**. 가격할인×배송비, 포인트 적립, 사은품 지급은 수량 조건 미사용 |
| 결제수단 | 특정 결제수단(카드사 등) 한정 | 옵션 — 전체 대상 가능하나 PG 실연동 Out-of-Scope로 조건 정의만 하고 실제 검증 생략(D6A Q9) |

**대상구분·혜택유형별 혜택조건 매트릭스**

### 2.4 혜택방법

> **용어 변경**: 구 "할인방법" → "혜택방법"으로 변경 — 가격할인 전용 계산방식이 아니라
> 3개 혜택유형 전체를 포괄하는 축으로 재정의했다. "수량연동"은 별도 방법이 아니라 정률·정액에
> §2.3 수량 조건이 결합된 형태로 흡수했다(방법과 조건을 분리).

| 혜택유형 | 방법 | 비고 |
|---|---|---|
| 가격할인 (상품·주문) | 정률, 정액 | 수량 조건과 결합 시 구간별 정률·정액 적용 가능 |
| 가격할인 (배송비) | 정률만 | 배송비 할인은 항상 비율로만 표현(무료배송=100%), 고정금액 차감 미지원 |
| 포인트 적립 | 정률, 정액 | 실제 계산 근거는 Member 도메인 회원등급 적립률(AS-IS §4.3)과 혼재 — Promotion이 별도 발행하는 적립 프로모션의 방법 상세는 **[Human Review]** |
| 사은품 지급 | N/A | 계량값(정률/정액/균일가) 없음 — 지급여부만 관리 |

가격할인의 균일가(정상가 무관 고정 판매가)는 상품 단위에서만 유효하며, 대상구분 매트릭스와
결합해 적용 범위가 결정된다.

### 2.5 혜택운영 (가격할인 전용)

> **재구성 배경**: 구 "회원대상"(⑤)·"운영"(⑥)이 개별 축으로 분리돼 있었으나, 쿠폰이라는
> 하나의 개념을 다루는 하위요소들이라 "혜택운영"으로 통합했다. 포인트 적립·사은품 지급은
> 항상 자동적용이고 발급형(쿠폰) 개념이 없어 이 축 자체가 N/A다.

| 하위요소 | 값 | 설명 |
|---|---|---|
| 적용방식 | 자동 / 쿠폰 | 자동은 조건 충족 시 시스템이 즉시 반영, 쿠폰은 발급·보유 후 고객이 선택 사용 |
| 운영 (적용방식=쿠폰일 때) | 자동발급·지급 / 수동지급(관리자발급, 다운로드, 코드입력) | 쿠폰의 구체적 전달수단 |
| 회원제한 (적용방식=쿠폰일 때) | 전체 / 회원등급 / 특정회원 | D6A Q5 원안(성별·연령대·회원상태·구매이력 포함 6종)에서 이번 정책서 범위로 3종 축소 |

> 등록 주체(직매입/입점형)에 따른 승인 게이트 분기는 AS-IS 정책서 §9.0 기준을 따른다 —
> 직매입은 MD 등록 즉시 ACTIVE, 입점형은 벤더 등록 → MD 승인 → ACTIVE.

### 2.6 제한수량 (신설, 전체 혜택유형 공통)

> **신설 배경**: 쿠폰의 발급수량 제한(구 §2.6 "제한조건")을 검토하는 과정에서, 자동적용
> 혜택(행사가 선착순형)에도 이미 동일한 성격의 수량 제한이 존재함이 확인되어(ERD
> `prm_discount_event.limit_type=QUANTITY`), 혜택운영 하위가 아닌 독립 축으로 분리했다.

| 하위요소 | 값 |
|---|---|
| 전체발급 한도 | 0 = 무제한 / N(양수) = 제한 인원 |
| 1인당 발급횟수 | 1회 고정 |

적용방식(자동/쿠폰)·혜택유형과 무관하게 모든 혜택에 공통 적용된다.

### 2.7 혜택정책 (가격할인 중심)

> **용어 변경**: 구 "적용정책" → "혜택정책"으로 변경.
