## 1. 정책 개요

### 1.1 목적

프로모션의 생성·운영·적용에 필요한 공통 정책을 정의하여, 프로모션 혜택이 일관된 기준에 따라
제공되고 프로모션 간 적용 규칙이 명확하게 관리되도록 한다.

- 프로모션 유형 및 적용 대상에 대한 기준 정의
- 할인 및 혜택 제공 조건 정의
- 회원 대상 및 운영 방식 정의
- 복수 프로모션 적용 시 처리 기준 정의
- 프로모션 운영 과정에서 발생하는 예외 및 제한 기준 정의

### 1.2 적용 범위

본 정책은 커머스 서비스에서 상품 및 주문에 적용되는 프로모션의 혜택 정의부터 적용 및 운영까지를
대상으로 한다.

**포함 범위**

- 가격할인, 쿠폰, 적립, 사은품, 배송혜택
- 프로모션 대상 및 조건
- 회원 대상
- 프로모션 발급·지급·적용 방식
- 프로모션 중복 및 우선순위
- 프로모션 제한 및 예외

**제외 범위**

- 프로모션 화면의 UI/UX 상세 설계
- 프로모션 시스템의 API 및 데이터 구조
- 프로모션 구현 방식 및 기술 아키텍처
- 일회성 운영 업무 중 시스템 정책으로 관리하지 않는 사항

> 제외 범위는 이 문서(DBA)의 몫이 아니라 후속 산출물의 몫이다 — UI/UX는 DN 화면레이아웃,
> API·데이터 구조는 DL 인터페이스명세·DF ERD, 구현 방식은 코드 구현 단계에서 다룬다.

### 1.3 용어 정의

| 용어 | 정의 |
|---|---|
| 프로모션 | 고객에게 가격 할인 또는 부가 혜택을 제공하기 위한 정책 단위 |
| 혜택유형 | 프로모션을 통해 제공되는 혜택의 종류 |
| 가격할인 | 상품 또는 주문 금액에서 직접 금액을 차감하는 혜택 |
| 쿠폰 | 특정 조건의 회원에게 발급되어 주문 시 사용할 수 있는 할인 수단 |
| 적립 | 구매 또는 특정 조건 충족 시 포인트 등을 지급하는 혜택 |
| 사은품 | 특정 조건 충족 시 상품 또는 경품 등을 제공하는 혜택 |
| 배송혜택 | 배송비 할인 또는 무료배송 등의 혜택 |
| 적용 대상 | 프로모션 혜택이 적용되는 상품·주문·배송비 등의 대상 |
| 할인 조건 | 프로모션 적용 여부를 판단하는 기간·금액·수량 등의 조건 |
| 회원 대상 | 프로모션 또는 쿠폰의 적용·발급 대상이 되는 회원 조건 |
| 적용 정책 | 여러 프로모션이 동시에 적용될 때의 순서·중복·우선순위 등의 규칙 |
| 프로모션 형태 | 기획전·시즌행사·타임세일 등 프로모션을 운영하는 형태 |

> 위 용어는 아래 "프로모션 구성요소"(①~⑧ 축)의 명칭과 1:1 대응한다 — 혜택유형=①, 적용
> 대상=②, 할인 조건=③, (할인 방법은 용어집에 없어 ④로만 존재), 회원 대상=⑤, 적용 정책=⑦,
> 프로모션 형태=⑧. C2 용어 컨벤션(있는 경우) 수립 시 이 표를 원본으로 참조한다.

### 1.4 기본 원칙

프로모션은 다음의 원칙에 따라 정의하고 운영한다.

| # | 원칙 | 설명 |
|---|---|---|
| ① | 명확성 | 프로모션의 혜택, 대상, 조건 및 적용 방법을 명확하게 정의한다 |
| ② | 조건 분리 | 혜택유형, 적용 대상, 할인 조건, 할인 방법, 회원 대상 및 운영 조건을 독립적인 정책 요소로 관리한다 |
| ③ | 일관성 | 동일한 유형의 프로모션은 동일한 기준과 적용 규칙을 따른다 |
| ④ | 우선순위 명확화 | 복수의 프로모션이 동시에 적용될 수 있는 경우 할인 차수, 중복 여부 및 우선순위를 명확하게 정의한다 |
| ⑤ | 자동 적용 원칙 | 자동 적용 대상 프로모션은 고객의 별도 행위 없이 조건 충족 여부에 따라 적용한다. 단, 쿠폰 등 고객의 참여가 필요한 혜택은 별도의 발급·다운로드·입력 절차를 적용할 수 있다 |
| ⑥ | 예외 최소화 | 일반 정책으로 처리할 수 있는 경우에는 공통 정책을 적용하고, 불가피한 경우에만 예외 조건을 정의한다 |

> 원칙 ②(조건 분리)가 아래 "프로모션 구성요소"를 8개 독립 축으로 나눈 근거이고, 원칙
> ④(우선순위 명확화)가 ⑦ 적용정책 축의 근거다.

## 2. 프로모션 구성요소

> Promotion을 하나의 객체로 보고 속성/정책 조합으로 분해하는 방식이다.

| 요소 | 목적 | 근거(D6A) |
|---|---|---|
| ① 혜택유형 | 어떤 것을 주는가 | Q1 |
| ② 대상구분 | 무엇에 주는가 | Q2 |
| ③ 할인조건 | 어떤 조건인가 | Q3 |
| ④ 할인방법 | 얼마나 주는가 | Q4 |
| ⑤ 회원대상 | 누구에게 주는가 | Q5 |
| ⑥ 운영 | 어떻게 실행하는가 | Q6 |
| ⑦ 적용정책 | 다른 혜택과 어떻게 관계하는가 | Q7 |
| ⑧ 프로모션 형태 | 어떤 행사로 운영하는가 | Q8 |

이 구조는 "프로모션 관리" Feature가 등록 → 대상설정 → 혜택설정 → 조건설정 → 할인차수/중복정책 →
기간설정 → 승인 → 적용 → 실적/정산으로 이어지는 업무 프로세스(DG에서 상세화)의 기초가 된다.

### 2.1 혜택유형

|---|---|---|

## 3. 후속 산출물 연계

| 후속 산출물 | 이 문서를 어떻게 쓰는가 |
|---|---|
| DC 상위 유스케이스 | 액터(관리자/고객/시스템연동)가 각 축의 값(혜택유형·대상구분 등)을 "설정·관리"하는 행위 단위로 전환 |
| DD EARS | 각 축의 조합 규칙을 "IF~THEN" 요구사항 문장으로 정형화 (예: 할인방법=균일가/수량연동은 혜택유형=가격할인에만 허용) |
| DF ERD | 8축을 Promotion·Coupon·DiscountPolicy 등 엔티티의 속성·enum 컬럼으로 확정 |
| DG 비즈니스 프로세스 | 등록→대상설정→혜택설정→조건설정→할인차수/중복정책→기간설정→승인→적용→실적/정산 흐름으로 상세화 |

## 5. 자가평가

- **완전성**: 충족 — 정책 개요(목적·범위·용어·기본원칙) + D6A Q1~Q8 회신 전체가 8축에 1:1 매핑, 누락 없음
- **일관성**: 충족 — 1.3 용어 정의가 2. 구성요소(①~⑧ 축) 명칭과 1:1 대응, AS-IS 정책서 §9.0(승인 분기)과 상충 없음, D4-범위 Out-of-Scope(PG·이관)와 정합
- **추적성**: 충족 — 각 축·항목에 D6A 질의 번호 명시
- **실행가능성**: 충족 — DC~DG 각 산출물이 이 문서의 어느 부분을 근거로 쓸지 "후속 산출물 연계" 표로 명시
- **정책 준수**: 충족 — work-scope 룰(Promotion 한정) 준수, 1.2 제외 범위로 이 문서의 경계를 명확히 함(UI/UX·API·구현방식은 후속 산출물 몫)
