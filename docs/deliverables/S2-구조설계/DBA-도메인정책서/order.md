> "주문결제·연동" 섹션은 Order 관점(결제를 요청하고 결과를 받는 지점)까지만 다룬다.

>
> **프로모션 연계 표기 원칙**: 프로모션 중복정책·우선순위·최대할인 등의 원본은
> `DBA-도메인정책서/promotion.md`(2.7 적용정책)이다. 여기서는 Order 관점에서 "언제 그 정책을

> **포인트 소유 도메인**: 현재 DB-도메인정의서에 포인트 소유 도메인이 명시돼 있지 않다(Member

## 1. 정책 개요

### 1.1 목적

Order 도메인(장바구니~주문~배송~클레임)의 생성·변경·상태전이·예외처리에 필요한 공통 정책을
정의하여, 주문 처리가 일관된 기준에 따라 수행되고 도메인 간 연동 규칙이 명확하게 관리되도록
한다.

- 장바구니 담기·변경·주문 전환 조건 정의
- 주문 생성·변경·확정·취소 조건 정의
- 배송 유형·배송비·출고 처리 기준 정의
- 클레임(반품/교환/환불) 신청·처리·비용 기준 정의
- 각 하위 프로세스의 예외·제한 기준 정의

### 1.2 적용 범위

본 정책은 커머스 서비스에서 장바구니 담기부터 주문·배송·클레임 완료까지 Order 도메인이
직접 책임지는 범위를 대상으로 한다.

**포함 범위**

- 장바구니 대상·담기·변경 정책
- 주문 생성·변경·확정·취소 정책
- 배송 유형·배송비·출고·배송처리 정책
- 클레임 유형·신청·처리·비용 정책
- 각 하위 프로세스의 상태 목록(전이 규칙은 DH 참조)

**제외 범위**

- 결제수단·PG 연동·결제 승인/실패 내부 로직 → `DBA-도메인정책서/payment.md`
- 쿠폰·할인·중복정책의 정책 값 원본 → `DBA-도메인정책서/promotion.md`
- 상태 전이 다이어그램·가드·부수효과 → `DH-상태머신/order.md`
- 화면 UI/UX 상세 설계, API·데이터 구조, 구현 방식 → 후속 산출물(DN·DL·DF·코드구현)

### 1.3 용어 정의

| 용어 | 정의 |
|---|---|
| 장바구니 | 고객이 주문 전 상품을 담아두는 임시 보관 단위 |
| 주문 | 고객이 결제를 통해 확정한 상품·수량·배송지 정보의 단위 |
| 클레임 | 주문 이후 발생하는 취소·반품·교환·환불 요청의 통칭 |
| 배송 실행 | 택배사가 실제로 물건을 이동시키는 구간(`ord_shipment`) |
| 귀책 판정 | 클레임 발생 원인이 고객(CUSTOMER)·판매자(VENDOR) 중 누구에게 있는지 확정하는 절차 |
| 맞교환 원칙 | 교환 시 귀책판정 완료 즉시 교환상품을 선출고하고, 원상품 수취는 그 이후 진행하는 원칙 |
| D+7 자동확정 | 배송완료 후 7일이 지나면 별도 조작 없이 구매확정으로 전환되는 규칙 |

### 1.4 기본 원칙

| # | 원칙 | 설명 |
|---|---|---|
| ① | 명확성 | 각 하위 프로세스(장바구니·주문·배송·클레임)의 대상·조건·처리 방법을 명확하게 정의한다 |
| ② | 조건 분리 | 대상·처리조건·금액·상태를 독립적인 정책 요소로 관리한다 |
| ③ | 일관성 | 동일한 유형의 처리(예: 취소)는 프로세스 단계와 무관하게 동일한 기준을 따른다 |
| ④ | 상태 단일 원천 | 상태 목록·전이 규칙의 Single Source of Truth는 DH이며, 이 문서는 목록만 인용한다 |
| ⑤ | 책임 주체 분리 | 직매입/입점형에 따라 재고관리·품절책임·출고배송 책임 주체가 다름을 명시한다 |
| ⑥ | 예외 최소화 | 일반 정책으로 처리할 수 있는 경우에는 공통 정책을 적용하고, 불가피한 경우에만 예외 조건을 정의한다 |

## 2. 장바구니 정책서

### 2.1 장바구니 대상

| 구성 | 설명 |
|---|---|
| 상품 | 담기 대상 상품 |
| 옵션 | 상품별 옵션(색상·사이즈 등) |
| 수량 | 상품·옵션별 담은 수량 |
| 판매 상태 | 판매중/품절/판매종료 등 Catalog 연동 상태 |

### 2.2 상품 담기 정책

| 항목 | 정책 |
|---|---|
| 담기 조건 | 로그인 여부와 무관하게 담기 가능(비회원은 §5 운영 정책 참조) |
| 재고 확인 | 담기 요청 시 Catalog PublicApi로 재고 확인, 품절 시 담기 거부 |
| 판매 가능 여부 | 판매상태·행사가격 유효성을 Catalog/Promotion PublicApi로 확인 |
| 중복 상품 처리 | 동일 상품·동일 옵션 재담기 시 수량 합산(신규 행 생성 아님) |

### 2.3 상품 변경 정책

| 항목 | 정책 |
|---|---|
| 수량 변경 | 담긴 상품의 수량 증감, 동일 상품 최대 수량 제한 적용 |
| 옵션 변경 | 옵션 변경 시 재고·가격 재확인 |
| 상품 삭제 | 개별/선택/전체 삭제 지원 |
| 변경 가능 조건 | 주문 전환 전까지 자유롭게 변경 가능 |

### 2.4 금액 정책

| 항목 | 정책 |
|---|---|
| 상품금액 | 상품가 × 수량 |
| 할인금액 | Promotion 연동 계산 (원본: `promotion.md` 2.1·2.4) |
| 쿠폰 | 적용 가능 쿠폰 목록·금액은 Promotion 연동 (원본: `promotion.md`) |
| 포인트 | 적립·사용 연동 대상, 정책 원본 소유 도메인 미확정 **[Human Review]** |
| 배송비 | §4 배송 정책서 배송비 정책 참조 |
| 예상 결제금액 | 상품금액 - 할인금액 - 쿠폰 - 포인트 + 배송비 |

### 2.5 프로모션 적용 정책

> 중복정책·우선순위·최대할인의 정책 값 원본은 `DBA-도메인정책서/promotion.md` 2.7
> 적용정책이다. 이 절에서는 장바구니 시점에 그 정책을 어떻게 호출·반영하는지만 다룬다.

| 항목 | 정책 |
|---|---|
| 상품 할인 | Catalog 상품별 행사가 반영 (원본: `promotion.md` 2.1) |
| 장바구니 할인 | 주문(장바구니 전체) 금액 기준 할인 (원본: `promotion.md` 2.2) |
| 쿠폰 | 적용 가능 쿠폰 후보 조회·검증 (원본: `promotion.md` 2.1·2.6) |
| 적용 조건 | 기간/금액/수량 조건 검증 (원본: `promotion.md` 2.3) |
| 중복 정책 | 할인차수·중복허용·우선순위·최대할인 (원본: `promotion.md` 2.7 — 여기서는 참조만) |
| 재계산 시점 | 담기·수량변경·로그인 후 머지 시, 행사 변경(updated_at 비교) 감지 시 재계산 |

### 2.6 주문 전환 정책

| 항목 | 정책 |

### 2.7 장바구니 상태

> 상태 목록만 표기한다. 전이 규칙·가드·부수효과는 장바구니 자체가 독립 상태머신을 갖지 않고

| 상태 | 설명 |
|---|---|
| 활성 | 담긴 상품이 유효한 상태 |
| 만료 | 보관 기간 초과로 자동 삭제 대상 |

## 3. 주문 정책서

### 3.1 주문 유형

| 유형 | 설명 |
|---|---|
| 일반주문 | 장바구니/바로구매를 통한 표준 주문 흐름 |

> 예약주문·기타 주문 유형은 현재 DB-도메인정의서·DC 상위유스케이스에 근거가 없어 본문에서
> 제외한다(`DC-상위유스케이스/order.md` 부록A와 동일한 제외 원칙 적용).

### 3.2 주문 생성 정책

| 항목 | 정책 |
|---|---|
| 주문 생성 조건 | 장바구니 주문 전환(§2.6) 또는 바로구매(장바구니 미경유) |
| 주문 상품 | 장바구니 담긴 항목 또는 바로구매 단일 상품 |
| 수량 | 장바구니와 동일 규칙 적용 |
| 주문자/수령자 | 주문자=로그인 회원, 수령자는 배송지 정보로 별도 지정 가능 |
| 주문금액 | §2.4 금액 정책과 동일 산식, 최소/최대 결제금액 제한 적용(값은 AS-IS 정책서 §7.4.1 참조) |

### 3.3 주문 변경 정책

| 항목 | 정책 |
|---|---|
| 상품 변경 | 결제 완료 전(TEMP~PAYMENT_PENDING)까지만 가능 |
| 수량 변경 | 결제 완료 전까지만 가능 |
| 배송정보 변경 | 출고 전(PREPARING 이전)까지 고객 채널에서 변경 가능. CS 대행 변경 API는 미설계(`DC-order.md` ④ 권한범위 참조) — **[Human Review]** |
| 변경 가능 조건 | 상태별 허용 범위는 `DH-상태머신/order.md` §1 ord_order 전이 규칙 참조 |

### 3.4 주문 확정 정책

| 항목 | 정책 |
|---|---|
| 주문 확정 조건 | 배송완료(DELIVERED) 상태에서 고객 수동 확정 또는 D+7 자동 확정 |
| 확정 시점 | 클레임 진행 중인 주문은 확정 보류 |

### 3.5 주문 취소 정책

| 항목 | 정책 |
|---|---|
| 취소 가능 조건 | PAYMENT_COMPLETED 상태까지 고객 단순 취소 가능, PREPARING은 CS 예외 취소만 가능 |
| 취소 불가 조건 | IN_DELIVERY 이후(배송실행 중)·CONFIRMED 이후는 취소 불가 — 반품(클레임)으로 전환 |
| 취소 처리 | 재고 복원, 결제 환불 요청(Payment 연동), 쿠폰/포인트 복원 |

### 3.6 주문 상태

| 상태 | 설명 |

| PAYMENT_COMPLETED | 결제 완료 |
| PREPARING | 출고 준비~배송 중 |
| DELIVERED | 배송 완료 |
| CONFIRMED | 구매 확정 |
| CANCELLED | 취소 |
| PAYMENT_FAILED | 결제 실패 |
| STOCK_FAILED | 재고 부족 실패 |

### 3.7 예외/제한 정책

|---|---|
| 재고 부족 | STOCK_FAILED 즉시 종료, 고객 알림 |

| 유형 | 설명 |
|---|---|
| 일반배송 | 단일 배송지·단일 택배사 처리 |

> 예약배송·묶음배송·분리배송은 현재 DB-도메인정의서·DC 상위유스케이스에 근거가 없어 본문에서

### 4.2 배송 대상 정책

| 항목 | 정책 |
|---|---|
| 배송 상품 | PAYMENT_COMPLETED 상태 주문의 상품 |
| 배송지 | 주문 시 지정한 배송지(§3.3 배송정보 변경 규칙 적용) |
| 배송 그룹 | 입점사 단위로 그룹화(입점사별 개별 출고) |
| 배송 가능 지역 | 현재 정책서에 지역 제한 근거 없음 — 전국 배송 전제 |

### 4.3 배송비 정책

> 상세 산식은 §2.4 금액 정책·`promotion.md` 2.2(배송혜택)를 참조한다. 이 절은 배송 자체의
> 처리 기준만 다룬다.

| 항목 | 정책 |
|---|---|
| 무료배송 | 프로모션 배송혜택 적용 시(원본: `promotion.md`) |
| 유료배송 | 기본 배송비 부과 |
| 조건부 무료배송 | 최소 주문금액 조건 충족 시(원본: `promotion.md` 2.3) |

### 4.4 출고 정책

| 항목 | 정책 |
|---|---|
| 출고 조건 | 입점사 확인 후 PAYMENT_COMPLETED→PREPARING 전이(`DH-상태머신/order.md` 참조) |
| 출고 처리 | 입점사가 출고관리에서 처리 |
| 송장 등록 | 운송장 등록 시 `ord_shipment` PENDING→IN_TRANSIT 전이 |

### 4.5 배송 처리 정책

| 항목 | 정책 |
|---|---|
| 배송 시작 | `ord_shipment` IN_TRANSIT |
| 배송중 표시 | PREPARING + shipment(OUTBOUND).status=IN_TRANSIT 조인으로 화면에서 계산(파생 상태) |
| 배송완료 | 택배사 배송완료 확인(배치) → shipment DELIVERED → order DELIVERED(파생) |
| 배송 실패 | shipment FAILED → 재발송 처리(PENDING으로 복귀) |

### 4.6 배송 상태

> 상태 목록만 표기한다. 전이 규칙은 `DH-상태머신/order.md` §3 ord_shipment.status를
> 참조한다.

| 상태 | 설명 |
|---|---|
| PENDING | 운송장 미등록 |
| IN_TRANSIT | 운송장 등록, 이동 중 |
| DELIVERED | 배송완료 |
| FAILED | 배송실패/반송 |
| CANCELLED | 상위 주문/클레임 취소로 배송 취소 |

### 4.7 배송 예외 정책

| 예외 | 처리 |
|---|---|
| 배송지 오류 | 입점사/CS가 배송관리에서 재발송 처리 |
| 배송 지연 | 별도 SLA 정책 없음 — 후속 확정 필요 **[Human Review]** |
| 배송 불가 | shipment FAILED 처리 후 재발송 또는 클레임 전환 |
| 분실/파손 | 클레임(§5)으로 전환 처리 |

### 4.8 운영 정책

| 항목 | 정책 |
|---|---|
| 택배사 | 입점사별 택배사 연동(Mock, 외부 실연동 Out-of-Scope) |
| 송장 | 운송장 번호는 shipment 레코드에 저장 |
| 배송 추적 | 60분 주기 배치로 택배사 배송완료 확인 |
