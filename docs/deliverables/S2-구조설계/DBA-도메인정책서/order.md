> **단계**: 구조설계
> **문서범위**: Domain
> **문서종류**: Design
>
> **작성 목적**: 도메인 내부의 정책 축·속성 카탈로그를 구조화한다 — 상위 유스케이스(DC)·EARS(DD)·
> ERD(DF)가 "무엇을 만들지" 판단하기 전에 "이 도메인이 어떤 규칙 축으로 구성되는지"를 먼저 정리한다.

## 1. 정책 개요

### 1.1 목적

Order 도메인(장바구니~주문~배송~클레임)의 생성·변경·상태전이·예외처리에 필요한 공통 정책을
정의하여, 주문 처리가 일관된 기준에 따라 수행되고 도메인 간 연동 규칙이 명확하게 관리되도록
한다.

- 장바구니 담기·변경·주문 전환 조건 정의
- 주문 생성·변경·확정·취소 조건 정의
- 배송 유형·배송비·출고 처리 기준 정의
- 클레임(반품/교환/환불) 신청·처리·비용 기준 정의
- 각 하위 프로세스의 예외·제한 기준 정의

### 1.2 적용 범위

본 정책은 커머스 서비스에서 장바구니 담기부터 주문·배송·클레임 완료까지 Order 도메인이
직접 책임지는 범위를 대상으로 한다.

**포함 범위**

- 장바구니 대상·담기·변경 정책
- 주문 생성·변경·확정·취소 정책
- 배송 유형·배송비·출고·배송처리 정책
- 클레임 유형·신청·처리·비용 정책
- 각 하위 프로세스의 상태 목록(전이 규칙은 DH 참조)

**제외 범위**

- 결제수단·PG 연동·결제 승인/실패 내부 로직 → `DBA-도메인정책서/payment.md`
- 쿠폰·할인·중복정책의 정책 값 원본 → `DBA-도메인정책서/promotion.md`
- 상태 전이 다이어그램·가드·부수효과 → `DH-상태머신/order.md`
- 화면 UI/UX 상세 설계, API·데이터 구조, 구현 방식 → 후속 산출물(DN·DL·DF·코드구현)

### 1.3 용어 정의

| 용어 | 정의 |
|---|---|
| 장바구니 | 고객이 주문 전 상품을 담아두는 임시 보관 단위 |
| 주문 | 고객이 결제를 통해 확정한 상품·수량·배송지 정보의 단위 |
| 클레임 | 주문 이후 발생하는 취소·반품·교환·환불 요청의 통칭 |
| 배송 실행 | 택배사가 실제로 물건을 이동시키는 구간(`ord_shipment`) |
| 귀책 판정 | 클레임 발생 원인이 고객(CUSTOMER)·판매자(VENDOR) 중 누구에게 있는지 확정하는 절차 |
| 맞교환 원칙 | 교환 시 귀책판정 완료 즉시 교환상품을 선출고하고, 원상품 수취는 그 이후 진행하는 원칙 |
| D+7 자동확정 | 배송완료 후 7일이 지나면 별도 조작 없이 구매확정으로 전환되는 규칙 |

### 1.4 기본 원칙

| # | 원칙 | 설명 |
|---|---|---|
| ① | 명확성 | 각 하위 프로세스(장바구니·주문·배송·클레임)의 대상·조건·처리 방법을 명확하게 정의한다 |
| ② | 조건 분리 | 대상·처리조건·금액·상태를 독립적인 정책 요소로 관리한다 |
| ③ | 일관성 | 동일한 유형의 처리(예: 취소)는 프로세스 단계와 무관하게 동일한 기준을 따른다 |
| ④ | 상태 단일 원천 | 상태 목록·전이 규칙의 Single Source of Truth는 DH이며, 이 문서는 목록만 인용한다 |
| ⑤ | 책임 주체 분리 | 직매입/입점형에 따라 재고관리·품절책임·출고배송 책임 주체가 다름을 명시한다 |
| ⑥ | 예외 최소화 | 일반 정책으로 처리할 수 있는 경우에는 공통 정책을 적용하고, 불가피한 경우에만 예외 조건을 정의한다 |

## 2. 장바구니 정책서

### 2.1 장바구니 대상

| 구성 | 설명 |
|---|---|
| 상품 | 담기 대상 상품 |
| 옵션 | 상품별 옵션(색상·사이즈 등) |
| 수량 | 상품·옵션별 담은 수량 |
| 판매 상태 | 판매중/품절/판매종료 등 Catalog 연동 상태 |

### 2.2 상품 담기

| 항목 | 정책 |
|---|---|
| 담기 조건 | 로그인 여부와 무관하게 담기 가능(비회원은 §5 운영 정책 참조) |
| 재고 확인 | 담기 요청 시 Catalog 재고를 확인하고, 품절 시 담기 거부 |
| 판매 가능 여부 | 판매상태는 Catalog, 행사가격 유효성은 Promotion 기준으로 확인 |
| 중복 상품 처리 | 동일 상품·동일 옵션 재담기 시 수량 합산(신규 행 생성 아님) |

### 2.3 상품 변경 정책

| 항목 | 정책 |
|---|---|
| 수량 변경 | 담긴 상품의 수량 증감, 동일 상품 최대 수량 제한 적용 |
| 옵션 변경 | 옵션 변경 시 재고·가격 재확인 |
| 상품 삭제 | 개별/선택/전체 삭제 지원 |
| 변경 가능 조건 | 주문 전환 전까지 자유롭게 변경 가능 |

### 2.4 금액 정책

| 항목 | 정책 |
|---|---|
| 상품금액 | 상품가 × 수량 |
| 할인금액 | Promotion 연동 계산 (원본: `promotion.md` 2.1·2.4) |
| 쿠폰 | 적용 가능 쿠폰 목록·금액은 Promotion 연동 (원본: `promotion.md`) |
| 포인트 | 적립·사용 연동 대상, 정책 원본 소유 도메인 미확정 **[Human Review]** |
| 배송비 | §4 배송 정책서 배송비 정책 참조 |
| 예상 결제금액 | 상품금액 - 할인금액 - 쿠폰 - 포인트 + 배송비 |

### 2.5 할인 항목 노출 정책

> **소유 도메인 안내**: 이 정책의 원본은 Catalog 도메인 정책서(§3.10 화면별 할인가 노출
> 정책)이지만, 실제 적용 화면인 장바구니·주문서는 Order 도메인 소유다. 소유 도메인(Catalog)과
> 적용 화면(Order)이 다른 경우이므로, Order DBA에도 화면 그룹별 노출 규칙을 명시한다.

| 화면 그룹 | 정가 | 행사가 | 전체대상쿠폰 | 회원등급할인 | 조건만족쿠폰 | 장바구니할인 | 포인트사용 |
|---|---|---|---|---|---|---|---|
| 장바구니 (그룹C) | 노출 | 노출 | 노출 | 노출 | 노출 | 노출 | 미노출 |
| 주문서 (그룹D) | 노출 | 항목 구분 표시 | 항목 구분 표시 | 항목 구분 표시 | 항목 구분 표시 | 항목 구분 표시 | 항목 구분 표시 |

> 주문서(그룹D)는 모든 할인 항목을 "정가 → 각 할인 항목 개별 차감 → 최종 결제가" 순서로
> 구분해서 표시한다(예: 행사가할인/공개쿠폰할인/회원등급할인/보유쿠폰할인/장바구니할인/포인트사용을
> 각각 별도 줄로 표시 후 배송비 가산). 값 산정 원본은 §2.4 금액 정책·`promotion.md`를 참조하고,
> 이 절은 "무엇을 어느 화면에서 구분해 보여줘야 하는가"만 규정한다. 실제 화면 배치는 DN에서
> 확정한다.

### 2.6 프로모션 적용 정책

> 중복정책·우선순위·최대할인의 정책 값 원본은 `DBA-도메인정책서/promotion.md` 2.7
> 적용정책이다. 이 절에서는 장바구니 시점에 그 정책을 어떻게 호출·반영하는지만 다룬다.

| 항목 | 정책 |
|---|---|
| 상품 할인 | Catalog 상품별 행사가 반영 (원본: `promotion.md` 2.1) |
| 장바구니 할인 | 주문(장바구니 전체) 금액 기준 할인 (원본: `promotion.md` 2.2) |
| 쿠폰 | 적용 가능 쿠폰 후보 조회·검증 (원본: `promotion.md` 2.1·2.6) |
| 적용 조건 | 기간/금액/수량 조건 검증 (원본: `promotion.md` 2.3) |
| 중복 정책 | 할인차수·중복허용·우선순위·최대할인 (원본: `promotion.md` 2.7 — 여기서는 참조만) |
| 재계산 시점 | 담기·수량변경·로그인 후 머지 시, 행사 변경(updated_at 비교) 감지 시 재계산 |

### 2.7 주문 전환 정책

| 항목 | 정책 |
|---|---|
| 주문 가능 조건 | 판매상태·재고·행사 유효성 재검증 통과 |
| 품절 처리 | 전환 시점 품절 확인된 항목은 자동 제외, 고객 안내 |
| 주문 생성 | §3 주문 정책서로 이관(ord_order TEMP 생성) |

**가격 변경 처리 (행사가 소진 등으로 인한 가격 역전)**

| 케이스 | 처리 방식 |
|---|---|
| 상세 진입 시 행사가 소진 | 상세 화면 상단 안내 배너 (DN에서 확정) |
| 상세 체류 중 행사가 소진 | 실시간 가격 변경 + 토스트 알림 (DN에서 확정) |
| 장바구니 담은 후 소진 | 장바구니 가격 변경 안내, 재계산 후 표시(§2.5 노출 규칙 적용) |
| 주문서 진입 후 소진 | 주문서 가격 재확인 요청, 고객 확인 필수(주문 생성 차단) |

### 2.8 장바구니 상태

> 상태 목록만 표기한다. 전이 규칙·가드·부수효과는 장바구니 자체가 독립 상태머신을 갖지 않고
> 주문 전환 시점에 `ord_order`로 이관되므로, 전이는 `DH-상태머신/order.md` §1(ord_order)의
> `[*]→TEMP` 진입 조건을 참조한다.

| 상태 | 설명 |
|---|---|
| 활성 | 담긴 상품이 유효한 상태 |
| 만료 | 보관 기간 초과로 자동 삭제 대상 |

### 2.9 예외/제한 정책

| 예외 | 처리 |
|---|---|

### 2.10 운영 정책

| 항목 | 정책 |

| 장바구니 보관 | 회원 장바구니 보관 기간(값은 AS-IS 정책서 §7.4.1 참조), 초과 시 자동 삭제 |
| 비회원 장바구니 | 로컬 스토리지/쿠키 기반 보관, 로그인 시 회원 장바구니로 머지 |
| 회원 장바구니 | 서버 저장, 기기 간 동기화 |

### 2.11 연관상품 추천 위젯 (화면 내 영역 안내)

> **소유 도메인 안내**: 이 위젯의 추천 로직·외부 추천 SaaS 연동 정책은 **Catalog 도메인 소유**다
> (`DBA-도메인정책서/catalog.md`, 아직 미작성 — Catalog DBA 진행 시 아래 "확인 필요" 항목을
> 정식 정책으로 정리). 이 절은 장바구니 화면(Order 소유)에 그 영역이 존재한다는 사실과
> 화면상 위치만 기록한다 — §2.5 할인 항목 노출 정책과 동일하게, 소유 도메인과 적용 화면이
> 다른 경우의 표기 원칙을 따른다.

| 항목 | 내용 |
|---|---|
| 위치 | 장바구니 화면 내, 담긴 상품 목록 하단 |
| 영역 성격 | "함께 구매하면 좋은 상품" 연관상품 추천 위젯 |
| 데이터 원천 | Catalog가 외부 상품추천 SaaS로부터 대상상품을 전달받아 제공 |
| Order의 역할 | 추천 결과를 화면에 배치·노출만 함(추천 로직·외부 연동에 관여하지 않음) |

> **Catalog DBA 진행 시 확인 필요**(현재 미확정, Human Review):
> - 연동 주체: Catalog가 외부 SaaS 연동을 전담하는지
> - 외부 연동 범위: SaaS 추천 로직 자체는 Out-of-Scope로 두고 "요청→응답" 계약만 정의할지
>   (PG·택배사 Out-of-Scope 원칙과 동일선상, `D4-범위(Scope).md` 참조)
> - 검증 필터: SaaS가 반환한 상품 중 품절·판매종료 상품을 Catalog가 제외하고 노출하는지
> - 프로모션 연동: 추천 상품에도 `promotion.md`·§2.5 노출정책(정가·행사가 등)을 동일 적용할지
> - 실패 시 처리: SaaS 응답 지연·실패 시 위젯을 숨기는지, 대체 로직(MD 수동 추천)으로
>   대체하는지

## 3. 주문 정책서

### 3.1 주문 유형

| 유형 | 설명 |
|---|---|
| 일반주문 | 장바구니/바로구매를 통한 표준 주문 흐름 |
