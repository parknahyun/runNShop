## 1. 정책 개요

### 1.1 목적

결제 요청·승인·실패·취소·환불에 필요한 공통 정책을 정의하여, 결제 처리가 일관된 기준에 따라
수행되고 Order·Settlement 등 연동 도메인과의 책임 경계가 명확하게 관리되도록 한다.

- 결제수단 종류 및 지원 범위 정의
- 결제금액 산정·제한 기준 정의
- 결제 처리(요청~승인~실패~취소~환불) 흐름의 정책 경계 정의
- 결제 실패·예외 상황의 처리 기준 정의
- PG 연동·운영 관련 제약 정의

### 1.2 적용 범위

본 정책은 Payment 도메인이 직접 책임지는 결제수단 관리부터 승인·취소·환불까지를 대상으로
한다.

**포함 범위**

- 결제 유형·결제수단 정책
- 결제금액 정책(Order에서 넘어온 금액을 기준으로 승인·환불 처리)
- 결제 처리(요청/승인/실패/취소/환불) 정책
- 결제 실패/예외 정책
- PG 연동·거래 추적 등 운영 정책

**제외 범위**

- 장바구니·주문·배송·클레임의 업무 프로세스 → `DBA-도메인정책서/order.md`
- 쿠폰·포인트 등 할인 산정의 정책 값 원본 → `DBA-도메인정책서/promotion.md`(쿠폰), 소유
  도메인 확정 후 이관(포인트)
- 상태 전이 다이어그램·가드·부수효과 → `DH-상태머신/payment.md`
- 화면 UI/UX 상세 설계, API·데이터 구조, 구현 방식 → 후속 산출물(DN·DL·DF·코드구현)

### 1.3 용어 정의

| 용어 | 정의 |
|---|---|
| 결제 | 고객이 주문 금액을 실제로 지불하는 행위와 그 기록 단위(`pay_payment`) |
| 결제수단 | 카드·계좌이체·간편결제 등 결제에 사용하는 수단 |
| 승인 | PG사가 결제 요청을 최종 확정하는 처리 |
| 취소 | 승인 전 또는 승인 후 결제를 무효화하는 처리(전액) |
| 환불 | 승인된 결제 금액의 전부 또는 일부를 고객에게 되돌리는 처리 |
| 부분 환불 | 클레임(개별 상품 반품 등)에 따라 결제금액의 일부만 환불하는 처리 |
| 멱등 보장 | 동일 PG 트랜잭션에 대해 중복 승인·중복 환불이 발생하지 않도록 하는 원칙 |

### 1.4 기본 원칙

| # | 원칙 | 설명 |
|---|---|---|
| ① | 명확성 | 결제수단·금액·처리 단계를 명확하게 정의한다 |
| ② | 상태 단일 원천 | 상태 목록·전이 규칙의 Single Source of Truth는 DH이며, 이 문서는 목록만 인용한다 |
| ③ | 원결제 수단 환불 원칙 | 환불은 원칙적으로 원결제 수단으로 처리한다(REQ-PAY-013) |
| ④ | 재시도 제한 | PG 승인 요청은 정해진 횟수·간격으로만 재시도하고, 소진 시 즉시 실패 처리한다 |
| ⑤ | 도메인 경계 준수 | Order의 업무 프로세스·쿠폰/포인트 정책 값은 이 문서에서 재정의하지 않고 참조만 한다 |

## 2. 결제 유형

| 유형 | 설명 |
|---|---|
| 일반결제 | 신용/체크카드, 계좌이체 등 표준 결제수단 |
| 간편결제 | 카카오페이·네이버페이 등 간편결제 수단(연동 방식은 Mock) |

> 이번 파일럿은 외부 PG 실연동이 Out-of-Scope이므로, 결제 유형별 실제 PG사 연동 세부사항은
> 이 문서에서 확정하지 않는다(`docs/deliverables/S0-착수/D4-범위(Scope).md` Out-of-Scope).

## 3. 결제수단 정책

| 수단 | 정책 |
|---|---|
| 신용/체크카드 | 카드사별 무이자 할부 설정 가능(값은 운영자 admin 설정, AS-IS 정책서 §7.4.1 참조) |
| 계좌이체 | 실시간 계좌이체만 지원(가상계좌는 이번 범위에서 제외) |
| 간편결제 | Mock 연동, 실제 PG 인증 없음 |
| 기타 | 정의된 근거 없음 — 확장 시 이 절에 추가 |

## 4. 결제금액 정책

> 상품금액·할인금액·쿠폰·포인트 산정 원본은 Order/Promotion 소유다. 이 절은 Payment가 그
> 결과값을 받아 승인·환불에 어떻게 반영하는지만 다룬다.

| 항목 | 정책 |
|---|---|
| 상품금액 | Order에서 확정한 주문금액을 그대로 승인 요청 금액으로 사용 |
| 할인금액 | Order/Promotion 연산 결과값 반영(정책 원본: `promotion.md`) |
| 배송비 | Order에서 확정한 배송비 포함 금액으로 승인 요청 |
| 쿠폰 | 쿠폰 적용 후 최종 금액 기준 승인(정책 원본: `promotion.md`) |
| 포인트 | 포인트 차감 후 최종 금액 기준 승인, 소유 도메인 미확정 **[Human Review]** |
| 최종 결제금액 | Order가 넘긴 금액과 PG 승인 금액이 일치해야 함(금액 일치 검증, REQ-PAY-007) |
| 최소/최대 결제금액 | 최소 1,000원, 최대 300만원(1회 결제 상한, 값은 AS-IS 정책서 §7.4.1 참조) |

## 5. 결제 처리 정책

> 전이 규칙·가드·부수효과는 `DH-상태머신/payment.md`를 참조한다. 이 절은 각 처리 단계의
> 정책적 경계(누가·언제·몇 번까지)만 다룬다.

| 항목 | 정책 |
|---|---|
| 결제 요청 | Order로부터 최종 금액을 받아 PG 요청 생성(pay_payment PENDING) |
| 승인 | PG 승인 응답 시 금액 일치 검증 후 PAYMENT_APPROVED 이벤트 발행 → Order |
| 실패 | 재시도 없이 즉시 실패 처리(값: AS-IS 정책서 §7.3), 3회 재시도 소진 시 PAYMENT_FAILED 이벤트 발행 |
| 취소 | ORDER_CANCELLED 이벤트 수신 시 PG 전액 환불 요청 |
| 환불 | CLAIM_COMPLETED 이벤트 수신 시 부분/전액 환불, 원결제 수단으로 처리(REQ-PAY-013) |

## 6. 결제 상태

> 상태 목록만 표기한다. 전이 규칙·전이 다이어그램은 `DH-상태머신/payment.md`
> pay_payment.status를 참조한다(중복 작성하지 않음).

| 상태 | 설명 |
|---|---|
| PENDING | 결제 대기(PG 요청 전 또는 요청 중) |
| PAID | 결제 완료(PG 승인 성공) |
| CANCELLED | 결제 취소(PG 실패 또는 전액 환불) |
| REFUNDED | 전액 환불 완료 |
| PARTIAL_REFUNDED | 부분 환불 완료 |

## 7. 결제 실패/예외 정책

| 예외 | 처리 |
|---|---|
| 승인 실패 | 재시도 없이 즉시 실패 처리, 보상 처리(재고·포인트·쿠폰 복원) 1회 시도 후 실패 시 운영팀 이관 |
| 결제 중단 | 고객이 결제 진행 중 이탈 시 PENDING 상태로 남고 이후 자동/수동 취소 처리 |
| 승인 후 주문 실패 | Order 측 재고 확보 실패 등으로 승인 후 주문이 실패하면 즉시 전액 환불 요청 |
| 중복 결제 | pg_transaction_id 기준 멱등 보장으로 방지(1.4 원칙 ④) |
| 재시도 기준 | 타임아웃 30초, 최대 3회 재시도(값은 AS-IS 정책서 §7.3, REQ-PAY-003/005 참조) |
| 모니터링 임계치 | 결제 승인 오류 10분 내 2회 이상 발생 시 관리자 알림(값은 AS-IS 정책서 §7.3 참조) |

| 후속 산출물 | 이 문서를 어떻게 쓰는가 |
|---|---|

## 자가평가

- **완전성**: 충족 — 결제 유형·수단·금액·처리·상태·예외·운영 전 영역을 1~8 섹션으로 커버, order.md에서 분리한 원본 내용 누락 없이 이관
- **일관성**: 충족 — 상태 정책은 DH 참조로 통일, 쿠폰/포인트는 소유 도메인(promotion.md/미확정) 참조로 통일
- **추적성**: 충족 — 각 항목에 원본 산출물(DH·AS-IS 정책서·REQ-PAY-ID) 명시
- **실행가능성**: 충족 — 후속 산출물 연계 표로 DC~DG가 이 문서를 어떻게 쓸지 명시
- **정책 준수**: 충족 — work-scope 룰 예외 승인 범위(Order·Payment 도메인 정책서 작성) 내에서 진행, 1.2 제외 범위로 Order/Promotion과의 경계 명확화
