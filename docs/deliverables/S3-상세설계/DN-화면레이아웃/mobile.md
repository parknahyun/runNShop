### 화면 구성

| 영역 | 데이터 소스 (API) | 표시 내용 |
|---|---|---|
| Header | — | "장바구니" 타이틀 + 전체 수량 `total_count` |
| 입점사별 상품 그룹 | GET /api/v1/cart → `vendors[]` | 입점사명, 배송비/무료배송 기준, 상품 목록 |
| 상품 카드 | GET /api/v1/cart → `vendors[].items[]` | 상품이미지, 상품명, 옵션(color/size), 정상가(취소선), 판매가, 수량(+/- 버튼), 삭제 |
| 혜택 안내 | GET /api/v1/cart → `summary` | 사용 가능 쿠폰 수(`coupon_benefit_text`), 포인트 잔액(`point_balance`) |
| 장바구니 할인행사 | GET /api/v1/cart → `cart_promotions[]` | 적용된 행사명, 할인 조건(N개 이상/세트 등), 할인 금액, 적용 여부 |
| 금액 요약 (CartSummary) | GET /api/v1/cart → `summary` | 상품금액, 상품할인, 장바구니할인, 배송비, 총 결제 예상금액 |
| 수량 변경 | PATCH /api/v1/cart/items/{cart_item_id}/quantity | +/- 버튼 클릭 시 재계산 |
| 옵션 변경 | PUT /api/v1/cart/items/{cart_item_id}/option | [옵션변경] 클릭 → 레이어 팝업(색상/사이즈 선택) → 변경 완료 시 재계산. 품절 판정 = 실재고 − 장바구니 선점수량 ≤ 0 (본인+타 고객 장바구니 포함), 품절 옵션 선택 불가 |
| 삭제 | DELETE /api/v1/cart/items/{cart_item_id} | 삭제 버튼 |
| CTA (CartBottomBar) | — | "선택상품 주문하기 · {total_payment}원" → 주문서(/orders/new) 이동 |

### 화면 구성

| 영역 | 데이터 소스 (API) | 표시 내용 |
|---|---|---|
| Header | — | "주문서" 타이틀 |
| 배송지 (AddressSection) | POST /api/v1/orders/sheet → `addresses[]` | 기본 배송지 표시. [변경] 클릭 시 배송지 선택 레이어 팝업 → 등록된 배송지 목록에서 선택(라디오). 주문서에서 직접 입력 불가, 비회원 주문 없음. 배송지 추가/수정은 마이페이지 > 배송지 관리에서 처리 |
| 주문 상품 (OrderItemList) | POST /api/v1/orders/sheet → `orders[]` | 입점사별 그룹 → 상품이미지, 상품명, 옵션, 판매가, 수량 |
| 쿠폰 (CouponSection) | POST /api/v1/orders/sheet → `coupons` | 사용 가능 쿠폰 수 표시, [>] 클릭 시 레이어 팝업. 팝업 진입 시 서버에서 모든 쿠폰 조합별 할인 결과를 캐시로 전달 → 라디오 선택 즉시 비교 금액 표시(서버 호출 없음). 현재 할인(즉시/조건) vs 쿠폰 할인 비교 + 유불리 표시. [적용하기] 클릭 시 서버 확정(Phase 2 재계산). 상품쿠폰↔즉시할인, 장바구니쿠폰↔조건할인 택1. 배송비쿠폰은 중복 적용 가능 |
| 포인트 (PointSection) | POST /api/v1/orders/sheet → `point` | 보유 포인트(`balance`), 사용 가능(`usable`), 최소 사용 1,000P, 포인트 입력 필드 + [전액사용] 버튼. 1,000P 미만 입력 시 "최소 1,000P부터 사용 가능합니다" 안내 |
| 결제수단 (PaymentMethod) | POST /api/v1/orders/sheet → `payment_methods[]` | 결제수단 버튼 목록 (신용카드, 계좌이체 등), 단일 선택 |

### 클레임 배송비 결제 (교환·반품)

> 고객 귀책 사유(단순 변심 등)로 교환·반품 신청 시 **클레임 배송비를 고객이 결제**해야 한다.
> 배송비 결제는 **클레임 상세 화면(§10)**에서 진행한다.

| 항목 | 내용 |
|---|---|
| 적용 조건 | 귀책 = 고객 (CUSTOMER) 인 교환·반품 |
| 배송비 금액 | 정책에 따라 결정 (예: 편도 5,000원) |
| 결제 시점 | 클레임 접수 후, 클레임 상세에서 배송비 결제 (결제 완료 시 수거 진행) |
| 결제 수단 | 기등록 결제수단 또는 주문 시 사용한 결제수단 |
| 입점사 귀책 | 배송비 0원 (결제 불필요, 즉시 수거 진행) |

### 클레임 상태 흐름 (배송비 결제 포함)

> **v6 갱신**: 배송 실행 구간(수거중/반송 배송중)은 더 이상 `claim.status` 값이 아니다. 공용 배송실행 엔티티 `ord_shipment`(shipment_type=PICKUP/RETURN)로 분리되었고, `claim.status`는 "고객·입점사·CS가 판단·결정하는 지점"만 표현한다. 아래 흐름에서 "수거 진행 중"·"반송 배송중"으로 화면에 보이는 문구는 `claim.status` + `shipment.status` 조인으로 계산되는 파생 표시이며, 실제 claim.status 값은 아니다(예: 화면 표시 "수거중" = claim.status(PAYMENT_PENDING 결제완료 후 또는 INSPECTING 진입 전) + shipment(PICKUP).status=IN_TRANSIT).

```
[정상 흐름]
접수(RECEIVED)
  → 배송비 결제 대기(PAYMENT_PENDING) ... [고객 귀책 시, 결제완료 후 shipment(PICKUP) 자동생성·진행]
  → 품질점검(INSPECTING) ................ [shipment(PICKUP) 배송완료 시 자동 진입(고객 귀책) 또는 입점사 귀책 시 즉시 진입, 입점사: 합격/거부 판정]
  → 수거완료(PICKED_UP) ................. [입점사: 합격 확인]
  → 환불완료(REFUNDED) .................. [어드민: 환불 처리]
  → 클레임완료(COMPLETED) ............... [배치: 자동 전환]

[품질점검 거부 (수거거부)]
  → 품질점검(INSPECTING)
  → 수거거부(PICKUP_REJECTED) ........... [입점사: 불합격 + 사유 등록]
  → 어드민 판정:
     ├─ 폐기(DISPOSED) → 클레임완료(COMPLETED)
     └─ 추가결제요청 → 반송 배송비 결제 대기(RETURN_PAYMENT_PENDING) ... [고객 결제 후 shipment(RETURN) 진행] → shipment(RETURN) 배송완료 → 클레임완료(COMPLETED)

[반려 (접수 단계)]
접수(RECEIVED) → 반려(REJECTED) ......... [어드민]

[결제 미완료]
접수(RECEIVED) → 배송비 결제 대기(PAYMENT_PENDING) → 1일 초과 → 자동취소(PAYMENT_EXPIRED)
```

### 클레임 상태별 정리

> claim.status 11상태 (v6 — PICKUP/RETURN_SHIPPING/RETURN_DELIVERED는 `ord_shipment`로 이관되어 제외). 근거: `S2-구조설계/DH-상태머신/order.md` §2.

| 상태 | 설명 | 수행 주체 |
|---|---|---|
| RECEIVED | 접수됨 | 고객 신청 |
| PAYMENT_PENDING | 수거 배송비 결제 대기 ~ 수거 진행 중 (고객 귀책, shipment(PICKUP) 병행) | 고객 → 입점사 (수거정보 입력) |
| PAYMENT_EXPIRED | 결제 1일 초과 → 자동 취소 | 배치 |
| INSPECTING | 품질점검 진행 중 (입점사 귀책 즉시 또는 shipment(PICKUP) 배송완료 후 진입) | 입점사 (합격/거부 판정) |
| PICKED_UP | 수거완료 (품질점검 합격) | 입점사 |
| PICKUP_REJECTED | 수거거부 (품질점검 불합격) | 입점사 (사유 등록) |
| REFUNDED | 환불 완료 | 어드민 |
| RETURN_PAYMENT_PENDING | 반송 배송비 결제 대기 ~ 반송 진행 중 (불합격 반송, shipment(RETURN) 병행) | 고객 → 입점사 (운송장 등록) |
| DISPOSED | 폐기 처리 | 어드민 |
| COMPLETED | 클레임 전체 완료 | 배치 (자동) |
| REJECTED | 접수 단계 반려 | 어드민 |

> 수거중/반송배송중 진행 상태의 상세(운송장·이동중·배송완료 등)는 `ord_shipment.status`(PENDING/IN_TRANSIT/DELIVERED/FAILED/CANCELLED)를 참조한다.
