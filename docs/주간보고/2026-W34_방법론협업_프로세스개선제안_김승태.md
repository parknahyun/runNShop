# 방법론 협업 프로세스 개선 제안

> **프로젝트**: runNshop
> **작성일**: 2026.08.21
> **작성자**: 김승태
> **대상**: PM / TL / 전체 개발팀

---

## 1. 배경

현재 runNshop 방법론 적용 시, 선두 작업자(Order/Payment 담당)가 기준을 정립하면 후발 작업자(Promotion/Catalog/Member 등)가 이어서 진행하는 구조로 운영 중입니다.

그러나 후발 작업자가 선두 작업자의 **의도·기획·히스토리를 파악하는 데 과도한 시간이 소요**되는 문제가 반복적으로 발생하고 있어, 개선 방안을 제안합니다.

### 현재 흐름

```
선두 작업자 (Order/Payment)
  → 방법론 확립 + 산출물 기준 정립 + ADR 결정
                      ↓ (시간차 발생)
후발 작업자 (Promotion/Catalog/Member...)
  → 정해진 기준을 따라가려 하나
  → "왜 이렇게 했지?" 매번 문의
  → 의도·히스토리·결정 맥락을 알 수 없음
  → 문의 → 대기 → 이해 → 작업 (비효율 반복)
```

## 2. 발견된 문제점

### 2.1 암묵지(Tacit Knowledge) 의존

| 문제 | 구체적 사례 |
|---|---|
| 결정 맥락 미기록 | 파일명 넘버링(06→DC)이 변경됐으나 "왜 변경했는지" 기록 없음. 후발 작업자가 기존 번호(06, 08...)로 작성 후 재작업 발생 |
| 진화 과정 누락 | 문서가 최종 상태만 보여주고, 초안→수정→확정의 변천사가 안 보임 |
| 구두 합의 유실 | 선두 작업자 간 회의에서 결정된 내용이 문서에 미반영된 채 작업 진행 |

### 2.2 온보딩 비용 과다

| 문제 | 구체적 사례 |
|---|---|
| 도메인별 진입 장벽 | 새 도메인 착수 시 "이 도메인은 어떤 패턴을 따라야 하는지" 파악에 1~2일 소요 |
| 선두 작업자 병목 | 문의가 몰리면 선두 작업자의 본 업무 중단 |
| 동일 질문 반복 | "직매입 쿠폰 등록 프로세스는?" 등 여러 담당자가 같은 질문을 각각 문의 |

### 2.3 일관성 유지 어려움

| 문제 | 구체적 사례 |
|---|---|
| 네이밍 불일치 | 같은 개념을 도메인마다 다르게 표기 (REQ 번호 체계 불일치 발견) |
| 패턴 해석 차이 | 같은 작성가이드를 보고도 문서 깊이·구조가 담당자마다 다름 |
| 도메인 간 계약 누락 | Order 이벤트 플로우에 Promotion 수신자 누락 → 쿠폰 복원 로직 미정의 (금주 발견) |

### 2.4 변경 전파 문제

| 문제 | 구체적 사례 |
|---|---|
| 기준 변경 미전파 | 선두 작업자가 파일명 규칙·상태머신 패턴을 변경해도 후발 작업자가 모름 |
| 문서 버전 불일치 | 이전 기준으로 작성한 문서가 새 기준과 충돌 |
| REQ 번호 정합성 | Promotion EARS의 도출근거가 Order EARS 초기 Draft 기준 → 확정 번호와 불일치 |

## 3. 개선 제안 (5건)

### 제안 1: 도메인별 "착수 가이드" 도입

후발 작업자가 새 도메인 착수 시 1페이지 요약 문서를 읽고 바로 작업에 진입할 수 있도록 함.

**포함 내용**:
- 필수 읽기 순서 (선행 문서 목록)
- 이 도메인의 특이사항
- 선두 작업자와의 계약/합의 사항
- 현재 미결 사항

**위치**: `docs/자산화-단계별/S2-구조설계/착수가이드-{Domain}.md`

**예상 효과**: 온보딩 시간 1~2일 → 2~3시간

---

### 제안 2: "의사결정로그" 신설

방법론 디렉토리에 **왜 이렇게 결정했는가**를 시간순으로 기록하는 문서 추가.

**구조**:

| 일자 | 결정 | 맥락 (왜?) | 검토한 대안 | 영향 범위 | 결정자 |
|---|---|---|---|---|---|
| 08-11 | 파일명 D1~DQ 넘버링 도입 | 기존 06~12가 단계(S0~S3) 숫자와 혼동 | 숫자 유지 vs 알파벳 | 전 도메인 파일명 | 페페 |
| 08-21 | Order EARS REQ-ORD-001~076 확정 | 초기 100번대 번호체계 정리 | 기존 번호 유지 vs 리넘버링 | Promotion 도출근거 참조 | 페페 |

**위치**: `docs/방법론/의사결정로그.md`

**예상 효과**: "왜 이렇게 했어요?" 질문 70% 감소

---

### 제안 3: 크로스 도메인 계약 매트릭스

각 도메인이 독립 작업하면서 연동 지점이 빠지는 문제를 방지하기 위해, 이벤트 발행/수신 계약을 한눈에 볼 수 있는 매트릭스 운영.

**구조**:

| 발행 도메인 | 이벤트 | 수신 도메인 | 수신측 REQ | 합의 상태 |
|---|---|---|---|---|
| Order | ORDER_CANCELLED | Payment | REQ-PAY-008 | ✅ 확정 |
| Order | ORDER_CANCELLED | Promotion | — | ⚠️ 협의 중 |
| Order | ORDER_CONFIRMED | Promotion | — | ⚠️ 협의 중 |
| Promotion | DISPLAY_PRICE_CHANGED | Catalog | REQ-CAT-032 | ✅ 확정 |
| Promotion | EVENT_ENDED | Catalog | — | ✅ 확정 |

**위치**: `docs/참고자료/크로스도메인_계약매트릭스.md`

**예상 효과**: 연동 누락 조기 발견, 통합 테스트 시 결함 감소

---

### 제안 4: 협의문서 디렉토리 팀 전체 활용

이번 주 도입한 `docs/참고자료/협의문서/` 구조를 팀 전체가 활용하여, 구두 문의 대신 **문서 기반 비동기 소통**으로 전환.

**기대 효과**:
- 질문이 자산이 됨 (같은 질문 반복 방지)
- 선두 작업자 병목 해소 (즉각 응대 불필요)
- 히스토리 추적 가능
- 다른 후발 작업자도 기존 협의 내용 참조 가능

**네이밍 규칙**: `{YYYYMMDD}_{주제}_{작성자}.md`

---

### 제안 5: CHANGELOG.md 도입

각 주요 디렉토리에 변경 이력을 기록하여, 후발 작업자가 "최근 뭐가 바뀌었는지" 즉시 파악.

**위치**:
```
docs/자산화-단계별/S2-구조설계/CHANGELOG.md
docs/방법론/CHANGELOG.md
```

**구조**:
```markdown
## 2026-08-21
- 파일명 넘버링 변경: 06~12 → D1~DQ (결정자: 페페)
- Order EARS 확정: REQ-ORD-001~076 최종 (기존 100번대 폐기)

## 2026-08-11
- Payment S2-구조설계 6종 Finalized
- Order S2-구조설계 6종 Finalized
```

**예상 효과**: git log 뒤지지 않아도 주요 변경 즉시 파악

## 4. 실행 우선순위

| 순위 | 액션 | 소요 시간 | 담당 제안 | 효과 |
|---|---|---|---|---|

| 4 | 협의문서 팀 활용 공지 | 즉시 | PM | 비동기 소통 정착 |
| 5 | CHANGELOG 도입 | 30분 | 각 디렉토리 관리자 | 변경 전파 해소 |
