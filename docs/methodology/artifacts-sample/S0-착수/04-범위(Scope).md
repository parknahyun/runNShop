# 샘플: 범위 (Scope)

> **단계**: 착수
> **문서범위**: Project
> **문서종류**: Proposal
>
> **작성 목적**: 프로젝트가 "무엇을 하고, 무엇을 하지 않는가"를 명확히 한다.
> In-Scope / Out-of-Scope를 확정하여, 이후 산출물의 대상 범위를 제한한다.
>
> **흐름 내 위치**:
> ```
> 이해관계자맵 → 범위(Scope) → 대안비교 → 리스크가정
> ```
>
> **작성 주체**: PM + 사업 담당자 (의사결정권자 승인)

---

## 필수 항목

| # | 항목 | 설명 |
|---|---|---|
| 1 | **In-Scope (확정)** | 반드시 구현하는 것 |
| 2 | **In-Scope (검토 중)** | 조건부 포함 (Go/No-Go 판단 대상) |
| 3 | **Out-of-Scope** | 명시적으로 제외하는 것 |
| 4 | **제외 리스크 수용** | Out-of-Scope 항목으로 인한 리스크와 수용 여부 |

## 작성 팁

| 팁 | 설명 |
|---|---|
| **Out-of-Scope가 더 중요** | "안 하는 것"을 명시해야 나중에 scope creep 방지 |
| **검토 중 항목에 판단 조건 필수** | "언제 포함할 것인가" 기준 없으면 영원히 검토 중 |
| **제약사항(①)과 연결** | Out-of-Scope 중 기술 제약은 범위정의 ① 제약사항으로 이관 |
| **발주자 서명 대상** | 범위 확정 = 계약 범위. 변경 시 변경 관리 필요 |
