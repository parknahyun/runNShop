# 샘플: 이해관계자 맵

> **단계**: 착수
> **문서범위**: Project
> **문서종류**: Proposal
>
> **작성 목적**: 프로젝트에 관여하는 모든 이해관계자를 식별하고,
> 각자의 역할·권한·관심사를 정의하여 커뮤니케이션 계획의 근거를 만든다.
>
> **흐름 내 위치**:
> ```
> 문제정의서 → 목표KPI → 이해관계자맵 → 범위(Scope)
> ```
>
> **작성 주체**: PM + AI 협업

---

## 필수 항목

| # | 항목 | 설명 |
|---|---|---|
| 1 | 이해관계자 목록 | 누가 관여하는가 |
| 2 | 역할·권한 | 각자 무엇을 하는가 / 무엇을 결정하는가 |
| 3 | 관심사·기대 | 각자가 이 프로젝트에서 원하는 것 |
| 4 | Gap (미확정) | 아직 배정되지 않은 역할 |

## 샘플 (이커머스 플랫폼)

| 이해관계자 | 역할 | 권한 | 관심사 | 확정 여부 |
|---|---|---|---|---|
| 사업 본부장 | Sponsor | Go/No-Go 결정, 예산 승인 | ROI, 일정 준수 | ✅ |
| PM | 프로젝트 관리 | 일정·리소스·리스크 관리 | 일정 준수, 품질 | ✅ |
| 시니어 개발자 | Tech Lead / 설계 | 아키텍처 결정, 코드 리뷰 | 기술 품질, 자산화 | ✅ |
| 기획자 | 요구사항 정리·검토 | 정책 확인, UC 승인 | 업무 정확성 | ✅ |
| AI 에이전트 (Claude/Kiro) | 설계·구현 협업 | 초안 생성, 코드 작성 | — | ✅ |
| 주니어 개발자 (2명) | 구현·테스트 | 코드 작성, 단위테스트 | 학습, 성장 | Gap |
| QA 담당자 | 테스트 계획·실행 | GWT 실행, 버그 보고 | 커버리지, 품질 | Gap |
| 디자이너 | UI/UX 디자인 | Figma 가이드 | 사용성, 일관성 | Gap (mobile 채널) |
| 발주자/현업 | 정책 확인·승인 | 정책서 확정, 최종 검수 | 업무 요구 반영 | ✅ |

### Gap 해소 계획

| Gap | 해소 시점 | 대안 |
|---|---|---|
| 주니어 개발자 | 범위정의 전 채용 | 채용 전까지 시니어+AI로 진행 |
| QA | 테스트 단계 전 | 구조설계까지는 개발자가 GWT 검토 |
| 디자이너 | 상세설계 mobile 화면 시 | admin/partner는 디자이너 없이 진행 |

## 작성 팁

| 팁 | 설명 |
|---|---|
| **Power/Interest 매트릭스 고려** | 권한 높고 관심 높은 사람 = 핵심 관리 대상 |
| **Gap은 명시적으로** | 숨기지 말고 "미확정"을 공개해야 리스크 관리 가능 |
| **AI도 이해관계자** | AI 에이전트의 역할·한계를 명시 |
| **Tasks 단계에서 RACI로 확장** | 이 맵이 RACI 매트릭스의 입력 |
