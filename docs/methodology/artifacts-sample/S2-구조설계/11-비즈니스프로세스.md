# 샘플: 비즈니스 프로세스

> **단계**: 구조설계
> **문서범위**: Domain
> **문서종류**: Design
>
> **작성 목적**: 상태머신(⑩)의 전이를 액티비티 흐름으로 확장하여,
> "누가 어떤 순서로 업무를 수행하는가"를 시각화한다.
> 상태머신이 "전이 규칙"이라면, 비즈니스 프로세스는 "전이를 포함한 업무 전체 흐름"이다.
>
> **흐름 내 위치**:
> ```
> ⑩ 상태머신 → ⑪ 비즈니스 프로세스 → ⑫ 이벤트 플로우
> ```
>
> **작성 주체**: 시니어 개발자 + AI 협업 (기획자·현업 검토·확인)

---

## 도출 방법

| 입력 | 변환 |
|---|---|
| 상태머신(⑩) 전이 1개 | → 프로세스 내 1 액티비티 |
| 상태머신(⑩) 가드 조건 | → 분기(Diamond) |
| 상위UC(⑥) 액터 | → 스윔레인 |
| 정책서 업무 규칙 | → 판단 조건·예외 흐름 |

---

## 샘플: 주문결제 프로세스 (Order 도메인)

```plantuml
@startuml
skinparam backgroundColor transparent
skinparam defaultFontSize 11
title 주문결제 비즈니스 프로세스

|고객|
start
:주문서 작성\n(배송지·쿠폰·포인트 선택);
:결제 요청;

|시스템(Order)|
:재고 선점 요청\n→ Catalog PublicApi;

if (재고 충분?) then (yes)
  :PG 결제 요청\n→ Payment 도메인;
else (no)
  :주문 실패\n(STOCK_INSUFFICIENT);
  stop
endif

|시스템(Payment)|
:PG 승인 처리;

if (승인 성공?) then (yes)
  :결제완료 이벤트 발행;
else (no)
  :결제실패 이벤트 발행;
  |시스템(Order)|
  :재고 복원;
  :PAYMENT_FAILED;
  stop
endif

|시스템(Order)|
:PAYMENT_COMPLETED;
:입점사별 주문 분할;

|판매자|
:출고 준비 확인;
:운송장 등록;

|시스템(Order)|
:IN_DELIVERY;
:배송상태 갱신 (배치, 60분);

if (배송완료?) then (yes)
  :DELIVERED;
else (no)
  :계속 추적;
  stop
endif

|고객|
if (수동 구매확정?) then (yes)
  :구매확정 요청;
else (D+7 경과)
  |시스템(배치)|
  :자동 구매확정;
endif

|시스템(Order)|
:CONFIRMED;
:구매확정 이벤트 발행\n→ Settlement(정산), Member(포인트);
stop

@enduml
```

---

## 작성 팁

| 팁 | 설명 |
|---|---|
| **스윔레인 = 액터** | 상위UC 액터를 그대로 사용 |
| **상태 전이마다 노드 표시** | 상태머신의 전이가 프로세스의 액티비티와 1:1 대응 |
| **도메인 경계 표시** | "→ Catalog PublicApi" 처럼 외부 호출을 명시 |
| **예외 흐름 포함** | 정상만 그리면 안 됨 — 실패·타임아웃 흐름 필수 |
| **이벤트 발행 표시** | 이벤트 플로우(⑫)의 입력이 됨 |

## 근거

| 항목 | 출처 |
|---|---|
