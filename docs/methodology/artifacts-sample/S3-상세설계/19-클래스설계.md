# 샘플: 클래스 설계

> **단계**: 상세설계
> **문서범위**: Bolt
> **문서종류**: Design
>
> **작성 목적**: 시퀀스(⑯)에 등장한 참여 객체를 클래스 구조로 전환한다.
> "어떤 클래스가 어떤 책임을 갖고, 어떤 메서드를 제공하는가"를 확정하여
> 구현(코드) 단계의 직접 입력이 된다.
>
> **흐름 내 위치**:
> ```
> ⑯ 시퀀스 (참여 객체) → ⑲ 클래스 설계 → 구현
> ```
>
> **작성 주체**: 시니어 개발자 + AI 협업

---

## 도출 방법

| 시퀀스 참여자 | → 클래스 | 역할 |
|---|---|---|
| Controller | CartController | HTTP 요청 수신, 응답 반환 |
| Service | CartService | 비즈니스 로직 (검증·조합·트랜잭션) |
| Repository | CartRepository | 데이터 접근 (JPA/QueryDSL) |
| PublicApi | CatalogPublicApi (interface) | 도메인 간 계약 |
| Entity/VO | CartItem, Cart | 도메인 모델 |
| DTO | AddToCartRequest, CartItemResponse | 요청·응답 전송 객체 |

## 작성 규칙

| 규칙 | 설명 |
|---|---|
| 시퀀스 참여자 = 클래스 | 1:1 대응 |
| Controller는 로직 없음 | 요청 수신·응답 반환만 (Thin Controller) |
| Service에 비즈니스 로직 | 검증·조합·트랜잭션 관리 |
| PublicApi = interface | 도메인 간 계약, 구현은 제공 도메인에서 |
| Entity는 행위를 가짐 | `cartItem.addQuantity(n)` — Rich Domain Model |

---

## 작성 팁

| 팁 | 설명 |
|---|---|
| **시퀀스에 없는 클래스는 불필요** | 시퀀스에 등장하지 않은 클래스를 미리 만들지 않음 |
| **메서드 시그니처만** | 구현 로직은 Code 단계에서. 여기서는 계약만 |
| **PublicApi 인터페이스가 핵심** | 도메인 간 경계를 코드 수준으로 명시화 |
| **DTO는 인터페이스 명세와 일치** | Request/Response 필드가 API 문서와 동일해야 함 |
