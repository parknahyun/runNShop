# 샘플: 화면 레이아웃

> **단계**: 상세설계
> **문서범위**: Bolt
> **문서종류**: Design
>
> **작성 목적**: 시퀀스(⑯)에서 확정된 API 호출 시점과 응답 데이터를 화면에 매핑한다.
> "어떤 화면에서 어떤 데이터를 어떤 API로부터 가져와 표시하는가"를 확정한다.
> 동시에, 화면ID·접근권한·화면전환·검증규칙 참조를 메타블록으로 흡수하여
> **일반 웹 개발의 "화면정의서" 역할을 이 문서 하나에서 수행**한다.
>
> **흐름 내 위치**:
> ```
> ⑯ 시퀀스 → ⑰ 화면 레이아웃
> ```
>
> **작성 주체**: 
> - admin/partner: 시니어 개발자 + AI (md → tsx 직행)
> - mobile: 기획자 + AI (md → Figma → tsx)

---

## 채널별 완성 경로

| 채널 | 경로 | 이유 |
|---|---|---|
| admin/partner | md(스펙) → tsx(React) 직행 | 내부 운영 도구, 디자인 자유도 낮음 |
| mobile | md(스펙) → Figma(디자인) → tsx(React) | 고객 대면, UX 중요, 디자이너 협업 필요 |

## 화면 섹션 표준 구조 — 6단 구성 (화면 섹션마다 필수)

> 모든 화면 섹션(`## N. 화면명`)은 아래 6개 하위섹션을 이 순서로 둔다.
> 화면ID는 프로그램목록(⑳ DQ)의 `SCR-*` ID를 그대로 표기하고,
> 관련UC·호출API는 세부유스케이스(⑭)·인터페이스명세(⑮) 파일에 대한 위키링크로 연결한다.
> 검증규칙은 본문에 복제하지 않고 GWT(⑬)·인터페이스명세(⑮)로 링크만 건다 —
> 규칙이 바뀌어도 이 문서를 다시 손댈 필요가 없도록 하기 위함(현행화 자연발생 원칙 유지).

```markdown
## N. {앱} — {화면명} ({컴포넌트명})

### 메타블록

| 항목 | 내용 |
|---|---|
| 화면 ID | SCR-M-001 |
| 앱 | mobile |
| 접근 권한 | 로그인 회원 |
| 관련 세부UC | [[14-세부유스케이스\|UC-1 장바구니 담기]] |
| 호출 API | [[15-인터페이스명세\|API-001~003]] |

### 와이어프레임
(ASCII 목업)

### 화면 구성
| 영역 | 데이터 소스 (API) | 표시 내용 |
|---|---|---|
...

### 화면 전환
| 트리거 | 이동 화면 (SCR-ID) |
|---|---|
| [주문하기] 클릭 | SCR-M-002 (주문서) |
| [옵션변경] 클릭 | 레이어 팝업 (화면 전환 아님) |

### 유효성 검증
> [[13-GWT(수용기준)|GWT §1 장바구니 Bolt]] · 에러코드는 인터페이스명세 참조

### 상태별 UI
| 상태 | 화면 표현 |
|---|---|
...
```

- **화면 전환**: 다른 화면(SCR-ID)으로 이동하는 트리거뿐 아니라, 레이어 팝업·모달처럼 **같은 화면
  내에서 열리는 트리거도 함께 표로 나열**한다 — 다만 이동 화면 칸에 `레이어 팝업 (화면 전환 아님)`처럼
  명시해 실제 화면 이동과 구분한다. 이렇게 해야 "이 화면에서 클릭 가능한 모든 트리거"를 이 표 하나로
  빠짐없이 확인할 수 있다.
- 외부 채널(알림톡·이메일처럼 DQ에 화면(SCR)으로 등록되지 않는 섹션)은 화면 ID를
  `없음 (외부 채널)`로 표기하고, 화면 전환은 "딥링크 클릭 → SCR-*"로 명시한다.
- 위키링크(`[[문서명|표시텍스트]]`) 문법과 도입 방법은
  `docs/reference/working/Foam-위키링크-활용가이드.md` 참조.

### 기획자·개발자 병행 작업 — TBD 태그

> admin/partner 선행 → mobile 후행이 원칙이지만, 실제로는 화면과 API가 거의 동시에 설계되는
> 경우가 많다. 이때 완성본을 주고받지 않고 미완성 칸을 표시하며 각자 채운다.

```markdown
### 화면 구성
| 영역 | 데이터 소스 (API) | 표시 내용 |
|---|---|---|
| 쿠폰 벤더 추천 배너 | [TBD-API] | 이 벤더가 자주 사는 상품 추천 배너 (문구·레이아웃은 확정) |
| 재입고 알림 버튼 | GET /api/v1/products/{id}/stock | [TBD-UX] (API는 확정, 화면 표시 방식 미정) |
```

- `[TBD-API]`: 기획자가 "표시 내용"만 먼저 채우고, 개발자가 DL에 API를 추가한 뒤 실제 경로로 교체
- `[TBD-UX]`: 개발자가 API만 먼저 확정하고, 기획자가 화면 표시 방식을 채움
- `grep -rn "TBD-" docs/deliverables/`로 전수 검색 — Bolt DoD 시점에는 0건이어야 함

## 샘플: 장바구니 화면 (mobile)

### 메타블록

| 항목 | 내용 |
|---|---|
| 화면 ID | SCR-M-001 |
| 앱 | mobile |
| 접근 권한 | 로그인 회원 |
| 관련 세부UC | [[14-세부유스케이스\|UC-1 장바구니 담기]] |
| 호출 API | [[15-인터페이스명세\|API-001 장바구니 담기, API-002 조회, API-003 수량변경]] |

### 화면 구성

| 영역 | 데이터 소스 (API) | 표시 내용 |
|---|---|---|
| Header | — | "장바구니" 타이틀 + 뒤로가기 |
| 상품 목록 | GET /api/v1/cart | 상품이미지, 상품명, 옵션명, 수량, 단가, 소계 |
| 할인 정보 | GET /api/v1/cart (응답 내 포함) | 적용된 행사가, 장바구니 할인 혜택 |
| 수량 변경 | PATCH /api/v1/cart/items/{id}/quantity | +/- 버튼, 재계산 |
| 옵션 변경 | PUT /api/v1/cart/items/{id}/option | [옵션변경] 클릭 → 레이어 팝업(색상/사이즈 선택) |
| 삭제 | DELETE /api/v1/cart/items/{id} | 스와이프 or 체크박스 삭제 |
| 합계 영역 | 계산 (FE) | 상품합계, 할인합계, 배송비, 최종결제금액 |
| CTA | POST /api/v1/checkout | "주문하기" 버튼 → 주문서 화면 이동 |

### 화면 전환

| 트리거 | 이동 화면 (SCR-ID) |
|---|---|
| [주문하기] 클릭 | SCR-M-002 (주문서) |
| [옵션변경] 클릭 | 레이어 팝업 (화면 전환 아님) |

### 유효성 검증

> [[13-GWT(수용기준)|GWT §1 장바구니 Bolt]] · CART_FULL 등 에러코드는 인터페이스명세(⑮) 참조

### 상태별 UI

| 상태 | 화면 표현 |
|---|---|
| 장바구니 비어있음 | 빈 상태 일러스트 + "쇼핑하러 가기" 버튼 |
| 품절 상품 포함 | 해당 아이템 비활성화 + "품절" 배지, 주문하기 시 제외 안내 |
| 로딩 중 | 스켈레톤 UI |
| 에러 | 토스트 메시지 (CART_FULL 등) |

## 작성 규칙

| 규칙 | 설명 |
|---|---|
| 6단 구조 필수 | 메타블록 → 와이어프레임 → 화면 구성 → 화면 전환 → 유효성 검증 → 상태별 UI 순서로 각 화면 섹션 작성 |
| 메타블록 표 형식 | 화면ID·앱·접근권한·관련UC·호출API를 표로 정리 |
| 영역별 API 매핑 필수 | "이 데이터가 어디서 오는가" 명시 |
| 화면 전환에 레이어 팝업 포함 | 다른 화면 이동뿐 아니라 같은 화면 내 팝업·모달도 표에 넣고 `(화면 전환 아님)`으로 구분 |
| 상태별 UI 정의 | 빈 상태, 로딩, 에러 상태 포함 |
| 인터페이스 명세(⑮) 참조 | API 경로·응답 필드명 일치 |
| 검증규칙 복제 금지 | 유효성 검증 규칙 본문은 GWT(⑬)·인터페이스명세(⑮)에만 두고, DN에는 링크만 건다 |

## 작성 팁

| 팁 | 설명 |
|---|---|
| **API 응답 필드 = 화면 표시 항목** | 인터페이스 명세에 없는 필드가 필요하면 명세 보완 |
| **admin은 테이블 중심** | 목록(DataGrid) + 상세(Form) 패턴 반복 |
| **mobile은 카드/리스트 중심** | 스크롤·무한 로딩·스와이프 패턴 |
| **Figma 가이드 필요 시** | mobile 채널은 이 문서 → Figma 디자인 → 개발 순서 |
| **화면ID는 DQ에서 역추출** | 프로그램목록(⑳)이 먼저 확정되지 않았다면, 이 문서 작성 시점에 임시 SCR-ID를 부여하고 DQ 작성 시 정합성 검증 |
| **비개발자(기획자)가 이 문서만 봐도 되게** | 메타블록의 위키링크을 따라가면 DK/DL/DJ까지 추적되므로, 화면 단위 작업 시 이 문서를 시작점으로 삼는다 |
