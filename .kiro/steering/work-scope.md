# 작업 범위 기준

- 앞으로 수정 및 작성하는 모든 문서의 작업 범위는 **도메인 기준 "Order(주문)"** 이다.
- 다른 도메인(Promotion, Payment, Catalog 등) 문서는 Order와의 연동·참조 목적으로만 열람하며, 직접 수정하지 않는다. (수정이 필요하면 먼저 사용자에게 확인)
- 문서 작성 시 도출 근거 원칙:
  - 상위 산출물(착수 S0, 범위정의 S1)의 산출물을 근거로 작성한다.
  - 도메인정의서(DB), 정책서를 1차 근거로 사용한다.
  - 후행 산출물(EARS 등)이나 비공식 참고자료(도메인기능표 등)를 도출 근거로 역참조하지 않는다.
- 문서 패턴은 기존 확정 문서(Payment/Order S2·S3)의 형식·레벨을 따른다.
- **코드 구현 시에도 동일한 도출 근거 원칙을 적용한다**: 새 클래스명·메서드명·파일명·API 경로 등 식별자를 짓기 전에, 먼저 `docs/deliverables/S3-상세설계/DP-클래스설계/{domain}.md`(클래스/메서드 시그니처), `DL-인터페이스명세/{domain}.md`(API·DTO 필드명)에 해당 식별자가 이미 정의돼 있는지 검색한다.
  - 이미 정의돼 있으면 **그 이름을 그대로** 쓴다 (의미가 비슷해도 임의로 새 이름을 만들지 않는다).
  - 정의돼 있지 않으면(완전히 신규) 같은 문서에 있는 기존 네이밍 패턴과 일관되게 짓고, 그 사실(신규 생성임)을 명시한다.
  - 이 확인을 생략하고 추정으로 이름을 지었다가 1차 근거와 다른 것으로 드러나면, 발견 즉시 1차 근거 기준으로 정정한다.
