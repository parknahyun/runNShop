> 참고 — 대시보드는 그 셸 안에서 열리는 여러 탭 중 **첫 번째로 고정된 탭 하나**일 뿐이며, 이
> 문서는 그 탭의 화면 내용만 다룬다.
>
> **⑤ 화면정의서 하네스 표준양식**(`docs/x. 하네스/표준양식/05. 화면정의서 하네스 표준양식 v1 0.md`)
> 기준으로 작성한다 — 아래 "하네스 헤더" ~ "[AI-H14] 화면 상태 관리"가 그 표준양식이 요구하는
> 필수 섹션이고, 그 이후 "보강 설명"은 이 프로젝트(docs_ai) 자체 관례(기준 vs 실제 소스 비교,
> 소스 수정 필요 표시)를 얹은 추가 내용이다.
>
> **이 문서는 기준(spec)이다.** 원본 §3.5 API 매핑표 #6~11(`ADM-HOME` 6개 API)을 기준으로 이
> 화면이 어떻게 동작해야 하는지 먼저 정의하고, 현재 소스(`shell/Dashboard.tsx`)가 그 기준과
> 다른 부분은 명시한다. 이 앱이 아직 백엔드 미연동 Mock 단계임을 감안해 API 연동 자체는
> "소스 수정 필요"에 넣지 않되(다른 도메인 화면도 전부 Mock 데이터로 FE를 완성해두는 것이 이
> 코드베이스의 관례이므로), **Mock 데이터로라도 채워야 할 카드**는 포함한다.

## 보강 설명

### 개요
로그인 직후 첫 번째 고정 탭(📌, 닫기 불가)으로 열리는 요약 대시보드. 다른 탭과 마찬가지로
[00-AppShell.md](00-AppShell.md)의 TabContent 영역에 렌더링된다는 점만 다르고 화면 자체는
그냥 하나의 탭 콘텐츠다.

### 화면 구성

| 화면 | 화면유형 | 소스 |
|------|---------|------|
| 대시보드 | `dashboard` | `apps/runNshop-admin/src/shell/Dashboard.tsx` |

### 카드 구성 — 기준 vs 실제 소스

실제 `Dashboard.tsx`는 4개 카드만 구현(3열 그리드, `grid-template-columns: repeat(3, 1fr)` —
카드가 4개라 2번째 줄엔 회원 현황 카드 1개만 배치):

| 카드 | 아이콘 | 지표 | Mock 값 |
|---|---|---|---|
| 주문 현황 | 🛒 | 금일 주문 / 주문접수 / 배송중 / 배송완료 / 실패 | 47 / 12 / 15(ok) / 9 / 3(실패>0이면 danger) |
| 클레임 현황 | 📋 | 취소·반품·교환 × 접수·처리중·완료 (3x3 테이블) | 취소 5/2/18, 반품 3/4/12, 교환 1/1/8 (접수>0이면 warn, 완료는 ok) |
| 상품 현황 | 📦 | 판매중 / 품절 / 심사중 / 반려 | 1,247(ok) / 89(warn) / 15 / 3(danger) |
| 회원 현황 | 👥 | 금일 가입 / 전체 회원 | 23(ok) / 12,450 |

### 소스 수정 필요

아래 4개 카드가 원본 §3.5 API 계획에는 있으나 현재 없다. Mock 데이터로라도 추가한다.

| 추가할 카드 | 대응 원본 API | 내용(안) |
|---|---|---|
| 처리 필요 항목 | `GET /home/pending` | 승인 대기 심사/신청 건수 요약(상품 심사 대기, 입점 신청 대기, 운영자 신청 대기 등) |
| 주문·매출 추이 | `GET /home/trend?days=7` | 최근 7일 주문 건수·매출 추이 차트 |
| 시스템 알림 | `GET /home/alerts` | 배치 실패, Outbox·DLQ 적체 등 시스템 경고 목록 |
| 진행 중 이벤트 | `GET /home/events/active` | 현재 진행 중인 기획전/프로모션 목록 |

기존 "주문 현황"·"상품 현황" 카드는 각각 원본의 "홈 요약"·"판매 상품 현황" 개념을 이미 충족하는
것으로 보고 유지한다(카드명·지표 변경 불필요).

### 크로스 도메인 의존성
