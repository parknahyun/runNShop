# ② 정책서 — §3.13 섹션종류 관리 정책 (신설)

> 원본: `docs/2. 정책서/runNshop_policy_v1_2.md` 3장(상품 관리 정책)은 §3.12 전시 페이지 상태
> 정책까지만 있고, 그 앞 단계인 섹션종류(ADM-020-010)에 대한 정책 섹션이 없다.
> `docs/`는 백업으로 보존, 이 파일이 §3.13으로 추가되는 신설 섹션이다. §3.12와 같은 위치
> (3장 맨 끝, 4장 회원 관리 정책 앞)에 들어간다.
>
> 수정 배경: BE Task Spec(`TSK-DPL-SEC-001-BE`) 검증 시 "source_policy: 해당 정책 없음"이라고
> 되어 있었고 실제로 정책서에 "섹션" 관련 내용이 0건이라 그 시점엔 맞는 판단이었다. 하지만 섹션종류
> 화면(FE 검증, `docs_ai/README.md` 1차 검증)에서 확인된 HARD 규칙들(sectionCode/fieldKey 불변,
> 사용 중 섹션종류 폐기 차단)은 성격상 "운영 정책"에 해당하므로, §3.12(페이지 상태 정책)처럼
> 정식 정책 섹션으로 승격해두는 게 맞다 — 이후 다른 화면이 같은 섹션종류 데이터를 참조할 때
> Task Spec이 `source_policy: POL-DPL-SEC-*`로 인용할 수 있게 된다.

---

### 3.13 섹션종류·필드 관리 정책

| 항목 | 규칙 |
|------|------|
| sectionCode | 등록 후 수정 불가 (불변) — ERD `cat_display_section_type.section_code` UNIQUE와 결합 |
| fieldKey | 필드 등록 후 수정 불가 (불변) — 섹션종류 내 UNIQUE (ERD `uk_section_field`) |
| 상태 | `ACTIVE` / `INACTIVE` / `DEPRECATED`. 물리적 삭제 없음, 폐기는 `DEPRECATED` 전환만 허용
       (§19.3 "전시(Display)" 행 참조 — `is_deleted` 표준 컬럼과 병행) |
| 사용 중 섹션종류 폐기 | 템플릿(`cat_display_area`)에서 참조 중인 섹션종류는 `DEPRECATED` 전환 기본 차단(409).
                        `force=true` 파라미터를 명시해야만 강제 허용 |
| 필드 타입 | 11종 지원(이미지/상품/텍스트/링크/색상/숫자/날짜시간/선택/이미지배열/상품배열/텍스트배열).
             타입별 기본값 UI가 다름 (숫자→number input, 선택→공통코드 그룹 select, 그 외→text) |
| "선택" 타입 기본값 | 이 화면 자체 데이터가 아니라 시스템 > 공통코드(Config 도메인) 그룹 목록을 그대로 참조.
                     섹션종류 도메인에서 별도 값 목록을 만들지 않는다 |

- 필드 추가/편집/삭제/순서변경은 화면에서 로컬로 처리하고, "저장" 클릭 시에만 서버에 일괄 반영한다
  (필드 단위 즉시 API 호출 금지)
- 위 "사용 중 섹션종류 폐기" 판단은 Catalog 도메인 내부에서 하되, 조회 대상(`cat_display_area`)이
  템플릿 소유 데이터이므로 도메인 간 직접 테이블 접근 금지 원칙(도메인정의서 §1 "데이터 소유권"
  원칙, `docs_ai/03-도메인/Catalog-Display.md`)을 지켜 내부 API/쿼리 메서드로 확인한다
