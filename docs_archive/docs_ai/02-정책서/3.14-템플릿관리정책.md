### 3.14 템플릿 관리 정책

| 항목 | 규칙 |
|------|------|
| 사용 중 템플릿 수정/삭제 제약 | `usedPageCount > 0 && status = 'ACTIVE'`인 템플릿은 기본정보·영역
  구성 **수정(PUT)과 삭제(DELETE) 모두 금지**. 삭제만이 아니라 수정 자체를 막는다
  (`decision_log` 2026-06-30, "운영 안정성 확보" 목적) |
| 제약 해제 방법 | 상태를 `INACTIVE`로 먼저 전환해야 수정 가능해짐 |
| 복사 원칙 | 페이지는 템플릿을 **복사**해서 생성 — 템플릿을 나중에 수정해도 이미 생성된 페이지에는
  전파되지 않음. 그래서 §3.13의 섹션종류와 달리 "사용 중" 여부와 무관하게 프론트 프로토타입에는
  수정 제약이 느슨하게 구현돼 있었음(`SectionsTab.tsx`의 `hasActivePages = false` 하드코딩,
  주석: "제약 해제: 페이지는 템플릿을 복사하므로 항상 수정 가능") — **이는 위 표의 정책과
  다르다.** 본개발 시 이 하드코딩을 실제 `usedPageCount>0 && ACTIVE` 체크로 교체해야 한다 |
| 상태 | `ACTIVE` / `INACTIVE` / `DEPRECATED`. 물리적 삭제 없음, 폐기는 `DEPRECATED` 전환
  (§19.3 "전시(Display)" 행과 동일 병행 패턴 — `is_deleted`+`status`) |
| 템플릿 유형 | `HOME`/`CATEGORY`/`EXHIBITION`/`EVENT` 4종 (ERD:977-978, "2026-07-06 크로스체크로
  HOME 누락 보완, 프로토타입 코드와 일치") |

⚠ **미해결 이슈 (결정 필요, 임시 반영)**: ERD의 `cat_display_area`(area_code, area_type
`FIXED`/`FLEXIBLE`) + `cat_display_content` 구조가 현재 화면 Mock의 `TemplateSection`
(sectionName/sectionType/sortOrder 3필드)보다 세분화돼 있어 구조가 다르다. "ERD로 통일" vs
"ERD를 Mock 수준으로 단순화" 결정 전까지, 이 정책 문서와 화면정의서는 **현재 프로토타입 Mock
기준**으로 작성된 임시 버전이다 (원본 하네스 샘플에 이미 같은 경고가 있었음 — 새로 발견한 문제
아니라 기존에 알려진 미결정 사항을 옮겨온 것).
