# ② 정책서 — §19.3 도메인별 소프트 삭제 적용 기준에 Display 추가

> 원본: `docs/2. 정책서/runNshop_policy_v1_2.md` §19.3 (line 2167-2176).
> `docs/`는 백업으로 보존, 이 파일은 표에 빠진 행 1개만 추가하는 보완본이다.
>
> 수정 배경: BE Task Spec 검증 중 "Display 도메인은 is_deleted 플래그 대신 status=DEPRECATED
> 전환을 쓴다"고 잘못 이해했던 적이 있었으나, ERD 확인 결과 `cat_display_section_type`은
> `is_deleted`/`deleted_at`/`deleted_by`(§19.2 표준 컬럼)와 `status` 컬럼을 **둘 다 가지고 있다**
> (ERD:1105-1128). 이는 §19.3에 이미 있는 "상품 | 판매종료·강제 삭제 | `DISCONTINUED` 상태와
> **병행**" 패턴과 동일한 것 — 새 패턴이 아니라 기존 §19.3 표에 Display 행이 빠진 것뿐이었다.

## §19.3 표 추가 행

| 도메인 | 삭제 트리거 | 비고 |
|--------|-----------|------|
| 전시(Display) | 섹션종류·템플릿·페이지 폐기 | `DEPRECATED`/`INACTIVE` 상태와 병행 (상품 도메인의 `DISCONTINUED` 병행 패턴과 동일) |

## 연동

같은 "병행" 표현은 `docs_ai/09-task-spec/TSK-DPL-SEC-001-BE-v2.md`의 HC-DPL-SEC-003 항목에도
반영돼 있다 (TC-ID 체계는 도입하지 않기로 결정 — 이 문서를 직접 인용).
