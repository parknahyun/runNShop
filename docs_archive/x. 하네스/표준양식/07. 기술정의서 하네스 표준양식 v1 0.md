# ⑦ 기술 정의서 (기술스택·아키텍처) — Harness 표준양식

- **매핑 Harness**: Output Schema Harness (원천)
- **원천 작성 항목**: 코드 생성 규칙, 프로토타입 단계 제약, 공통 기술 제약, 앱별 UI 패턴
- **AI-H**: AI-H19 (코드 생성 규칙), AI-H20 (프로토타입), AI-H21 (기술 제약), AI-H22 (UI 패턴)
- **참고**: 프로젝트 전체에 1개 작성 (도메인별 아님). ⑧ API정의서 Output Schema의 공통 기반.

## AI 보강 섹션

```
[AI-H19] 코드 생성 규칙 (레이어·패턴)         ← Output Schema Harness (원천)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
code_generation_rules:
  backend:
    layer_structure:
      - Controller: ""
      - Service: ""
      - Repository: ""
      - DTO: ""
    naming:
      controller: "{Domain}{Role}Controller"
      service: "{Domain}Service"
      repository: "{Domain}Repository"
      dto: "{Action}{Domain}Request/Response"
    package: "com.{project}.{domain}.{layer}"

  frontend:
    apps:
      - name: {app-name}
        framework: ""
        styling: ""
        structure: ""

[AI-H20] 프로토타입 단계 제약                  ← Output Schema Harness (원천)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
prototype_rules:
  - "Controller → MockLoader → JSON 반환 (Service 로직 미구현)"
  - "POST/PUT/DELETE: API 호출은 하되, 실제 저장 없이 성공 응답"
  - "Mock 파일 위치: resources/mock/{경로}/"
  - "Mock 파일명: {규칙}"
  - "화면 간 네비게이션은 모두 정상 동작"
  - "유효성 검증은 실제와 동일하게 구현"

production_rules:
  - "MockLoader → 실제 Service 교체"
  - "Service → Repository → {ORM} Mapper"
  - "@Transactional 위치: Service 레벨"
  - "이벤트 발행: Outbox 테이블 INSERT (같은 트랜잭션)"

[AI-H21] 공통 기술 제약 (프레임워크 레벨)      ← Output Schema Harness (원천)

    applies_to: "전체"

  - id: TC-002
    rule: "도메인 간 직접 테이블 접근 금지"
    applies_to: "Repository 레이어"
    wrong_pattern: ""

  - id: TC-003
    rule: "복제 테이블은 READ ONLY (INSERT/UPDATE 금지)"
    applies_to: "Repository 레이어"

  # 추가 제약은 TC-004, TC-005 ... 순서로 추가
```

## 작성 기준

| 항목 | 기준 |
|------|------|
| 코드 생성 규칙 | AI가 파일 생성 시 네이밍·위치·패턴을 강제하는 규칙 |
| prototype_rules | 프로토타입 단계에서 AI가 넘지 않을 경계 (실 DB 접근 금지 등) |
| technical_constraints | 전체 도메인에 공통 적용되는 제약 (wrong_pattern 포함 권장) |
| ui_patterns | 앱별 레이아웃·팝업 방식 (AI가 화면 코드 생성 시 결정 근거) |

## 하위 문서 역참조 경로

```
기술정의서 (프로젝트 공통)
  └─ 코드 생성 규칙 → ⑧ API정의서 Output Schema(expected_classes)에서 구체화
  └─ TC-* 제약     → ⑧ API정의서 Domain Constraint HARD에서 참조
  └─ prototype_rules → ⑧-2 Data Contract wrong_patterns과 연계
```
