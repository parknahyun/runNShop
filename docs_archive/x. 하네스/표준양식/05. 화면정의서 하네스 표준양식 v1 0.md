# ⑤ 화면 정의서 — Harness 표준양식

- **매핑 Harness**: Requirements Validation Harness (UI 측 원천)
- **원천 작성 항목**: 컴포넌트-API 매핑, 프론트 유효성 검증, 화면 상태 관리
- **AI-H**: AI-H12 (컴포넌트-API 매핑), AI-H13 (유효성 검증), AI-H14 (상태 관리)
- **참고**: ⑧ API정의서 Request/Response 필드의 입력 원천

---

```
|---|------|------|------|------|

• 버튼 A → {화면ID} ({화면명})

```

## 작성 기준

| 항목 | 기준 |
|------|------|
| 컴포넌트-API 매핑 | 화면의 모든 API 호출 시점을 빠짐없이 정의 (AI 코드 생성의 직접 근거) |
| 유효성 검증 | 프론트 검증 전용 (백엔드 검증과 분리. 백엔드는 API정의서에서 정의) |
| refresh_trigger | API 호출 후 상태 갱신이 필요한 모든 사용자 액션 포함 |
| optimistic | 낙관적 업데이트 적용 시 명시 → AI가 상태 롤백 로직도 함께 생성 |
| skeleton | 첫 로딩에 스켈레톤 UI가 필요한 API만 true |

## 하위 문서 역참조 경로

```
{APP}-{SEQ}
  └─ 호출 API   → ⑧ API정의서에서 Request/Response 필드로 전개
  └─ 검증 규칙  → ⑧ API정의서 Requirements Validation에서 참조
  └─ 화면 전환  → ④ 업무흐름 Step 흐름과 일치해야 함
```
