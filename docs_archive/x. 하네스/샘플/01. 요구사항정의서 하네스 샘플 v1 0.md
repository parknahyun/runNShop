# ① 요구사항 정의서 — Harness 샘플

> **샘플 도메인**: Order / **요구사항**: FR-ORD-001 주문 생성

---

## 기본 섹션

```
요구사항 ID    : FR-ORD-001
요구사항명     : 고객 주문 생성
분류           : 기능(FR)
우선순위       : P1(Must)
도메인         : Order
상태           : CONFIRMED
변경 이력      : 2026-07-03 최초 작성
요청 부서      : 커머스사업부
관련 화면      : CUS-040 (주문서), CUS-041 (결제)
관련 업무흐름  : BPM-ORD-001 (주문 생성 플로우)

[설명]
고객이 장바구니에서 상품을 선택하여 주문을 생성한다.
쿠폰 및 포인트를 적용할 수 있으며, 배송지를 선택하고 최종 결제 금액을 확인 후 결제 화면으로 이동한다.
입점사별로 주문이 분리되어 관리된다 (1개 플랫폼 주문 → N개 입점사 주문).

[상세 규칙]
• 장바구니에서 선택한 상품만 주문 대상이 된다
• 입점사별로 주문이 자동 분리된다
• 쿠폰은 1회 사용 후 사용 처리된다
• 포인트는 보유 잔액 이하만 사용 가능하다
• 주문 생성 시점에 재고를 예약(차감)한다
• 주문 생성 후 30분 내 결제 미완료 시 자동 취소된다

[수용 기준 - Acceptance Criteria]
AC-1: 장바구니에서 선택한 상품이 포함된 주문서가 생성된다
AC-2: 쿠폰·포인트 적용 시 최종 결제 금액이 정확히 계산된다
AC-3: 재고 부족 상품이 포함된 경우 주문이 실패하고 사유가 표시된다
AC-4: 만료된 쿠폰 적용 시 주문이 실패하고 사유가 표시된다
AC-5: 주문 생성 후 결제 화면(CUS-041)으로 이동한다

[비기능 요구사항]
• 성능: 주문 생성 API p95 응답시간 1,000ms 이하
• 보안: 로그인한 고객만 접근 가능 (JWT 인증)
• 데이터: 주문 데이터 7년 보존 (감사 로그 포함)
```
