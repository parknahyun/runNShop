## 기본 섹션

```
문서명         : runNshop 기술 스택 정의서
프로젝트       : runNshop (러닝 전문 버티컬 쇼핑몰)
버전           : v1.0
상태           : CONFIRMED

[기술 스택]
| 항목 | 기술 | 버전 |
|------|------|------|
| 백엔드 | Kotlin + Spring Boot | 3.3 |
| 프론트 (고객앱) | Next.js (App Router) | 14 |
| 프론트 (어드민·파트너) | Next.js (CSR SPA) | 15 |
| 언어 (프론트) | TypeScript | 5.x |
| DB | PostgreSQL | 16 |
| ORM | MyBatis | 3.x |
| 캐시 | Redis | 7.x |
| 검색 | Elasticsearch | 8.x |
| 메시지 | Kafka (Outbox Pattern) | 3.x |
| 인프라 | Docker Compose (개발) / k8s (운영) | |

[프로젝트 구조]
runNshop/
├── backend/           # Kotlin Spring Boot (모듈러 모놀리스)
│   └── src/main/kotlin/com/runnshop/
│       ├── order/     # Order 도메인
│       │   ├── controller/
│       │   ├── service/
│       │   ├── repository/
│       │   └── dto/
│       └── ...
├── runNshop-mobile/   # Next.js 14 App Router (고객앱)
│   └── app/{route}/page.tsx + components/
├── runNshop-admin/    # Next.js 15 CSR SPA (어드민)
│   └── src/{domain}/{Feature}Tab.tsx
└── runNshop-partner/  # Next.js 15 CSR SPA (파트너BO)
    └── src/{domain}/{Feature}Tab.tsx

[실행 환경]
| 앱 | 포트 | 실행 명령 |
|----|------|---------|
| Backend | 8080 | ./gradlew bootRun |
| runNshop-mobile | 3000 | npm run dev |
| runNshop-admin | 3001 | npm run dev |
| runNshop-partner | 3002 | npm run dev |
| PostgreSQL | 5432 | docker compose up db |
| Redis | 6379 | docker compose up redis |
```

```
[AI-H19] 코드 생성 규칙 (레이어·패턴)         ← Output Schema Harness (원천)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
code_generation_rules:
  backend:
    layer_structure:
      - Controller: "API 진입점, 요청 검증, 응답 변환 (비즈니스 로직 금지)"
      - Service: "비즈니스 로직, @Transactional 관리"
      - Repository: "MyBatis Mapper 인터페이스 + XML (SELECT/INSERT/UPDATE)"
      - DTO: "Request/Response 데이터 클래스 (data class in Kotlin)"
    naming:
      controller: "{Domain}{Role}Controller"   # CustomerOrderController, AdminOrderController
      service: "{Domain}Service"               # OrderService
      repository: "{Domain}Repository"         # OrderRepository
      dto: "{Action}{Domain}Request/Response"  # CreateOrderRequest, CreateOrderResponse
    package: "com.runnshop.{domain}.{layer}"  # com.runnshop.order.service
    mapper_xml: "resources/mapper/{domain}/{Entity}Mapper.xml"

  frontend:
    apps:
      - name: runNshop-mobile
        framework: "Next.js 14 (App Router)"
        styling: "Tailwind CSS"
        structure: "app/{route}/page.tsx + app/{route}/components/"
        state: "React Query (서버 상태) + useState (로컬 상태)"
      - name: runNshop-admin
        framework: "Next.js 15 (CSR SPA, pages router)"
        styling: "순수 CSS (globals.css, BEM 방법론)"
        structure: "src/{domain}/{Feature}Tab.tsx"
        state: "React useState + useEffect (서버 상태 직접 관리)"
      - name: runNshop-partner
        framework: "Next.js 15 (CSR SPA, pages router)"

        structure: "src/{domain}/{Feature}Tab.tsx"
        state: "React useState + useEffect"

[AI-H20] 프로토타입 단계 제약                  ← Output Schema Harness (원천)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
prototype_rules:
  - "Controller → MockLoader → JSON 파일 반환 (Service 클래스 미생성)"
  - "POST/PUT/DELETE: API 호출은 하되, DB 저장 없이 200/201 성공 응답"
  - "Mock 파일 위치: backend/src/main/resources/mock/{v1|admin|partner}/"
  - "Mock 파일명: {domain}__{METHOD}_{path_snake}.json  예: order__POST_orders.json"
  - "화면 간 네비게이션(페이지 이동, 팝업 열기)은 모두 정상 동작"
  - "유효성 검증 규칙(필수값, 타입, 범위)은 실제와 동일하게 구현"
  - "로딩·오류 상태(스켈레톤, 에러 메시지)는 실제와 동일하게 구현"

production_rules:
  - "MockLoader → 실제 OrderService (Service 로직 구현)"
  - "Service → OrderRepository → MyBatis Mapper XML"
  - "@Transactional: Service 메서드 레벨에만 적용"
  - "이벤트 발행: 같은 @Transactional 내 ord_outbox 테이블 INSERT"
  - "외부 API 호출: @Transactional 밖에서 완료 후 트랜잭션 진입"

[AI-H21] 공통 기술 제약 (프레임워크 레벨)      ← Output Schema Harness (원천)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
technical_constraints:
  - id: TC-001
    rule: "물리적 DELETE 전면 금지 (is_deleted = TRUE UPDATE만 허용)"

    wrong_pattern: "DELETE FROM {table} WHERE id = ?"

  - id: TC-002
    rule: "도메인 간 직접 테이블 접근 금지 (PublicApi 또는 복제 테이블만)"
    applies_to: "Repository 레이어"
    wrong_pattern: "OrderRepository에서 cat_sku_stock 테이블 JOIN 또는 직접 UPDATE"

  - id: TC-003
    rule: "복제 테이블은 READ ONLY (INSERT/UPDATE/DELETE 금지)"
    applies_to: "Repository 레이어"
    wrong_pattern: "UPDATE mbr_member_replica SET ..."

  - id: TC-004
    rule: "프론트 데이터 하드코딩 금지 (모든 데이터는 API 응답 기반)"
    applies_to: "Frontend 전체"
    wrong_pattern: "const categories = ['러닝화', '의류', ...] // 하드코딩"

  - id: TC-005
    rule: "에러 메시지 다국어 키 사용 (문자열 하드코딩 금지)"
    applies_to: "Backend 에러 응답"
    wrong_pattern: "throw RuntimeException('재고가 부족합니다') // 한국어 하드코딩"

  - id: TC-006
    rule: "동일 로직 3개 앱에서 사용 시 → Controller 메서드 1개에 3개 URL 매핑"

  - id: TC-007
    rule: "Outbox INSERT는 반드시 @Transactional 내에서 실행"
    applies_to: "Service 레이어 (이벤트 발행 포함)"
    wrong_pattern: "주문 INSERT 커밋 후 별도 메서드에서 Outbox INSERT"
```
