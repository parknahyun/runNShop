# ⑤ 화면 정의서 — Harness 샘플

> **샘플 도메인**: Order / **화면**: CUS-040 주문서 화면

---

## 기본 섹션

```
화면 ID        : CUS-040
화면명         : 주문서
앱             : 고객웹 (runNshop-mobile, Next.js 14 App Router)
화면 유형      : 등록
접근 권한      : 로그인 고객 전용

[레이아웃]
Header (로고, 뒤로가기)
├─ 배송지 섹션
│   ├─ 기본 배송지 (이름, 전화, 주소)
│   └─ [배송지 변경] 버튼 → 배송지 팝업
├─ 주문 상품 섹션
│   └─ 입점사별 그룹 (입점사명, 상품 목록, 소계)
├─ 쿠폰·포인트 섹션
│   ├─ [쿠폰 선택] 드롭다운
│   └─ 포인트 입력 (보유 포인트 표시)
├─ 최종 결제 금액 섹션
│   ├─ 상품 합계
│   ├─ 배송비
│   ├─ 쿠폰 할인
│   ├─ 포인트 사용
│   └─ **최종 결제 금액**
└─ [결제하기] 버튼 (고정 하단)

[UI 요소]
| # | 요소 | 타입 | 동작 | 비고 |
|---|------|------|------|------|
| 1 | 배송지 변경 버튼 | Button | onClick → 배송지 팝업 오픈 | |
| 2 | 쿠폰 선택 드롭다운 | Select | onChange → 할인 금액 재계산 | 보유 쿠폰 목록 |
| 3 | 포인트 입력 | Input | onChange (debounce 500ms) → 할인 금액 재계산 | 숫자만, 보유 포인트 이하 |
| 4 | 전액 사용 버튼 | Button | onClick → 포인트 input에 보유 전액 세팅 | |
| 5 | 결제하기 버튼 | Button | onClick → POST /api/v1/orders | 로딩 스피너 표시 |

[화면 전환]
• 뒤로가기 → CUS-030 (장바구니)
• 결제하기 성공 → CUS-041 (결제)
• 결제하기 실패 (재고 부족) → 모달 팝업 표시 후 장바구니로 이동
```

## AI 보강 섹션

```
[AI-H12] 컴포넌트-API 매핑                   ← Requirements Validation Harness (원천)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
| UI 요소/영역 | 호출 API | 시점 | 비고 |
|-------------|---------|------|------|
| 화면 진입 | GET /api/v1/orders/sheet?cartItemIds={ids} | onMount | 배송지·상품·기본 금액 로드 |
| 쿠폰 선택 드롭다운 오픈 | GET /api/v1/promotions/coupons/available?subtotal={n} | onOpen | 사용 가능 쿠폰 목록 |
| 쿠폰 선택 변경 | PUT /api/v1/orders/sheet/discount | onChange | 할인 금액 재계산 (서버) |
| 포인트 입력 | PUT /api/v1/orders/sheet/discount | onChange (debounce 500ms) | 할인 금액 재계산 (서버) |
| 배송지 변경 완료 | PUT /api/v1/orders/sheet/delivery | onChange (팝업 확인) | 배송비 재계산 (도서산간 여부) |
| 결제하기 버튼 | POST /api/v1/orders | onClick | 주문 생성 최종 확정 |

[AI-H13] 유효성 검증 규칙 (프론트)           ← Requirements Validation Harness (원천)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
| 필드/동작 | 검증 규칙 | 메시지 | 시점 |
|----------|----------|--------|------|
| 포인트 입력 | 숫자만, 0 이상 정수 | "숫자만 입력 가능합니다" | onChange |
| 포인트 입력 | 보유 포인트 이하 | "보유 포인트({n}P)를 초과할 수 없습니다" | onChange (debounce) |
| 결제하기 | 배송지 선택 필수 | "배송지를 선택해주세요" | onClick |
| 결제하기 | 재고 부족 응답 (서버) | "'{상품명}'의 재고가 부족합니다. 장바구니를 확인해주세요." | onClick 후 응답 처리 |

[AI-H14] 화면 상태 관리                       ← Requirements Validation Harness (원천)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
states:
  - name: orderSheet
    source: GET /api/v1/orders/sheet
    refresh_trigger: ["배송지 변경", "쿠폰 변경", "포인트 입력"]
  - name: availableCoupons
    source: GET /api/v1/promotions/coupons/available
    refresh_trigger: ["화면 진입"]
  - name: discountSummary
    source: PUT /api/v1/orders/sheet/discount
    refresh_trigger: ["쿠폰 선택 변경", "포인트 입력 (debounce 500ms)"]
  - name: finalAmount
    derived: "subtotal - couponDiscount - pointAmount + shippingFee"

loading_states:
  - api: GET /api/v1/orders/sheet
    skeleton: true                  # 초기 로딩 스켈레톤
  - api: POST /api/v1/orders
    spinner: true                   # 결제하기 버튼 로딩 스피너 (중복 클릭 방지)
  - api: PUT /api/v1/orders/sheet/discount
    optimistic: false               # 서버 계산값 수신 후 반영 (낙관적 업데이트 X)
```
