## 2. 현재 가능한 것 vs 범용화 후 가능한 것

### 2.1 지금 당장 가능한 것 (현재 자산 그대로)

| 산출물 | 방법 | 품질 |
|--------|------|------|
| **정책서 초안** | runNshop 정책서를 골격으로 → RFP 업종·규칙으로 치환 | 70~80% |
| **BC 초안** | 12개 도메인 구조를 참조 → 신규 프로젝트 도메인에 맞게 조정 | 60~70% |
| **ERD 초안** | 107테이블 중 해당 도메인만 추출 → 컬럼 조정 | 50~60% |
| **화면정의서 초안** | 158화면 중 유사 화면 추출 → 명칭·필드 치환 | 60~70% |
| **프로젝트 구조** | Scaffolding 가이드로 모노레포 즉시 생성 | 90% |
| **Steering 파일** | 공통 규칙은 그대로, 프로젝트명만 치환 | 80% |

### 2.2 범용화 완료 후 가능한 것 (Phase 1~2 목표 달성 시)

| 산출물 | 방법 | 품질 |
|--------|------|------|
| **정책서** | 템플릿 변수 + RFP 키워드 매핑 → AI 자동 생성 | 85~90% |
| **화면정의서** | 화면유형 카탈로그 + RFP 기능목록 → 자동 조합 | 80~85% |
| **동작 프로토타입** | 코드 템플릿 + 화면정의서 → 2주 내 전체 화면 | 80% |
| **API 목록** | 화면정의서에서 자동 도출 | 90% |

## 3. 실제 진행 시나리오 (RFP 투입 → 산출물)

```
입력: RFP + 제안서 (텍스트 정리본)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Step 1 (30분, AI)
    RFP에서 추출:
    → 업종·업무 범위·주요 기능 목록·비기능 요건·일정

Step 2 (2~4시간, AI)
    runNshop 정책서 골격 복사 → 프로젝트에 맞게 치환
    → 해당 없는 챕터 제거 (예: 러닝 전문 → 의류 전문이면 사이즈 정책 추가)
    → 산출물: {프로젝트명}_policy_v0_1.md

Step 3 (2~4시간, AI)
    정책서 기반으로 BC·아키텍처 초안
    → runNshop BC 12개에서 해당 도메인만 추출·재조합
    → 산출물: {프로젝트명}_bounded_context_v0_1.md

Step 4 (4~8시간, AI)
    화면정의서 초안
    → runNshop 158화면에서 유사 화면 매핑
    → RFP 기능 목록과 1:1 대응
    → 산출물: {프로젝트명}_screen_definition_v0_1.md

Step 5 (1~2일, AI + Kiro)
    프로토타입 생성
    → Scaffolding으로 프로젝트 구조 생성
    → 코드 템플릿으로 화면 구현
    → Mock API 연결
    → 산출물: 동작하는 프로토타입

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
총 소요: 3~5일 (1인 + AI 기준)
```

## 5. 전제 조건과 한계

### 5.1 잘 되는 경우 (유사도 높음)

- RFP가 **e커머스 / 플랫폼 / 어드민 / 입점사 구조**일 때
- 주문·상품·결제·배송·정산·회원 도메인이 포함될 때
- 어드민 + 고객웹 + 입점사(파트너) 3앱 구조일 때
- B2C 또는 B2B2C 모델일 때

### 5.2 추가 작업이 필요한 경우 (유사도 낮음)

| 차이점 | 추가 작업 | 추정 공수 |
|--------|---------|---------|
| **업종 특화 도메인** (의료, 물류, 교육 등) | 해당 정책 신규 작성 | +2~3일 |
| **앱 유형 차이** (B2B only, SaaS, 구독형) | 화면 패턴 재설계 | +3~5일 |
| **기술 스택 차이** (Vue, Flutter 등) | Steering·코드 템플릿 재작성 | +1~2주 |
| **규모 차이** (마이크로 vs 대규모) | 아키텍처 재설계 | +1주 |

### 5.3 재활용 불가 영역

```
재활용 불가 (신규 작성 필수)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
• 업종 고유 비즈니스 규칙 (예: 의료법 규제, 금융 컴플라이언스)
• 외부 연동 명세 (PG사, 물류사, API가 프로젝트마다 다름)
• UI 디자인 (브랜딩, 컬러, 폰트)
• 비기능 요건 중 인프라 사양 (트래픽 규모, SLA)
```
