# 3TOP 2본부 AI활용 개발공정 가이드 슬라이드 (4장)

---

## 슬라이드 1: 왜 만드는가?

**제목: AI 에이전트와 협업하는 방법론을 도입하여 개발 생산성을 향상한다.**

```
현재 문제
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
• 유사업무인데 매번 처음부터 설계.구현 → 프로젝트당 24~40주
• 현업이 결정할 근거(화면·데이터)가 없음 → 의사결정 지연·요건변경
• 화면기획서와 구현물의 불일치 → 기획대로 안 만들어짐 (재작업)
• 경험이 사람 머릿속에만 있음 → 사람 떠나면 소멸

해결 방향
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
• AI 에이전트 + 축적된 자산으로 프로젝트 진행
• 프로토타입을 먼저 보여주고 → "맞나요?" (선택결정)
• 자산이 있으면 2~3주 내 전체 화면 프로토타입 가능
• 프로젝트당 18~28주로 단축
```

---

## 슬라이드 2: 어떻게 진행되는가

**제목: AI 와 협업하여 선택지를 제안하고, 현업은 결정한다.**

```
Phase A: 프로토타입 (1~2주, AI 주도)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
자산(초안+템플릿)을 신규 프로젝트에 맞게 커스터마이징
→ AI가 전체 화면 프로토타입 생성
→ 산출물: 동작하는 프로토타입 (Mock 기반)

• 활용 자산: 설계 템플릿 5종 + Scaffolding + Steering + 코드 템플릿
• 역할: AI가 생성, 사람은 확인·확정
• 품질: 88% (검증된 자산 기반, 보완 1~2회로 완성)

Phase B: 요구사항 확정 (2~4주, 현업 주도)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
프로토타입을 현업에게 시연
→ "맞나/아닌가" 피드백 수집 → 즉시 수정 → 재시연
→ 산출물: 확정 요구사항 정의서

• 진행: 3회 시연 (워크쓰루 → 세부조정 → 최종확인)
• 역할: 현업이 화면 보고 결정, AI가 즉시 반영
• 핵심: "문서 읽고 결정" → "화면 보고 결정"으로 전환

Phase C: 설계 확정 (1~2주, AI 주도)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
확정 요구사항 기반 설계 문서 보완·확정
→ 크로스체크 + API 명세 완성
→ 산출물: 확정 설계 + API 명세

• 진행: 변경 반영 → 크로스체크 5회 자동 실행 → API 명세 완성
• 역할: AI가 검증·생성, 사람은 불일치 방향 결정
• 품질: 95% (크로스체크로 정합성 보장)

Phase D: 실구현 (프로젝트 규모에 따라, 팀 주도)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Mock → 실DB·PG·외부 연동 → 테스트 → 오픈
→ 산출물: 운영 가능한 시스템

• 핵심: 프로토타입 = 코드베이스 (처음부터 다시 만들 필요 없음)
• 전환: Service 레이어만 Mock → 실제 로직 교체
• 역할: 팀이 실구현, AI가 코드 생성 보조 + 테스트 자동화
```

```
*관리 방법론에 AI-DLC 공정과 AI 협업사항 표기
```

## 슬라이드 3: 어떤 효과가 나는가

**제목: AI와 협업으로 의사결정은 빨라지고 재작업은 줄어, 일정이 단축된다**

```
                        전통 방식           AI-DLC
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
요구사항 확정       4~8주              2~4주
                      (문서 기반 회의)     (화면 보면서)

  • 전통: 요구사항 정의서 작성 → 회의 → 수정 → 재회의 (3~5회 반복)
  • AI-DLC: 프로토타입 시연 → "이거 맞아/아니야" → 즉시 수정 → 재시연
  • 효과: 현업이 결정할 "근거 데이터"가 화면으로 제공되어 결정 속도 2배 향상

현업 이해도           낮음               높음
                      (문서 읽기)        (화면 직접 조작)

  • 전통: 50페이지 문서 → 현업 "다 읽었는데 감이 안 와요"
  • AI-DLC: 동작하는 화면 → 현업 "아, 여기 이거 바꿔주세요"
  • 효과: 요건 변경률 50% 감소 (초기에 정확히 확인하므로 후반 변경 최소화)

설계-구현 갭          큼                 없음
                      (설계 따로 구현 따로) (프로토타입 = 코드베이스)

  • 전통: 설계서대로 안 만들어짐 → 기획자/개발자 갈등 → 재작업
  • AI-DLC: 프로토타입 자체가 코드 → 실구현 시 Service만 교체
  • 효과: 재작업 비용 제거, 설계 문서와 코드가 항상 동기화 상태

전체 일정     16~24주            30% 단축

  • 전통: 설계 4~8주 + 구현 8~12주 + 테스트 4주 (순차 진행)
  • AI-DLC: 설계+프로토타입 동시 1~2주 → 요건확정 2~4주 → 실구현
  • 효과: 설계/구현 병행 + 재작업 제거로 전체 30% 이상 단축

산출물 정합성         수동 검증           자동 크로스체크
                      (사람이 문서 비교)  (AI가 5회 자동 검증)

  • 전통: 정책서·ERD·화면정의서 각각 따로 관리 → 불일치 발견 못함
  • AI-DLC: AI가 문서 간 크로스체크 자동 실행 → 불일치 즉시 발견·수정
  • 효과: 설계 품질 95% 보장, 통합 테스트 단계 결함 대폭 감소

의사결정 지연         지속               해소
                      (결정 데이터 없음)  (선택지 제시 → 확인만)

  • 전통: "어떻게 할까요?" 질문 → 현업 "검토 후 알려드릴게요" → 2주 대기
  • AI-DLC: "A안/B안 화면 보세요" → 현업 "B로 갑시다" → 당일 확정
  • 효과: 의사결정 사이클 2주 → 1~2일로 단축

재사용성              매번 처음부터        초안 + 템플릿 재활용

  • 전통: 프로젝트 종료 → 산출물 아카이브 → 다음 프로젝트에서 참고만
  • AI-DLC: 설계 템플릿 + 코드 템플릿 → 변수 치환으로 즉시 재활용
  • 효과: 2번째 프로젝트부터 초기 산출물 3~5일 내 생성 (vs 8~14주)

인력 의존도           높음               낮음
                      (경험자 부재 시 중단) (자산에 경험 축적)

  • 전통: 핵심 인력 이탈 → 설계 의도 소실 → 프로젝트 지연·품질 저하
  • AI-DLC: 정책·설계·패턴이 자산으로 축적 → 누가 해도 동일 품질
  • 효과: 인수인계 비용 최소화, 신규 투입 인력도 즉시 생산 가능
                      (경험자 부재 시 중단) (자산에 경험 축적)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

## 슬라이드 4: 무엇이 필요한가?

**제목: AI와 협업이 가능한 재사용 가능한 자산이 필요하다.**

```
자산 현황 (현재 → 목표)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
설계 초안 5종        ✅ 작성됨 → ⬜ 범용 템플릿 추출
Scaffolding 가이드   ✅ 작성됨 → ⬜ 변수화 (프로젝트명 치환)
Steering 파일       ✅ 작성됨 → ⬜ 공통/프로젝트별 분리
코드 템플릿          🔄 구현중 → ⬜ 전체 화면 완성 + 템플릿 추출
AI 코딩 가이드       ⬜ 없음  → ⬜ 주요 모듈 구현하며 도출

현재 상태: 자산은 "작성됨"이지 "재사용 가능"이 아님
→ 목표: 자산을 재사용 가능한 형태로 만드는 것
```

```
진행 일정 (12주)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Phase 1 (1~4주)
    • 프로토타입 전체 화면 완성
    • Scaffolding·Steering 범용화
    • AI 코딩 가이드 초안

Phase 2 (5~7주)
    • API 정의서 작성
    • 산출물 보완·정제 (초안 → 범용 템플릿 추출)
    • 설계 문서 ↔ 프로토타입 크로스체크

Phase 3 (8~12주)
    • 주요 모듈 AI 코딩 (주문·재고·결제)
    • AI 코딩 가이드 보완 (문제점·보완점 도출)
    • 방법론 문서 확정
    • 타 프로젝트 적용 준비

Phase 4 (옵션, 2~3주) — B2B커머스 검증
    • B2B커머스 프로젝트에 방법론 시범 적용
    • 자산(템플릿+Steering) 범용성 검증
    • 프로토타입 생성 → 현업 시연 → 피드백 수집
    • 검증 결과로 자산·프로세스 보완점 도출
    ※ 적용 가능 프로젝트 확보 시 진행
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

전체 일정: 12주 (검증단계 포함 시 14~15주)
자산 완성도: RFP 기준 2주 내 프로토타입 생성 가능
```
