## 2. 협업 방식

### 2.1 역할 분담

| 역할 | 담당 | 내용 |
|------|------|------|
| 비즈니스 오너 | 페페 (3TOP) | 정책 결정·방향 확정·피드백·검토 |
| 설계 에이전트 | Claude | 산출물 생성·크로스체크·구조화·문서화 |
| 구현 에이전트 | Kiro | 코드 구현·빌드 검증·패턴 적용 |

### 2.2 협업 원칙

```
1. 페페가 방향·정책·결정 사항을 제시
2. AI가 구조화·문서화·코드 생성
3. 페페가 검토·수정·확정
4. AI가 반영 후 다음 단계 진행
5. 반복
```

### 2.3 도구

| 도구 | 용도 | 사용 단계 |
|------|------|---------|
| Claude 채팅 | 설계 협업 채널 | 1~9공정 (설계) |
| Kiro | 코드 구현·빌드·검증 | 10공정~ (구현) |
| Mermaid | 다이어그램 시각화 | 설계 |
| Markdown | 산출물 문서화 | 전체 |
| Steering 파일 | AI 에이전트 코딩 규칙 주입 | 구현 |

## 3. 전체 진행 절차

#### ⚡ 순서 변경 공정 (1건)

| 변경 | 정규 순서 | 실제 순서 | 이유 |
|------|---------|---------|------|
| 6공정 ↔ 7공정 교환 | 6공정(프로세스) → 7공정(화면) | 7공정(화면정의서, 7단계) → 6공정(프로세스, 8단계) | 이벤트 흐름과 화면을 먼저 확정해야 프로세스에서 정확한 노드 배치 가능 |

#### ✅ 누락 공정 (없음)

```

1공정 정책서         → 2단계 + 9단계(크로스체크)
2공정 BC            → 3단계

6공정 프로세스       → 8단계 + 10단계(다이어그램)
7공정 화면          → 7단계(화면정의서) + 20~28단계(프로토타입)
```

#### ❌ 불필요 공정 (없음, 단 추가 활동 5건 존재)

| 단계 | 작업 | 구분 | 판단 |

| 불필요 공정 | 0건 | 정규 9개 모두 유효 |
| 추가 활동 | 5건 | 와이어프레임 확인·크로스체크·문서 통합·방법론·온보딩 |

#### 💡 순서 변경의 의미

```
정규 순서 (이론)
    1 → 2 → 3 → 4 → 5 → 6 → 7 → 8 → 9
    정책 → 도메인 → 아키텍처 → ERD → 이벤트 → 프로세스 → 화면 → 요구사항 → 구현

실제 순서 (실전)
    (확인) → 1 → 2 → 3 → 4 → 5 → 7 → 6 → 1(검증) → 8 → 9
    와이어프레임확인 → 정책 → BC → 아키텍처 → ERD → 이벤트 → 화면정의 → 프로세스 → 크로스체크 → 요구사항 → 구현

순서 변경 이유 (6공정 ↔ 7공정)
    → 정규: 이벤트(5) → 프로세스(6) → 화면(7)
    → 실제: 이벤트(5) → 화면(7) → 프로세스(6)
    → 화면 구성 요소를 먼저 정의해야 프로세스에서
      "어떤 화면을 거쳐 어떤 흐름으로 진행되는가"를 정확히 표현 가능
    → 프로세스 다이어그램에 화면 노드를 배치하려면 화면 목록이 먼저 있어야 함

기타 특이점
    → 1단계 와이어프레임은 공정이 아닌 "방향 확인" — 본격 7공정은 화면정의서+프로토타입
    → 크로스체크를 공정 사이에 삽입하여 반복 검증 수행
    → 정규 순서의 단방향 흐름 → 실제는 피드백 루프가 포함된 순환 구조
```

## 6. 협업 특징 및 패턴

### 6.1 페페의 협업 스타일

```
간결한 지시
    → "넵" / "다음" / "네" (승인)
    → "정책서 수정" / "BC 반영" (방향 지시)
    → "~추가해줘" / "~참고해서 수정해줘" (구현 요청)

정확한 수정 요청
    → "배송지 변경은 입점사 업무가 아니라 어드민 업무"
    → "페이지 관리를 참고해서 주문현황 수정해줘"
    → "레인은 표시하지 말고 색상으로만 구분해줘"

통찰적 질문
    → "화면을 정의하고 ERD를 작성하였는데 이번에는 순서가 바뀌었어"
    → "요구사항이 '무엇을 해주세요'가 아니라 '이렇게 합니다'로 정리된듯하네"
```

### 6.2 AI의 협업 스타일

```
설계 단계 (Claude)
    → 자율적 크로스체크 (문서 간 불일치 자동 발견)
    → A/B/C 방안 제시 → 페페가 선택
    → 점진적 개선 (v1 → v2 → v3)

구현 단계 (Kiro)
    → 기존 코드 패턴 분석 → 동일 패턴 적용
    → 변경 범위 사전 확인 → 페페 승인 후 진행
    → 빌드 검증 (tsc + next build) 자동 수행
    → Steering 규칙 준수 (순수 CSS, Mock API 호출 등)
```

### 6.3 반복 패턴

```
패턴 1: 생성 → 피드백 → 재생성 (설계)
    AI 초안 생성 → 페페 검토·피드백 → AI 수정·재생성 → 페페 확정

패턴 2: 제안 → 선택 (설계)
    AI가 A/B/C 방안 제시 → 페페가 선택 → AI가 선택안 적용

패턴 3: 크로스체크 → 확정 (설계)
    AI가 불일치 항목 테이블 제시 → 페페가 방향 지시 → AI 일괄 반영

패턴 4: 참고 → 적용 (구현)
    페페가 레퍼런스 지정 ("페이지 관리 참고해서")
    → AI가 패턴 분석 + 변경 범위 확인
    → 페페 승인
    → AI가 구현 + 빌드 검증
```

### 6.4 오류 발생 및 수정 사례
