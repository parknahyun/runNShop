## 도메인 개요

전시(Display) 도메인은 고객앱 화면의 시각적 구성 요소를 어드민에서 관리하는 기능이다.

```
섹션종류 (SectionType)   → 개발팀이 정의하는 UI 블록 타입 (필드 구조 포함)
    ↓ 참조
템플릿 (Template)        → XML로 와이어프레임 구조를 정의하고, 각 영역(area)에 섹션종류를 지정
                           페이지 생성 시 XML 구조를 복사하여 초기 섹션 구성 생성
    ↓ 복사(XML 파싱)
전시페이지 (DisplayPage) → 실제 고객앱에 게시되는 페이지 (섹션별 콘텐츠 데이터 포함)
```

**템플릿 XML 구조 (와이어프레임)**:
```xml
<template id="TPL-001" name="홈 기본" type="HOME">
  <row seq="1">
    <area seq="1" label="메인 배너" width="full" sectionType="HERO_BANNER" required="true"/>
  </row>
  <row seq="2">
    <area seq="1" label="추천 상품" width="full" sectionType="PRODUCT_CAROUSEL" required="false"/>
  </row>
  <row seq="3">
    <area seq="1" label="왼쪽 이미지" width="1/2" sectionType="IMAGE_LINK" required="false"/>
    <area seq="2" label="오른쪽 이미지" width="1/2" sectionType="IMAGE_LINK" required="false"/>
  </row>
</template>
```

| XML 요소 | 주요 속성 | 설명 |
|---------|---------|------|
| `<template>` | id, name, type | 템플릿 메타정보 |
| `<row>` | seq | 수평 행 (위→아래 순서) |
| `<area>` | seq, label, width, sectionType, required | 영역 (열 분할) |

- `width`: full / 1/2 / 1/3 / 2/3
- `sectionType`: ACTIVE 상태 섹션종류 코드만 허용

**페이지 유형**: HOME / CATEGORY / EVENT
**페이지 상태**: DRAFT → SCHEDULED / PUBLISHED → DEPRECATED

```
• XML은 row(행) > area(영역) 계층 구조로 와이어프레임을 표현

• 페이지 생성 시 XML 파싱 → area별 섹션 레코드 INSERT

[가정 항목 — 2차 확인 필요]

AC-2: 페이지 등록 시 선택한 템플릿의 XML을 파싱하여 area별 초기 섹션이 생성된다
AC-3: 원본 템플릿 XML 수정이 이미 생성된 페이지에 영향을 주지 않는다
AC-4: 템플릿 XML은 유효한 스키마(row > area, sectionType 필수)를 따라야 저장된다
```

## FR-DPL-003 전시 페이지 등록 및 섹션 구성

```
요구사항 ID    : FR-DPL-003
요구사항명     : 전시 페이지 신규 등록 및 섹션 콘텐츠 입력
분류           : 기능(FR)
우선순위       : P1(Must)
도메인         : Display
상태           : DRAFT
출처           : RFP ("콘텐츠를 등록·수정할 수 있어야 합니다"), 인터뷰-Q1~Q4
도출방식       : 명시적요청

[설명]
운영자가 템플릿을 선택하여 전시 페이지를 생성하고, 각 섹션에 콘텐츠 데이터를 입력한다.

[인터뷰 확인 내용]
• 페이지 유형: HOME / CATEGORY / EVENT
• 템플릿 선택 후 섹션 구성 복사 방식
```
