# ② 정책서 — Harness 표준양식

- **매핑 Harness**: Domain Constraint Harness (원천)
- **원천 작성 항목**: 정책 코드화(HARD/SOFT), 변경 영향 범위
- **AI-H**: AI-H3 (정책 코드화), AI-H4 (변경 영향 범위)

---

## 기본 섹션 (일반 방법론)

```
정책 ID        : POL-{도메인}-{SEQ}
정책명          : 
적용 도메인     : 
적용 대상       : 고객 / 입점사 / 플랫폼 / 전체
우선순위        : 
상태            : DRAFT / CONFIRMED / CHANGED
변경 이력       : 

[정책 내용]
(상세 비즈니스 규칙)

[적용 조건]
• 조건 1
• 조건 2

[예외 처리]
• 예외 1 → 처리 방안
• 예외 2 → 처리 방안
```

---

## AI 보강 섹션

```
[AI-H3] 정책 코드화 (실행 가능한 규칙)      ← Domain Constraint Harness (원천)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
constraint_type: HARD / SOFT

rule_expression: |
  (의사코드 또는 조건식으로 표현)
  예: IF order.total < 50000 THEN shipping_fee = 3000
      IF vendor.grade == "Elite" THEN commission_rate -= 1.5%

applies_to:
  - req_id: FR-{DOM}-{SEQ}      # 이 정책이 적용되는 요구사항 ID
  - req_id: FR-{DOM}-{SEQ}

wrong_pattern: |
  AI가 이 정책을 잘못 해석하는 패턴
  예: 수수료 감면을 절대값으로 적용 (퍼센트 포인트가 아닌 퍼센트로 계산)

[AI-H4] 변경 영향 범위                      ← Context Harness (전파 추적)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
affected_domains: []
affected_apis: []
affected_batches: []
change_frequency: 높음 / 보통 / 낮음

※ change_frequency가 "높음"이면:
  → 정책값을 하드코딩 금지, Config 테이블 또는 상수 분리 필수
  → AI 코딩 지시: "이 값은 config 테이블에서 조회"
```

---

## 작성 기준

| 항목 | 기준 |
|------|------|
| rule_expression | 자연어 정책을 AI가 코드로 직접 변환할 수 있는 의사코드 수준 |
| HARD vs SOFT | 위반 시 시스템 오류 → HARD / 권고·정책 → SOFT |
| wrong_pattern | 비슷해 보이지만 틀린 구현 패턴 (단위 혼동, 방향 역전 등) |
| affected_domains | 이 정책을 변경했을 때 수정해야 하는 코드 범위 (AI 재작업 범위) |
| Config 분리 | change_frequency 높음 → 정책값 하드코딩 절대 금지 |

## 하위 문서 역참조 경로

```
POL-{DOM}-{SEQ}
  └─ 근거 요구사항: FR-{DOM}-{SEQ}   (① 요구사항에서 AC로 표현된 규칙)
  └─ 적용 API:      {DOM}-{SEQ}      (⑧ API정의서에서 HARD/SOFT로 참조)
  └─ 영향 도메인:   DOM-{DOM}        (③ 도메인정의에서 통신 계약 영향)
```
