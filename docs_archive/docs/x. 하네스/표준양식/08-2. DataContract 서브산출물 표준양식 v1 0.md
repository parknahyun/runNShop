## [AI-H24] Data Contract (API별)              ← Data Contract Harness

### 도메인 레벨 규칙 참조 (⑥ ERD 원천)

```yaml
invariants_ref: AI-H15           # 불변식 원천
# 이 API에 적용되는 불변식: (ERD에서 복사하지 않고 참조 ID만 표기)

state_transition_ref: AI-H16     # 상태 전이 원천
# 이 API가 유발하는 상태 전이: {FROM} → {TO}

soft_delete_ref: AI-H17          # 소프트 삭제 규칙 원천
# immutable_fields 중 이 API가 특히 주의할 컬럼: []
```

### API 레벨 영속성 계약 (직접 작성)

```yaml
persistence:
  target_tables:
    - {prefix}_{table}           # INSERT/UPDATE 대상 테이블
    - {prefix}_outbox            # 이벤트 발행 시 필수

  read_fields:
    | 필드 | 테이블 | 조건 | 비고 |
    |------|--------|------|------|
    | field_name | table_name | WHERE 조건 | |

  write_fields:
    | 필드 | 테이블 | 액션 | 비고 |
    |------|--------|------|------|
    | field_name | table_name | INSERT/UPDATE | |

  default_query_scope: "is_deleted = FALSE AND ..."
  index_hint:
    - idx_{table}_{col}: "사용 이유"

transaction_annotation: "@Transactional(readOnly = false / true)"
isolation_level: READ_COMMITTED   # 기본; 필요 시 REPEATABLE_READ 명시

wrong_patterns:
  - "is_deleted = TRUE 행 조회 필터 누락"
  - "immutable_fields UPDATE 쿼리 포함"
  - "복제 테이블에 INSERT/UPDATE"
  - "Outbox INSERT를 트랜잭션 외부에서 실행"
```

---

## 작성 기준

| 항목 | 기준 |
|------|------|
| read_fields | SELECT 절·FROM 절·WHERE 절 근거 → MyBatis Mapper XML 생성 직접 입력 |
| write_fields | INSERT INTO / UPDATE SET 컬럼 목록 → DTO-Entity 매핑 생성 근거 |
| default_query_scope | 모든 SELECT에 공통으로 붙는 WHERE 조건 (AI가 자주 누락하는 항목) |
| index_hint | 풀스캔 방지 인덱스 활용 방향 (AI가 N+1 쿼리 대신 인덱스 활용 코드 생성) |
| Outbox 포함 여부 | 이벤트 발행이 있는 API만 target_tables에 outbox 추가 |
| 작성 생략 | 단일 테이블 단순 조회/저장, 복잡한 조건 없음 → 생략 가능 |
