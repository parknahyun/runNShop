# ⑧ API 정의서 — Harness 표준양식 (6개 Harness 종합)

- **매핑 Harness**: 6개 전체 종합 (참조 기반)
- **직접 작성 항목**: Output Schema (expected_classes), endpoint, response error_catalog
- **참조 항목**: Context(③), Domain Constraint(①②), Requirements Validation(⑤), Feedback Loop(①)
- **서브산출물**: Sequence(⑧-1), Data Contract(⑧-2) — 복잡도 높은 API에 별도 작성

---

## 문서 헤더

```yaml
api_id: {DOM}-{SEQ}
api_name: 
domain: 
type: A / B / C / D               # A=표준/운영, B=협상·프로모션, C=개발주도, D=사업주도
source_req: FR-{DOM}-{SEQ}        # ① 원천 요구사항
source_policy: POL-{DOM}-{SEQ}    # ② 적용 정책
source_domain: DOM-{DOM}          # ③ 도메인 정의 참조
source_process: BPM-{DOM}-{SEQ}   # ④ 업무흐름 참조
source_screen: {APP}-{SEQ}        # ⑤ 화면 참조 (없으면 생략)
source_entity: {prefix}_{table}   # ⑥ ERD 참조
source_tech: TC-{SEQ}            # ⑦ 기술 제약 참조
```

## 6개 Harness 종합 (참조 기반)

```
[Context Harness]                           ← ③ 도메인정의 참조 + Sequence 서브산출물
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
bounded_context: (DOM-{DOM} 참조)
dependencies: (AI-H6 통신 계약 참조)
communications: (AI-H6 참조)

endpoint:
  method: GET / POST / PUT / DELETE / PATCH
  path: /api/v1/{resource}
  auth: 로그인 필요 / 불필요 / 어드민 전용
  role: []                         # 접근 가능 역할 목록

sequence_ref: SEQ-{DOM}-{SEQ}      # ⑧-1 Sequence 서브산출물 참조 (복잡한 API만)

[Requirements Validation Harness]           ← ⑤ 화면정의에서 도출
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
request:
  | 필드 | 타입 | 필수 | 제약조건 |
  |------|------|------|---------|
  | | | | |

response:
  success:
    status: 200 / 201
    body: {}
  error_catalog:
    - {code: , http: , condition: , message_key: }

cross_field_rules:
  - rule: (① AC에서 상속)

[Domain Constraint Harness]                 ← ①② 에서 상속
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
HARD:
  - HC-{DOM}-{SEQ}: (① 요구사항 HARD Constraint 참조)
  - TC-{SEQ}: (⑦ 기술 제약 참조)
SOFT:
  - POL-{DOM}-{SEQ}: (② 정책서 rule_expression 참조)

[Data Contract Harness]                     ← ⑥ ERD 참조 + Data Contract 서브산출물
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
invariants: (⑥ AI-H15 참조)
state_transition: (⑥ AI-H16 참조)
soft_delete: (⑥ AI-H17 참조)

data_contract_ref: DC-{DOM}-{SEQ}   # ⑧-2 Data Contract 서브산출물 참조 (복잡한 API만)

[Output Schema Harness]                     ← ⑦ 기술정의 상속 + API별 직접 작성
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
layer: (⑦ AI-H19 code_generation_rules 기반)
pattern: Command / Query
expected_classes:
  - {Domain}Controller
  - {Domain}Service
  - {Domain}Repository
  - {Action}{Domain}Request
  - {Action}{Domain}Response
transaction_annotation: "@Transactional(readOnly = false / true)"
event_publishing:
  timing: AFTER_COMMIT / 없음
  method: Outbox / 없음

[Feedback Loop Harness]                     ← ① 에서 상속 + API별 분배
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
test_scenarios: (① AI-H2 검증시나리오를 이 API 단위로 분배)
quality_gate:
  p95_latency: ms
  test_coverage: %
```

## 작성 기준

| 항목 | 기준 |
|------|------|
| 참조 항목 | 원천 문서 ID만 표기 (내용 재작성 금지) |
| expected_classes | 이 API를 위해 생성할 구체 클래스명 목록 (AI 코드 생성 지시) |
| error_catalog | HTTP 상태코드 + 비즈니스 에러코드 + 조건 + 다국어 키 세트로 정의 |
| Sequence 서브산출물 | 외부 API 호출·이벤트·트랜잭션이 복합된 API만 SEQ-* 작성 |
| Data Contract 서브산출물 | 다수 테이블 read/write·복잡한 WHERE 조건이 있는 API만 DC-* 작성 |
