## CUS-030 — 통합 검색 (mobile, 소스가 명시적으로 미구현)

> **소스에 미구현이 직접 기록되어 있음**: `apps/runNshop-mobile/app/search/page.tsx`가 `<p>검색 화면은 아직 구현되지 않았습니다.</p>`라는 placeholder만 렌더링한다. `02-Catalog.md`의 CUS-010(카테고리 목록)과 동일한 패턴(안내 문구만 존재).

### 메타정보

> **화면 ID**: CUS-030 · **화면명**: 통합 검색 (SearchPage) · **유형**: 목록형
> **메뉴 경로**: 검색 (BottomNav 또는 GNB, `/search?q={keyword}`) · **권한**: 전체
> **소스**: `apps/runNshop-mobile/app/search/page.tsx`(placeholder만 존재)
> **문서상태**: DRAFT-v1.0 (일반기능 기준, 소스는 미구현 안내만)

## 도메인 정의와 실제 구현 사이의 간극

`DB-도메인정의서.md`(자산화 산출물)는 Search 도메인의 책임을 "상품 검색·필터·자동완성, 인기 검색어, 검색 색인 관리"로 정의하고, admin 채널("검색어 관리·분석")도 있다고 서술한다. 그러나:

- **admin에 검색어 관리 화면이 없다** — `navMenus.ts` 전수 검색 결과 관련 메뉴 자체가 존재하지 않음
- **mobile CUS-030도 placeholder뿐**이다
- `10-Search.md`(이 문서)가 다룰 실제 구현체가 **하나도 없다**

> **Human Review**: Search 도메인은 설계(도메인정의서·화면정의서 API 목록)는 존재하지만 실제 화면 구현이 전무한 상태다. `RFP-10-Search.md`(질의서)에서 이미 검색엔진 선정(Elasticsearch vs 내장 구현) 여부를 발주사에게 묻고 있는데, 이는 아직 착수하지 않은 도메인이라는 뜻과도 부합한다. 향후 실제 구현 시 이 문서(일반기능 기준 추정)를 초안으로 쓸 수 있으나, 검색엔진 선정 결과에 따라 API 구조가 달라질 수 있음을 감안해야 한다.
