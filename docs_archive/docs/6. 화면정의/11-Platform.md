# 화면정의서 — Platform (인증/공통설정/시스템관리) 도메인

> **작성 목적**: `runNshop_screen_definition_v1_1.md`에서 v1.0→v1.1 전환 시 삭제된 와이어프레임을 보완한다. `화면정의서_작성_표준안.md` 방식(메타정보+영역·속성·기능·UI상태)을 따르되 와이어프레임(ASCII)과 상세디스크립션을 한 파일에 통합했다.
> **소스 대조 원칙**: 구현이 있는 화면은 소스를 근거로, 없는 화면은 B2C 커머스 일반기능 수준으로 작성(문서 내 표기).
> **원본 화면 목록**: `runNshop_screen_definition_v1_1.md` §3.3(ADM-000-*, ADM-090-001~004/006~010, ADM-100-001~002), §4.2(VND-000-*, VND-080-001~003)
> **도메인 경계**:
> - 12개 업무도메인 분류상 "Platform"은 원본 화면목록의 특정 챕터명이 아니라, 이 자산화 작업에서 **인증(로그인/2FA/비밀번호)·공통 설정(약관/배너/공지/금지어)·시스템 관리(운영자/권한/프로그램/공통코드/배치/Outbox·DLQ)**를 하나로 묶기 위해 새로 도입한 경계다.
> - 감사 로그(ADM-100-003)와 고객정보 접근 이력(ADM-090-010)은 **조회 전용 로그·추적** 성격이 강해 `12-Audit.md`로 분리한다. 배치 관리(ADM-100-001)·Outbox·DLQ(ADM-100-002)는 로그 조회가 아니라 **운영 조치가 있는 시스템 인프라 화면**이라 이 문서에 포함한다.
> - 알림 템플릿(ADM-090-005)은 `08-Notification.md`에서 이미 다뤘다(발송자 관점). 입점사 알림 설정(VND-080-003)은 이 문서(계정 설정 묶음)에서 다룬다.
> - 입점사 로그인(VND-000-*)·계정 관리(VND-080-*)는 `07-Vendor.md`에서 admin이 입점사를 "관리"하는 관점과 분리해 이 문서로 이관했다(다른 채널 인증 체계와 통일 목적).
> - 고객(mobile) 로그인·회원가입(CUS-080~085)은 `03-Member.md`에서 이미 다뤘다. 이 문서는 admin/partner 채널의 인증만 다룬다.
> **작성일**: 2026-08-26

**세션 정책 (mockAuth.ts 인용)**

- 로그인 성공 시 세션을 `localStorage`(`runNshop_admin_mock_session`)에 저장 — 새로고침해도 로그인 유지(코딩 표준 "세션 만료 미적용" 규칙과 부합).
- `checkSession()`은 `GET /api/admin/v1/auth/me` 격의 300ms 지연 후 저장된 세션 반환.
- `logout()`은 `POST /api/admin/v1/auth/logout` 격으로 저장된 세션 삭제.
- 원본 정책(§3.1 공통 레이아웃 인접 텍스트에는 명시 없으나 VND 쪽 §4.1과 대비): admin 세션은 "JWT + 세션 8시간"(`runNshop_screen_definition_v1_0.md` §도입부 채널표)이나, mock 구현은 세션 만료를 시뮬레이션하지 않는다(코딩 표준 문서의 "세션 만료: 미적용" 규칙에 부합).

> **Human Review**: 로그인 실패 케이스(잘못된 이메일 형식, 5회 연속 실패 시 잠금)는 안내 문구만 있고 실제 로직이 없다. mock 단계이므로 의도된 결과이나, 실 서비스 전환 시 이메일 형식 검증과 계정 잠금 정책(원본에는 명시 없음 — 신규 정책 필요) 확정이 필요하다.
