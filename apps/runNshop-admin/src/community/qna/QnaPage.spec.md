# QnA 관리 (QnaPage)

## 개요
고객이 남긴 상품문의·주문문의를 통합 조회하고 답변·활동지수 지급·숨김을 처리하는 현황목록 화면.
(ADM-080-002, `cmt_qna` — PRODUCT·ORDER 두 유형을 하나의 테이블로 통합 관리)

- PRODUCT 문의: 상품상세 페이지에서 등록되며 기본 공개(`is_public = TRUE`), 운영자 또는 입점사가 답변 가능
- ORDER 문의: 주문 관련 개인정보(배송지 등)가 노출될 수 있어 `is_public`이 항상 FALSE로 고정되며, 운영자만 답변
- 관리자가 신규로 QnA를 등록하는 기능은 없다 (고객의 문의 등록 행위로만 생성됨)

## 유형 (qnaType)
| 코드 | 라벨 | 참조(refName) |
|------|------|------|
| PRODUCT | 상품문의 | 상품명 |
| ORDER | 주문문의 | 주문번호 |

## 상태 (status)
| 코드 | 라벨 | 의미 |
|------|------|------|
| PENDING | 답변대기 | 아직 답변이 등록되지 않은 상태 (기본값) |
| ANSWERED | 답변완료 | 답변이 등록된 상태 |
| HIDDEN | 숨김 | 부적절한 문의 등으로 관리자가 숨김 처리한 상태 |

상태 전이: 답변 등록 시 `PENDING → ANSWERED`, 숨김/활성화 액션으로 `(PENDING|ANSWERED) ↔ HIDDEN` 전이가 가능하다.
숨김에서 활성화로 되돌리면 답변 유무에 따라 `ANSWERED` 또는 `PENDING`으로 복귀한다.

## 필터바
- 키워드 (질문내용 / 작성자명)
- 유형 선택 (전체/상품문의/주문문의)
- 상태 선택
- 조회 버튼

## 요약바
전체 / 답변대기 / 답변완료 / 숨김 건수 표시 (조회 후 노출)

## 목록 테이블
| 컬럼 | 설명 |
|------|------|
| QnA번호 | QNA-001 형식, 클릭 시 상세 모달 오픈 |
| 유형 | 상품문의/주문문의 |
| 참조 | 상품명 또는 주문번호 |
| 작성자 | 마스킹 표시 |
| 질문내용 | 1줄 요약(말줄임) |
| 공개여부 | 공개/비공개 (주문문의는 항상 비공개) |
| 활동지수 | 지급 여부 |
| 상태 | 배지 |
| 문의일시 | |

## 규칙 (현황목록 공통)
- 진입 시 TitleBar + FilterBar만 표시, 데이터 미노출
- 조회 버튼 클릭 후 SummaryBar + Table + Pagination 동시 노출 (Enter 키 조회 가능)
- 행 클릭 → 상세 모달 오픈 (탭으로 열지 않음)
- 등록 버튼 없음

## 상세 모달 (QnaDetail)
탭 구성: **기본정보** (단일 탭)

### 기본정보 탭
- 읽기 전용: QnA번호, 유형, 참조, 작성자, 상태, 공개여부, 문의일시, 답변일시, 답변자 유형(운영자/입점사), 질문내용, 활동지수 지급여부·지급일시
- 답변 영역: 상태가 숨김이 아닌 경우 답변 textarea가 노출되며, 답변이 없으면 "답변 등록", 있으면 "답변 수정" 버튼으로 저장한다. 저장 시 상태가 답변완료로 전환되고 답변자 유형은 운영자(OPERATOR), 답변일시가 기록된다.
  - 숨김 상태에서는 답변을 읽기 전용 텍스트로만 표시한다(편집 불가).

## 액션 (모달 하단 고정 영역)
- **활동지수 지급**: 답변이 등록된 이후에만 활성화되며, 이미 지급된 경우 다시 누를 수 없다(버튼 비활성화). 클릭 시 지급여부·지급일시가 기록된다. 우수 답변에 대한 커뮤니티 활동지수 보상 개념으로, 회원 등급에 실제로 반영하는 로직은 이 mock 범위에서 다루지 않는다.
- **숨김**: 상태가 숨김이 아닐 때 노출되며, 클릭 시 즉시 상태를 숨김으로 전환한다 (별도 사유 입력 없음 — `cmt_qna`에는 사유 컬럼이 없다).
- **활성화**: 상태가 숨김일 때 노출되며, 클릭 시 답변 유무에 따라 답변완료 또는 답변대기로 복귀한다.

## 비고
- 일괄 숨김/일괄 활성화, 엑셀 다운로드는 API 목록(`/api/admin/v1/qna/excel` 등)에는 정의되어 있으나 본 화면에서는 스텁(엑셀) 또는 범위 외(일괄 처리)로 처리한다.
- 활동지수 지급은 API상 `POST /api/admin/v1/qna/{id}/activity-score`에 대응하며, 실 서비스에서는 회원의 커뮤니티 활동지수(회원 등급 산정 요소 중 하나)에 반영되나 본 mock은 QnA 레코드 자체의 지급 여부·일시만 기록한다.
