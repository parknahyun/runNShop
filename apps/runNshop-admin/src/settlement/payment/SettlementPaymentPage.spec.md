# 지급 관리 (SettlementPaymentPage)

## 개요
확정된 정산에 대한 입점사 계좌 지급을 처리·추적하는 현황목록 화면.
(ADM-070-002, `stl_settlement_payment`)

정산이 `CONFIRMED` 상태로 전이되면 배치가 지급 스케줄(`SCHEDULED`)을 자동 생성한다(본 화면 밖의 배치 로직, mock 미표현).
본 화면은 이미 생성된 지급 스케줄을 조회하고 지급완료·보류·보류해제를 처리하는 관리자용 화면이며, 지급 건을 신규로 등록하는 기능은 없다.

## 상태 (status)
| 코드 | 라벨 | 의미 |
|------|------|------|
| SCHEDULED | 지급예정 | 지급 스케줄이 생성된 초기 상태 |
| PAID | 지급완료 | 입점사 계좌로 지급이 완료된 상태 |
| HOLD | 보류 | 이의제기 검토 등의 이유로 지급이 보류된 상태. 지급예정으로 되돌릴 수 있음 |
| FAILED | 지급실패 | PG/은행 계좌 이체 실패 상태 (계좌 오류 등). 본 화면에서 재시도 액션은 없음 |

상태 전이: `SCHEDULED → (PAID | HOLD)`, `HOLD → SCHEDULED`(보류 해제). `PAID`·`FAILED`는 최종 상태로 액션이 없다.

## 필터바
- 키워드 (정산번호 / 입점사명)
- 상태 선택
- 지급예정일 기간 (from ~ to)

## 요약바
전체 / 지급예정 / 지급완료 / 보류 건수 표시, 지급실패는 0건이면 카드 숨김 (조회 후 노출)

| 컬럼 | 설명 |
|------|------|
| 정산번호 | 클릭 시 상세 모달 오픈 |
| 입점사 | |
| 은행 | 은행코드 → 은행명 매핑 |

## 규칙 (현황목록 공통)
- 진입 시 TitleBar + FilterBar만 표시, 데이터 미노출
- 조회 버튼 클릭 후 SummaryBar + Table + Pagination 동시 노출 (Enter 키 조회 가능)
- 행 클릭 → 상세 모달 오픈 (탭으로 열지 않음)
- 등록 버튼 없음 (지급 스케줄은 정산 확정 시 배치가 자동 생성함)
- Toolbar의 `일괄 지급`은 선택된 여러 건을 한 번에 지급 처리하는 기능이나, 본 mock 화면은 스텁(alert)으로만 동작한다

## 상세 모달 (SettlementPaymentDetail)
탭 없이 기본정보(정산번호·입점사·상태·은행·계좌번호·예금주·지급금액·지급예정일·지급완료일시·보류사유·생성/수정일시)를 단일 화면에 표시한다. 조회할 하위 데이터가 없어 InnerTabs를 사용하지 않는다.

## 상태 전이 액션 (모달 하단 고정 영역)
- 상태 = 지급예정: **지급 보류** / **지급 완료** 버튼
  - 지급 보류 시 보류사유 입력 필수
  - 지급 완료 시 지급완료일시가 기록됨
- 상태 = 보류: **보류 해제** 버튼 → 지급예정으로 전이, 보류사유 초기화
- 상태 = 지급완료 / 지급실패: 액션 버튼 없음 (최종 상태)

## 비고
- 실 서비스에서는 지급 스케줄 생성 시 PG/은행 이체 API가 연동되며, 이체 실패 시 상태가 `FAILED`로 전이되고 재시도 배치(`SettlementPaymentRetryBatch`)가 재처리한다. 본 화면은 이러한 이체 연동·재시도 배치를 mock으로 표현하지 않는다.
- 계좌번호는 이미 마스킹된 문자열로 mock 데이터에 저장되어 있으며, 실 서비스에서는 조회 시점에 서버가 마스킹을 적용한다.
