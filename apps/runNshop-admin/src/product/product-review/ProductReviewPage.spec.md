# 상품 심사 (ProductReviewPage)

## 개요
입점사가 등록(신청)한 상품을 승인/반려하는 심사 전용 현황목록 화면.
"상품 목록"과 동일한 상품 마스터 데이터를 다루지만, 이 화면에서만 심사상태(승인/반려)를 변경할 수 있다.
등록 기능은 없다(등록은 "상품 목록" 화면에서 처리하며, 등록 즉시 심사대기 상태로 이 화면에 나타난다).
(ADM-020-001, `prd_product`)

## 심사상태
| 코드 | 라벨 |
|------|------|
| PENDING | 심사대기 |
| APPROVED | 승인 |
| REJECTED | 반려 |

## 필터바
- 키워드 (상품ID / 상품명 / 입점사)
- 브랜드 선택
- 심사상태 선택 (기본값: 심사대기 — 진입 후에도 조회 버튼을 눌러야 데이터가 노출된다)
- 조회 버튼

## 요약바
전체 / 심사대기 / 승인 / 반려 건수 표시 (조회 후 노출). 등록 버튼은 없다(이 화면은 심사 전용).

## 규칙 (현황목록 공통)
- 진입 시 TitleBar + FilterBar만 표시, 데이터 미노출
- 조회 버튼 클릭 후 SummaryBar + Table + Pagination 동시 노출 (Enter 키 조회 가능)
- 행 클릭 → 상세 모달 오픈 (탭으로 열지 않음)

## 상세 모달 (ProductReviewDetail)
**"상품 목록"의 상세(ProductDetail)와 완전히 동일한 화면을 조회 전용(readOnly)으로 재사용**하고,
하단에 심사 액션 영역만 추가로 붙인 구성이다 — 별도의 read-only 레이아웃을 새로 만들지 않는다.
- 탭 구성도 동일: 기본정보 / 이미지 (N) / 옵션 (N) / 재고이력 (N) / 문의 (N) / 상품평 (N)
- 조회 전용이므로 모든 탭에서 편집·추가·삭제·SKU생성·입출고 등록·답변·숨김처리 등 변경 액션 버튼이 노출되지 않는다(값 확인만 가능)
- **심사대기 상태에서만** 탭 영역 하단에 "승인" / "반려" 액션이 고정으로 노출된다
  - **승인**: 즉시 심사상태를 "승인"으로 전환한다 (별도 확인 입력 없음)
  - **반려**: 반려사유 입력 폼이 펼쳐지며, 사유를 입력해야 "반려 확정" 버튼이 활성화된다. 반려사유는 입점사에게 전달되는 것으로 간주한다
- 이미 승인/반려된 상품은 심사 액션 영역 자체가 노출되지 않는다(재심사가 필요하면 상품을 새로 등록해야 한다)

## 비고
- "상품 목록"과 "상품 심사"는 같은 상품 데이터를 다루는 서로 다른 화면이며, 이 mock 구현에서는 각 화면이 초기 데이터를 독립적으로 들고 있어 동시에 두 화면을 열어둔 상태에서의 실시간 동기화는 지원하지 않는다(실제 백엔드 연동 시에는 동일 저장소를 공유한다).
