# 운영자 신청 승인 (OperatorApplicationPage)

## 개요
외부 신청자가 제출한 운영자(admin) 계정 신청을 조회하고 승인·반려하는 현황목록 화면.
(ADM-090-002)

운영자 계정은 `cfg_operator`에 실제 계정이 생성되어야 로그인할 수 있는데, 이 화면은 그 계정을 만들기 전 단계인
"신청" 레코드를 관리하는 화면이다. 별도 ERD 테이블이 정의되어 있지 않아 신청 레코드는 화면 전용 mock으로 관리되며,
승인 시 실제 `cfg_operator` 계정·`cfg_role` 부여가 뒤따르는 것으로 간주하되 그 연동은 본 화면에서 표현하지 않는다.

## 요청역할 (requestedRoleCode)
`cfg_role.role_code` 값 중 자기 신청이 가능한 역할만 노출한다. `SUPER_ADMIN`은 시스템 최초 계정에만 부여되는
역할이라 신청 대상에서 제외한다.

| 코드 | 라벨 |
|------|------|
| MD | MD |
| CS | CS |
| SETTLEMENT | 정산 |
| VENDOR_MANAGER | 입점사관리 |

## 상태 (status)
| 코드 | 라벨 | 의미 |
|------|------|------|
| APPLIED | 신청 | 신청서가 제출되어 검토 대기 중인 초기 상태 |
| APPROVED | 승인 | 관리자가 승인한 상태 (최종) |
| REJECTED | 반려 | 관리자가 반려한 상태 (최종) |

상태 전이: `APPLIED → (APPROVED | REJECTED)`. 클레임 관리와 달리 중간 처리 단계(처리중)가 없는 단일 스텝 승인 플로우이며,
상세 모달 하단 액션 버튼으로만 전이한다. 역방향 전이는 없다.

## 필터바
- 키워드 (이름 / 이메일)
- 상태 선택 (전체/신청/승인/반려)
- 요청역할 선택
- 조회 버튼

## 요약바
전체 / 신청 / 승인 / 반려 건수 표시 (조회 후 노출)

## 목록 테이블
| 컬럼 | 설명 |
|------|------|
| 신청ID | OPA-001 형식, 클릭 시 상세 모달 오픈 |
| 이름 | 신청자 이름 |
| 이메일 | 신청자 이메일 |
| 요청역할 | 신청한 cfg_role.role_code 라벨 |
| 신청사유 | 1줄로 말줄임 표시, 전체 내용은 툴팁(title)·상세 모달에서 확인 |
| 상태 | 배지 |
| 신청일시 | |
| 처리일시 | 미처리 시 `-` |

## 규칙 (현황목록 공통)
- 진입 시 TitleBar + FilterBar만 표시, 데이터 미노출
- 조회 버튼 클릭 후 SummaryBar + Table + Pagination 동시 노출 (Enter 키 조회 가능)
- 행 클릭 → 상세 모달 오픈 (탭으로 열지 않음)
- 등록 버튼 없음 (신청은 외부 신청자의 자기신청 행위로만 생성됨, 관리자가 대리로 신청을 만들 수 없음)

## 상세 모달 (OperatorApplicationDetail)
탭 구성: **기본정보** (단일 탭)

신청부터 승인/반려까지 단일 스텝이라 클레임 관리의 "처리이력" 탭처럼 별도 이력 탭을 두지 않는다.
기본정보 탭은 신청ID·이름·이메일·요청역할·상태·신청일시·처리자·처리일시·신청사유를 표시하며,
반려 상태인 경우 반려사유를 추가로 표시한다. 신청 내용 자체를 관리자가 수정하는 기능은 없다(읽기 전용).

## 상태 전이 액션 (모달 하단 고정 영역)
- 상태 = 신청: **반려** / **승인** 버튼
  - 반려 시 반려사유 입력 필수, 반려사유는 신청자에게 전달되는 것으로 간주
  - 승인 시 처리자·처리일시가 즉시 기록됨
- 상태 = 승인/반려: 액션 버튼 없음 (최종 상태)

## 비고
- 실 서비스에서는 승인 시 `cfg_operator` 계정 생성과 `cfg_role` 매핑, 초기 비밀번호 발급 메일 발송이 뒤따르나
  본 화면은 이러한 계정 프로비저닝 연동을 mock으로 표현하지 않는다.
- 이미 계정이 발급된 운영자의 상태(활동/중지/탈퇴) 관리는 `시스템 관리 > 운영자 현황`(OperatorStatus) 화면에서 별도로 다룬다.
