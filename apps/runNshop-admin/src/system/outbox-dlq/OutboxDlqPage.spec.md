# Outbox·DLQ 관리 (OutboxDlqPage)

## 개요
트랜잭션과 함께 적재되는 도메인 이벤트 발행함(`cmn_outbox_event`)과, 발행에 반복 실패해 격리된
Dead Letter Queue(`adt_dlq`)를 조회·조치하는 운영 모니터링 화면.
(ADM-100-002)

두 목록은 서로 독립적인 자료구조이며 화면 상단의 탭 전환(InnerTabs)으로 오간다. **Outbox** 탭은 조회 전용이고,
**DLQ** 탭에만 재시도·무시 조치 액션이 있다.

## 상태

### Outbox (status)
| 코드 | 라벨 | 의미 |
|------|------|------|
| PENDING | 대기 | 적재되었으나 아직 릴레이가 발행을 시도하지 않은 상태 |
| PROCESSING | 처리중 | 발행 시도 중 |
| PROCESSED | 처리완료 | 컨슈머까지 정상 전달 완료 |
| FAILED | 실패 | 발행에 실패한 상태 (재시도 소진 시 DLQ로 격리됨) |

### DLQ (status)
| 코드 | 라벨 | 의미 |
|------|------|------|
| PENDING | 대기 | 격리된 채 조치 대기 중인 초기 상태 |
| RESOLVED | 해결 | 재시도로 정상 처리되었거나 원인 조치 후 해결 처리된 상태 |
| IGNORED | 무시 | 재처리가 불필요하다고 판단되어 무시 처리된 상태 |

상태 전이: `PENDING → (RESOLVED | IGNORED)`. 역방향 전이는 없다.

## Outbox 탭

### 필터바
- 키워드 (이벤트유형 / 대상ID)
- 상태 선택
- 조회 버튼

### 요약바
전체 / 대기 / 처리중 / 처리완료 / 실패(1건 이상일 때만) 건수 표시 (조회 후 노출)

### 목록 테이블
| 컬럼 | 설명 |
|------|------|
| 이벤트ID | |
| Trace ID | 분산 추적용 식별자 |
| 대상 유형 | aggregateType (예: Order, Claim, Settlement) |
| 대상 ID | aggregateId |
| 이벤트유형 | eventType (예: ORDER_CREATED) |
| 상태 | 배지. FAILED인 경우 배지에 마우스오버 시 오류 메시지 툴팁 표시 |
| 재시도 | 재시도 횟수 |
| 발생일시 | |
| 처리일시 | 미처리 시 `-` |

조회 전용이며 행 클릭·상세 모달·액션 버튼이 없다.

## DLQ 탭

### 필터바
- 키워드 (이벤트유형)
- 상태 선택
- 조회 버튼

### 요약바
전체 / 대기(1건 이상일 때 경고 강조) / 해결 / 무시 건수 표시 (조회 후 노출)

### 목록 테이블
| 컬럼 | 설명 |
|------|------|
| DLQ ID | |
| Outbox 이벤트ID | 원본 `cmn_outbox_event` 참조 |
| Trace ID | |
| 이벤트유형 | |
| 실패사유 | 1줄 말줄임, 툴팁(title)으로 전체 확인 |
| 재시도 | DLQ 격리 전까지의 재시도 횟수 |
| 상태 | 배지 |
| 처리자 / 처리메모 | 미처리 시 `-` |
| 발생일시 | |
| 액션 | 상태 = 대기인 행에만 **재시도** / **무시** 버튼 노출 |

### 액션
- **재시도**: 클릭 즉시 처리. `retryCount + 1`, 상태를 해결로 변경하고 처리자=현재 사용자, 처리메모="재시도 성공"으로 기록한다.
  별도 확인 모달 없이 원클릭으로 처리되는 경량 액션이다.
- **무시**: 처리 메모 입력 모달(`IgnoreDlqModal`)을 띄운다. 메모는 필수 입력이며, 확정 시 상태를 무시로 변경하고
  처리자·처리일시·처리메모를 기록한다.
- 상태 = 해결/무시인 행은 액션 컬럼에 `-`만 표시된다 (최종 상태).

## 규칙
- Outbox·DLQ 모두 진입 시 각 탭 내부에 TitleBar 없이 FilterBar만 표시되고, 조회 버튼을 눌러야 SummaryBar+Table이 노출된다.
- 탭 전환 시에도 각 탭의 조회 상태(필터·조회 결과)는 유지된다 (InnerTabs가 두 탭을 모두 마운트한 채 표시만 전환하기 때문).
- 탭 라벨의 건수(`Outbox (N)` / `DLQ (N)`)는 전체 데이터 건수를 실시간 반영하며 필터링 결과와는 무관하다.
- 등록·수정 폼이 없는 순수 모니터링·조치 화면이다.

## 비고
- 실 서비스에서는 Outbox 릴레이 배치가 주기적으로 `PENDING` 이벤트를 폴링해 발행하고, 지정된 재시도 횟수를 넘겨 실패하면
  자동으로 DLQ에 격리한다. 본 화면은 이 릴레이·자동격리 배치를 mock으로 표현하지 않으며 이미 격리된 DLQ 항목에 대한
  수동 조치만 다룬다.
