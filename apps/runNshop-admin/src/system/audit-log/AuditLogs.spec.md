# 감사 로그 (AuditLogs)

## 개요
도메인 엔티티의 생성·수정·삭제·상태변경 이력을 변경 전/후 값과 함께 남기는 불변(immutable) 감사 추적 화면.
(ADM-100-003, `adt_audit_log`)

클레임 처리·상품 심사·정산 정정·운영자 승인 등 여러 도메인에서 발생한 변경 이벤트가 하나의 로그로 적재되며,
본 화면은 이를 조회하는 조회 전용 화면이다. 등록·수정·삭제 기능은 없다.

## 작업구분 (action)
| 코드 | 라벨 | 의미 |
|------|------|------|
| CREATE | 생성 | 엔티티가 신규로 생성됨 |
| UPDATE | 수정 | 엔티티의 일부 필드가 변경됨 |
| DELETE | 삭제 | 엔티티가 삭제됨 |
| STATUS_CHANGE | 상태변경 | 엔티티의 상태 필드가 전이됨 (클레임 처리, 승인/반려 등) |

## 실행주체 (actorType)
| 코드 | 라벨 | 의미 |
|------|------|------|
| SYSTEM | 시스템 | 배치·자동화 로직에 의한 변경. `actorId`는 null |
| MEMBER | 회원 | 회원이 직접 수행한 변경 (예: 주문 생성) |
| OPERATOR | 운영자 | 어드민 운영자가 수행한 변경 |
| VENDOR | 입점사 | 입점사 계정이 수행한 변경 (예: 판매가 수정) |

## 필터바
- 키워드 (도메인 / 이벤트유형 / 대상ID)
- 작업구분 선택
- 실행주체유형 선택
- 발생일 기간 (from ~ to)
- 조회 버튼

## 요약바
전체 / 생성 / 수정 / 삭제 / 상태변경 건수 표시 (조회 후 노출)

## 목록 테이블
| 컬럼 | 설명 |
|------|------|
| 발생시각 | 클릭 시 상세 모달 오픈 |
| 도메인 | 예: Claim, Order, Member, Product, Settlement |
| 이벤트유형 | eventType (예: CLAIM_STATUS_CHANGED) |
| 작업구분 | 배지 |
| 대상 | aggregateType · aggregateId |
| 실행주체 | 실행주체유형 라벨 · actorId (SYSTEM인 경우 actorId 미표시) |

## 상세 모달 (AuditLogDetail)
탭 없이 단일 화면으로 구성된다 (조회 전용이라 탭으로 분리할 만큼의 편집 흐름이 없음).

- **기본 정보**: 로그ID, Trace ID, 도메인, 이벤트유형, 작업구분(배지), 대상(유형·ID), 실행주체(유형·ID), 실행IP, 발생시각을 모두 표시
- **변경 내역**: `beforeValue` / `afterValue`를 각각 `JSON.stringify(value, null, 2)`로 정리해 좌우 2단 `<pre>` 블록으로 나란히 표시하는
  간단한 diff 뷰. 별도 diff 라이브러리 없이 좌/우 값을 그대로 비교해서 보는 방식이며, 값이 없는 경우(`null`)는 `(없음)`으로 표시한다
  (예: CREATE 액션은 beforeValue가 항상 `(없음)`, DELETE 액션은 afterValue가 항상 `(없음)`)

## 규칙 (조회 전용 공통)
- 진입 시 TitleBar + FilterBar만 표시, 데이터 미노출
- 조회 버튼 클릭 후 SummaryBar + Table + Pagination 동시 노출 (Enter 키 조회 가능)
- 행 클릭 → 상세 모달 오픈
- 등록·수정·삭제 버튼 없음 (감사 로그는 시스템이 각 도메인 이벤트 발생 시점에 자동 적재하는 불변 레코드)

## 비고
- 실 서비스에서는 `adt_trace_log`(요청 단위 분산 추적 로그)를 함께 조회해 감사 로그의 `traceId`로 API 호출 체인을 역추적할 수 있으나,
  본 화면은 감사 로그 조회에 집중하며 트레이스 로그 조회는 범위에서 제외한다.
- 감사 로그는 법적·내부통제 목적의 불변 기록이므로 실 서비스에서는 수정·삭제 API 자체가 존재하지 않는다.
